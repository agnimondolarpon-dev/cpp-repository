# 0.4 — কম্পাইলার, লিঙ্কার এবং লাইব্রেরির ভূমিকা (0.4 — Introduction to the compiler, linker, and libraries)

আগের পাঠে (0.3 — C++ ডেভেলপমেন্টের ভূমিকা) এই ডায়াগ্রাম নিয়ে আমাদের যে আলোচনা শুরু হয়েছিল, তা এখানে চালিয়ে যাওয়া যাক:

**সফটওয়্যার ডেভেলপমেন্ট প্রক্রিয়া (Software Development Process):**

```
+-------------------------+
|          Step 1         |
```

## ধাপ 4: সোর্স কোড কম্পাইল করা (Step 4: Compiling your source code)

C++ সোর্স কোড ফাইল কম্পাইল করার জন্য আমরা একটি কম্পাইলার (compiler) ব্যবহার করি। C++ কম্পাইলার আপনার প্রোগ্রামের প্রতিটি সোর্স কোড (`.cpp`) ফাইলের মধ্য দিয়ে ক্রমান্বয়ে যায় এবং দুটি গুরুত্বপূর্ণ কাজ করে:

প্রথমত, কম্পাইলার আপনার C++ কোড পরীক্ষা করে দেখে যে সেটি C++ ভাষার নিয়ম অনুসরণ করছে কিনা। যদি তা না করে, তাহলে কম্পাইলার আপনাকে একটি এরর (এবং সংশ্লিষ্ট লাইন নম্বর) দেখাবে, যা কী ঠিক করতে হবে তা বুঝতে সাহায্য করবে। এরর ঠিক না হওয়া পর্যন্ত সংকলন প্রক্রিয়াও বাতিল থাকবে।

দ্বিতীয়ত, কম্পাইলার আপনার C++ কোডকে মেশিন ভাষার নির্দেশাবলীতে রূপান্তর করে। এই নির্দেশাবলী অবজেক্ট ফাইল (object file) নামক একটি মধ্যবর্তী ফাইলে সংরক্ষিত হয়। অবজেক্ট ফাইলে অন্যান্য এমন ডেটাও থাকে, যা পরবর্তী ধাপগুলোর জন্য প্রয়োজনীয় বা উপকারী (যেমন ধাপ 5-এ লিঙ্কারের প্রয়োজনীয় ডেটা এবং ধাপ 7-এ ডিবাগিংয়ের জন্য প্রয়োজনীয় ডেটা)।

অবজেক্ট ফাইল সাধারণত `name.o` বা `name.obj` নামে পরিচিত, যেখানে `name` হলো সেই `.cpp` ফাইলের নামের মতোই, যা থেকে এই অবজেক্ট ফাইলটি তৈরি হয়েছে।

উদাহরণস্বরূপ, যদি আপনার প্রোগ্রামে 3টি `.cpp` ফাইল থাকে, তাহলে কম্পাইলার 3টি অবজেক্ট ফাইল তৈরি করবে:

**সংকলন প্রক্রিয়া (Compilation Process):**

```
+-------------------+   +-------------------+   +-------------------+
|   Source file:    |   |   Source file:    |   |   Source file:    |
|  Calculator.cpp   |   |   Fraction.cpp    |   |     Math.cpp      |
+-------------------+   +-------------------+   +-------------------+
          |                       |                       |
       Compile                 Compile                 Compile
          |                       |                       |
          v                       v                       v
+-------------------+   +-------------------+   +-------------------+
|   Object file:    |   |   Object file:    |   |   Object file:    |
|   Calculator.o    |   |    Fraction.o     |   |      Math.o       |
+-------------------+   +-------------------+   +-------------------+
```

C++ কম্পাইলার বিভিন্ন অপারেটিং সিস্টেমের জন্য পাওয়া যায়। আমরা শীঘ্রই কম্পাইলার ইনস্টল করার বিষয়ে আলোচনা করব, তাই এখন এ নিয়ে চিন্তার দরকার নেই।

## ধাপ 5: অবজেক্ট ফাইল ও লাইব্রেরি লিঙ্ক করে কাঙ্ক্ষিত আউটপুট ফাইল তৈরি করা (Step 5: Linking object files and libraries and creating the desired output file)

কম্পাইলার সফলভাবে কাজ শেষ করার পর, লিঙ্কার (linker) নামে আরেকটি প্রোগ্রাম কাজ শুরু করে। লিঙ্কারের কাজ হলো সব অবজেক্ট ফাইল একত্রিত করে কাঙ্ক্ষিত আউটপুট ফাইল তৈরি করা (যেমন এমন একটি এক্সিকিউটেবল (executable) ফাইল, যা আপনি চালাতে পারবেন)। এই প্রক্রিয়াকে বলা হয় লিঙ্কিং (linking)। লিঙ্কিং প্রক্রিয়ার কোনো ধাপ ব্যর্থ হলে, লিঙ্কার সমস্যাটি বর্ণনা করে একটি এরর মেসেজ তৈরি করবে এবং এরপর প্রক্রিয়াটি বাতিল করবে।

প্রথমত, লিঙ্কার কম্পাইলার দ্বারা তৈরি প্রতিটি অবজেক্ট ফাইল পড়ে এবং নিশ্চিত করে যে সেগুলো বৈধ কিনা।

দ্বিতীয়ত, লিঙ্কার নিশ্চিত করে যে সব ক্রস-ফাইল নির্ভরতা (cross-file dependency) সঠিকভাবে সমাধান হয়েছে কিনা। উদাহরণস্বরূপ, আপনি যদি একটি `.cpp` ফাইলে কিছু সংজ্ঞায়িত করেন এবং পরে সেটি অন্য একটি `.cpp` ফাইলে ব্যবহার করেন, তাহলে লিঙ্কার এই দুইটিকে একসাথে সংযুক্ত করে দেয়। লিঙ্কার যদি কোনো রেফারেন্সকে তার সংজ্ঞার সাথে সংযুক্ত করতে ব্যর্থ হয়, তাহলে আপনি একটি লিঙ্কার এরর পাবেন এবং লিঙ্কিং প্রক্রিয়াটি বাতিল হয়ে যাবে।

তৃতীয়ত, লিঙ্কার সাধারণত এক বা একাধিক লাইব্রেরি ফাইলের (library files) সাথে লিঙ্ক করে, যেগুলো হলো আগে থেকে কম্পাইল করা (precompiled) কোডের এমন সংগ্রহ, যা অন্যান্য প্রোগ্রামে পুনরায় ব্যবহারের জন্য "প্যাকেজড আপ" করা হয়েছে।

সবশেষে, লিঙ্কার কাঙ্ক্ষিত আউটপুট ফাইলটি তৈরি করে। সাধারণত এটি এমন একটি এক্সিকিউটেবল ফাইল হয়, যা চালানো যায় (তবে আপনি আপনার প্রজেক্ট কীভাবে সেট আপ করেছেন তার উপর নির্ভর করে এটি একটি লাইব্রেরি ফাইলও হতে পারে)।

**লিঙ্কিং প্রক্রিয়া (Linking Process):**

```
+-------------------+   +-------------------+   +-------------------+
|    Object file:   |   |    Object file:   |   |    Object file:   |
|    Calculator.o   |   |     Fraction.o    |   |       Math.o      |
+-------------------+   +-------------------+   +-------------------+
          |                       |                       |
          v                       v                       v
          +-----------------------+-----------------------+
                                  |
                                  v
                    +---------------------------+
                    |                           |
                    |                           |
                    |                           |
                    |           Linker          |
                    |                           |
          +-------->|                           |<--------+
          |         |                           |         |
          |         +---------------------------+         |
          |                       |                       |
          |                       |                       |
          |                       |                       |
          |                       v                       |
+-------------------+   +-------------------+   +-------------------+
|    C++ Standard   |   |  Executable file: |   |  Other Libraries  |
|      Library      |   |   Calculator.exe  |   |                   |
+-------------------+   +-------------------+   +-------------------+
```

## স্ট্যান্ডার্ড লাইব্রেরি (The Standard Library)

C++-এর সাথে **C++ Standard Library** (সাধারণত "স্ট্যান্ডার্ড লাইব্রেরি" নামে পরিচিত) নামে একটি বিস্তৃত লাইব্রেরি আসে, যা আপনার প্রোগ্রামে ব্যবহারের জন্য দরকারী কিছু ক্ষমতার সেট সরবরাহ করে। C++ Standard Library-র সবচেয়ে বেশি ব্যবহৃত অংশগুলোর একটি হলো ইনপুট/আউটপুট লাইব্রেরি (প্রায়শই `iostream` বলা হয়), যাতে মনিটরে টেক্সট প্রিন্ট করা এবং ব্যবহারকারীর কাছ থেকে কীবোর্ড ইনপুট নেওয়ার জন্য প্রয়োজনীয় ফাংশনালিটি থাকে।

প্রায় প্রতিটি লিখিত C++ প্রোগ্রামই কোনো না কোনোভাবে স্ট্যান্ডার্ড লাইব্রেরি ব্যবহার করে, তাই আপনার প্রোগ্রামে C++ Standard Library লিঙ্ক করা থাকা অত্যন্ত সাধারণ একটি ব্যাপার। বেশিরভাগ C++ লিঙ্কার ডিফল্টভাবে স্ট্যান্ডার্ড লাইব্রেরির সাথে লিঙ্ক করার জন্য কনফিগার করা থাকে, তাই সাধারণত এটি নিয়ে আপনাকে আলাদাভাবে চিন্তা করতে হয় না।

## তৃতীয় পক্ষের লাইব্রেরি (3rd Party Libraries)

আপনি চাইলে ঐচ্ছিকভাবে তৃতীয় পক্ষের লাইব্রেরি ব্যবহার করতে পারেন, যেগুলো স্বাধীন প্রতিষ্ঠান বা ব্যক্তি দ্বারা তৈরি এবং বিতরণ করা হয় (C++ স্ট্যান্ডার্ডের অংশ হিসেবে নয়)। উদাহরণস্বরূপ, ধরা যাক আপনি এমন একটি প্রোগ্রাম লিখতে চেয়েছেন, যেটি শব্দ বাজাবে। C++ Standard Library-তে এই ধরনের কোনো ফাংশনালিটি নেই। যদিও আপনি চাইলে ডিস্ক থেকে সাউন্ড ফাইল পড়ার জন্য, সেগুলো বৈধ কিনা তা যাচাই করার জন্য, অথবা স্পিকারের মাধ্যমে বাজানোর জন্য অপারেটিং সিস্টেম বা হার্ডওয়্যারে সাউন্ড ডেটা কীভাবে রুট করতে হবে তা বের করার জন্য নিজের কোড লিখতে পারেন — কিন্তু সেটা অনেক বড় কাজ হয়ে যাবে! তার বদলে, এমন কোনো বিদ্যমান সফটওয়্যার প্রজেক্ট খুঁজে পাওয়ার সম্ভাবনাই বেশি, যার একটি লাইব্রেরি ইতিমধ্যে এই সব কাজ আপনার জন্য বাস্তবায়ন করে রেখেছে।

লাইব্রেরিতে কীভাবে লিঙ্ক করতে হয় (এবং কীভাবে নিজের লাইব্রেরি তৈরি করতে হয়!) সে বিষয়ে আমরা পরিশিষ্টে আলোচনা করব।

## বিল্ডিং (Building)

যেহেতু একাধিক ধাপ জড়িত থাকে, তাই **বিল্ডিং (building)** শব্দটি প্রায়ই সোর্স কোড ফাইলগুলোকে একটি চালানোর-উপযোগী এক্সিকিউটেবলে রূপান্তরিত করার সম্পূর্ণ প্রক্রিয়াকে বোঝাতে ব্যবহৃত হয়। বিল্ডিংয়ের ফলাফল হিসেবে তৈরি হওয়া কোনো নির্দিষ্ট এক্সিকিউটেবলকে মাঝে মাঝে একটি **বিল্ড (build)** ও বলা হয়।

> **উন্নত পাঠকদের জন্য:**
> জটিল প্রজেক্টের ক্ষেত্রে প্রোগ্রাম বিল্ড করা এবং স্বয়ংক্রিয় টেস্ট চালানোর প্রক্রিয়া অটোমেট করার জন্য প্রায়ই বিল্ড অটোমেশন টুল (যেমন `make` বা `build2`) ব্যবহার করা হয়। এই ধরনের টুল শক্তিশালী ও নমনীয় হলেও, যেহেতু এগুলো C++ মূল ভাষার অংশ নয় এবং এগিয়ে যাওয়ার জন্য এগুলো ব্যবহার করা বাধ্যতামূলকও নয়, তাই আমরা এই নোট সিরিজে এগুলো নিয়ে আলোচনা করব না।

## ধাপ 6 ও 7: টেস্টিং এবং ডিবাগিং (Steps 6 & 7: Testing and Debugging)

এটাই মজার অংশ! এখন আপনি আপনার এক্সিকিউটেবল চালিয়ে দেখতে পারবেন এটি আসলে কী করে!

একবার প্রোগ্রাম চালাতে পারলে আপনি সেটি টেস্ট করতে পারবেন। **টেস্টিং (testing)** হলো আপনার সফটওয়্যার প্রত্যাশিতভাবে কাজ করছে কিনা তা যাচাই করার প্রক্রিয়া। বেসিক টেস্টিংয়ে সাধারণত বিভিন্ন ইনপুট কম্বিনেশন ব্যবহার করে দেখা হয়, যাতে নিশ্চিত হওয়া যায় যে সফটওয়্যারটি বিভিন্ন পরিস্থিতিতে সঠিকভাবে আচরণ করছে।

প্রোগ্রামটি যদি প্রত্যাশিতভাবে কাজ না করে, তাহলে আপনাকে কিছুটা **ডিবাগিং (debugging)** করতে হবে, যা প্রোগ্রামিং এরর খুঁজে বের করে ঠিক করার প্রক্রিয়া।

পরবর্তী অধ্যায়গুলোতে আমরা আপনার প্রোগ্রাম আরও বিস্তারিতভাবে কীভাবে টেস্ট এবং ডিবাগ করতে হয়, তা নিয়ে আলোচনা করব।

## ইন্টিগ্রেটেড ডেভেলপমেন্ট এনভায়রনমেন্ট (Integrated Development Environment, IDE)

লক্ষ্য করুন যে ধাপ 3, 4, 5 এবং 7-এ এমন সফটওয়্যার প্রোগ্রাম জড়িত থাকে, যেগুলো ইনস্টল করা আবশ্যক (এডিটর, কম্পাইলার, লিঙ্কার, ডিবাগার)। যদিও আপনি এই কার্যক্রমগুলোর প্রতিটির জন্য আলাদা আলাদা প্রোগ্রাম ব্যবহার করতে পারেন, তবে ইন্টিগ্রেটেড ডেভেলপমেন্ট এনভায়রনমেন্ট (IDE) নামে পরিচিত একটি সফটওয়্যার প্যাকেজ এই সব বৈশিষ্ট্যকে একত্রে বান্ডেল ও ইন্টিগ্রেট করে।
