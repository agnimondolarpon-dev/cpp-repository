# C++ Basics — Chapter 1: Introduction to C++

## 1.1 Statements and the Structure of a Program

### Definition — Statement (স্টেটমেন্ট) কী?

প্রোগ্রামিং-এ **statement** হলো একটি সম্পূর্ণ নির্দেশনা (instruction) যা কম্পাইলারকে বলে দেয় একটি নির্দিষ্ট কাজ সম্পন্ন করতে। মানুষের ভাষায় একটি বাক্য (sentence) যেমন একটি সম্পূর্ণ ভাব প্রকাশ করে, তেমনি একটি statement কম্পিউটারকে একটি সম্পূর্ণ কাজ করার নির্দেশ দেয়।

C++-এ বেশিরভাগ statement একটি সেমিকোলন (`;`) দিয়ে শেষ হয়, যা কম্পাইলারকে জানিয়ে দেয় যে এই statement-টি এখানেই সম্পূর্ণ হয়েছে।

```cpp
int x = 5;        // একটি statement
std::cout << x;    // আরেকটি statement
```

### কেন Statement প্রয়োজন (Why It Exists)

কম্পিউটার নিজে থেকে কিছু বোঝে না — এটি শুধু নির্দিষ্ট, স্পষ্ট, ধাপে ধাপে দেওয়া নির্দেশনা অনুসরণ করতে পারে। একটি প্রোগ্রাম আসলে statement-এর একটি ক্রমানুসারে সাজানো তালিকা, যা কম্পিউটারকে বলে দেয় ঠিক কী কী কাজ, কোন ক্রমে করতে হবে।

যদি statement-এর ধারণা না থাকত, তাহলে কম্পাইলার বুঝতে পারত না একটি নির্দেশনা কোথায় শেষ হচ্ছে এবং পরেরটি কোথায় শুরু হচ্ছে। সেমিকোলন এই বিভাজন রেখা তৈরি করে দেয়।

### Statement-এর প্রকারভেদ

C++-এ বিভিন্ন ধরনের statement আছে, যেগুলোর প্রতিটির নিজস্ব উদ্দেশ্য রয়েছে:

1. **Declaration statement** — একটি নতুন identifier (যেমন variable) ঘোষণা করে
   ```cpp
   int age;
   ```
2. **Expression statement** — একটি expression মূল্যায়ন (evaluate) করে, সাধারণত কোনো ফলাফল সংরক্ষণ বা প্রদর্শনের জন্য
   ```cpp
   x = 5 + 3;
   ```
3. **Jump statement** — প্রোগ্রামের normal flow পরিবর্তন করে (যেমন `return`, `break`)
   ```cpp
   return 0;
   ```
4. **Compound statement (block)** — একাধিক statement-কে `{ }` দিয়ে একত্রে গ্রুপ করা
5. **Selection statement** — শর্তসাপেক্ষে ভিন্ন পথে প্রোগ্রাম চালায় (যেমন `if`, `switch`) — এগুলো পরবর্তী চ্যাপ্টারে বিস্তারিত আলোচিত হবে
6. **Iteration statement** — বারবার একই কাজ করে (যেমন `for`, `while`লুপ) — এগুলোও পরবর্তী চ্যাপ্টারে আলোচিত হবে

এই চ্যাপ্টারে আমরা মূলত declaration এবং expression statement নিয়ে কাজ করব, কারণ এগুলোই একটি বেসিক প্রোগ্রামের ভিত্তি তৈরি করে।

### C++ প্রোগ্রামের গঠন (Structure)

একটি সম্পূর্ণ C++ প্রোগ্রামের মৌলিক কাঠামো নিচের মতো দেখতে হয়:

```cpp
#include <iostream>

int main()
{
    std::cout << "Hello, world!" << std::endl;
    return 0;
}
```

এই প্রোগ্রামের প্রতিটি অংশ ব্যাখ্যা করা যাক লাইন ধরে ধরে:

- **লাইন ১:** `#include <iostream>` — এটি একটি **preprocessor directive**, যা কম্পাইলারকে বলে `iostream` নামক লাইব্রেরির কন্টেন্ট এই ফাইলে যুক্ত করতে। এটি একটি statement নয় (এর শেষে সেমিকোলন নেই), বরং এটি কম্পাইলেশনের আগে ঘটা একটি প্রক্রিয়া।
- **লাইন ৩:** `int main()` — এটি **main function**-এর ঘোষণা। প্রতিটি C++ প্রোগ্রামে ঠিক একটি `main` function থাকতেই হবে, নাহলে প্রোগ্রামটি **link** করতে ব্যর্থ হবে (link ধারণাটি ভবিষ্যৎ চ্যাপ্টারে বিস্তারিত আলোচিত হবে; আপাতত শুধু জেনে রাখা যথেষ্ট যে `main` অনুপস্থিত থাকলে প্রোগ্রামটি একটি সম্পূর্ণ এক্সিকিউটেবল হিসেবে তৈরি হতে পারবে না)। এটিই সেই জায়গা যেখান থেকে প্রোগ্রাম চালানো শুরু হয় (entry point)।
- **লাইন ৪ ও ৭:** `{` এবং `}` — এই braces (কোঁকড়া বন্ধনী) দিয়ে function-এর **body** নির্দিষ্ট করা হয়। এর মধ্যে যা কিছু আছে তা সবই `main` function-এর অন্তর্গত।
- **লাইন ৬:** `std::cout << "Hello, world!" << std::endl;` — এটি একটি expression statement যা স্ক্রিনে টেক্সট প্রদর্শন করে।
- **লাইন ৭:** `return 0;` — এটি একটি jump statement যা `main` function থেকে অপারেটিং সিস্টেমকে একটি মান ফেরত পাঠায়, যা নির্দেশ করে প্রোগ্রামটি সফলভাবে সম্পন্ন হয়েছে।

### Program Execution Flow (প্রোগ্রাম চলার ধারা)

C++ প্রোগ্রাম সবসময় `main` function থেকে execution শুরু করে — তা প্রোগ্রামে যতই অন্য function থাকুক না কেন। এরপর `main`-এর ভেতরের statement গুলো **উপর থেকে নিচে, একটির পর একটি** ক্রমানুসারে (sequentially) চলে, যতক্ষণ না কোনো বিশেষ কন্ট্রোল স্ট্রাকচার (যেমন `if`, লুপ, বা function call) এই স্বাভাবিক ধারা পরিবর্তন করে।

উদাহরণস্বরূপ:

```cpp
#include <iostream>

int main()
{
    std::cout << "প্রথম লাইন" << std::endl;   // ধাপ ১: এটি প্রথমে চলবে
    std::cout << "দ্বিতীয় লাইন" << std::endl;  // ধাপ ২: এরপর এটি চলবে
    std::cout << "তৃতীয় লাইন" << std::endl;    // ধাপ ৩: সবশেষে এটি চলবে
    return 0;                                    // ধাপ ৪: প্রোগ্রাম শেষ হবে
}
```

এই প্রোগ্রামটি রান করলে আউটপুট হবে:
```
প্রথম লাইন
দ্বিতীয় লাইন
তৃতীয় লাইন
```

লক্ষণীয় বিষয় হলো, কম্পাইলার ঠিক সেই ক্রমেই statement গুলো execute করে যে ক্রমে সেগুলো লেখা হয়েছে (কিছু ব্যতিক্রম বাদে, যা পরবর্তী চ্যাপ্টারগুলোতে আলোচিত হবে)।

### Blocks এবং Statements (ব্লক ও স্টেটমেন্ট)

একাধিক statement-কে `{ }` দিয়ে ঘিরে একত্রে গ্রুপ করাকে বলা হয় **compound statement** বা **block**। একটি function-এর body আসলে একটি ব্লক।

```cpp
int main()
{   // ব্লক শুরু
    int x{ 5 };
    int y{ 10 };
    std::cout << x + y << std::endl;
}   // ব্লক শেষ
```

ব্লকের বৈশিষ্ট্য:
- একটি ব্লকের ভেতরে আরেকটি ব্লক থাকতে পারে (nested block)
- একটি ব্লক নিজে থেকেই একটি সম্পূর্ণ "স্কোপ" তৈরি করে — অর্থাৎ ব্লকের ভেতরে ঘোষিত variable ব্লকের বাইরে থেকে অ্যাক্সেস করা যায় না (এই বিষয়টি পরবর্তী চ্যাপ্টারে বিস্তারিত আলোচিত হবে)
- ব্লকের শেষে সেমিকোলনের প্রয়োজন নেই (function বা ব্লকের ক্ষেত্রে), যদিও কিছু বিশেষ ক্ষেত্রে (যেমন class ঘোষণা) সেমিকোলন লাগে — সেটি পরবর্তীতে আলোচিত হবে

### Behind the Scenes — কম্পাইলার কীভাবে Statement ব্যাখ্যা করে

কম্পাইলার একটি C++ সোর্স ফাইলকে কয়েকটি ধাপে প্রসেস করে:

1. **Preprocessing** — `#include` এর মতো directive গুলো প্রসেস করা হয়, যেখানে হেডার ফাইলের কন্টেন্ট বসিয়ে দেওয়া হয়।
2. **Tokenization / Lexical Analysis** — সোর্স কোডকে ছোট ছোট অংশ (token) এ ভাঙা হয়, যেমন keyword, identifier, operator, literal ইত্যাদি।
3. **Parsing / Syntax Analysis** — এই token গুলো একটি নির্দিষ্ট গ্রামার অনুসারে সাজানো হয়েছে কিনা যাচাই করা হয়, এবং একটি **Abstract Syntax Tree (AST)** তৈরি করা হয়।
4. **Semantic Analysis** — কোডের অর্থ ঠিক আছে কিনা যাচাই করা হয় (যেমন, টাইপ মিলছে কিনা)।
5. **Code Generation** — মেশিন কোড বা অবজেক্ট কোড তৈরি করা হয়।

কম্পাইলার প্রতিটি সেমিকোলনকে একটি statement-এর সীমানা (boundary) হিসেবে চেনে। যদি সেমিকোলন না দেওয়া হয়, কম্পাইলার পরবর্তী statement-এর সাথে বর্তমান statement-কে একত্রিত করে ফেলার চেষ্টা করবে, যার ফলে সিনট্যাক্স এরর দেখা দেবে।

### একাধিক উদাহরণ

**উদাহরণ ১ — সাধারণ Declaration ও Expression Statement:**
```cpp
#include <iostream>

int main()
{
    int score{ 100 };            // Declaration statement
    score = score + 50;          // Expression statement (assignment)
    std::cout << score;          // Expression statement (output)
    return 0;                     // Jump statement
}
```

**উদাহরণ ২ — একাধিক Statement-এর ক্রমানুসারে execution:**
```cpp
#include <iostream>

int main()
{
    std::cout << "ধাপ ১: শুরু" << std::endl;
    int total{ 0 };
    total = total + 10;
    std::cout << "ধাপ ২: total এখন " << total << std::endl;
    total = total + 20;
    std::cout << "ধাপ ৩: total এখন " << total << std::endl;
    return 0;
}
```
এখানে প্রতিটি লাইন ক্রমানুসারে execute হয়, এবং `total`-এর মান ধাপে ধাপে পরিবর্তিত হয়।

**উদাহরণ ৩ — Nested Block:**
```cpp
#include <iostream>

int main()
{
    int outer{ 1 };
    {
        int inner{ 2 };
        std::cout << outer << " " << inner << std::endl;
    }
    // এখানে 'inner' আর অ্যাক্সেসযোগ্য নয়, কারণ এটি ভেতরের ব্লকে সীমাবদ্ধ
    return 0;
}
```

### Common Mistakes (সাধারণ ভুল)

1. **সেমিকোলন ভুলে যাওয়া**
   ```cpp
   int x = 5   // ভুল! সেমিকোলন নেই
   std::cout << x;
   ```
   এটি একটি কম্পাইল-টাইম এরর তৈরি করবে। বিগিনাররা প্রায়ই এই ভুলটি করে থাকে।

2. **অতিরিক্ত সেমিকোলন দেওয়া (যদিও এটি সবসময় এরর নয়)**
   ```cpp
   int x = 5;;   // দুইটি সেমিকোলন — দ্বিতীয়টি একটি "empty statement" হিসেবে গণ্য হয়, এরর দেয় না কিন্তু ভালো প্র্যাকটিস নয়
   ```

3. **Block-এর braces মেলাতে ভুল করা**
   ```cpp
   int main()
   {
       std::cout << "Hello";
   // } ভুলে বাদ পড়ে গেছে — এটি কম্পাইল এরর তৈরি করবে
   ```

4. **statement-এর ক্রম নিয়ে ভুল ধারণা রাখা** — অনেক বিগিনার মনে করে প্রোগ্রাম "একসাথে" সব statement চালায়, কিন্তু বাস্তবে C++ স্বাভাবিকভাবে একটির পর একটি, ক্রমানুসারে (sequential) execute করে।

### Professional Tips (প্রফেশনাল পরামর্শ)

- প্রতিটি statement আলাদা লাইনে লেখা উচিত — একই লাইনে একাধিক statement লেখা কোড পড়া কঠিন করে তোলে, যদিও এটি সিনট্যাক্টিকালি বৈধ।
- সবসময় opening brace `{` এবং closing brace `}` একই ইনডেন্টেশন লেভেলে রাখার চেষ্টা করুন (Style নিয়ে বিস্তারিত 1.8-এ আলোচিত হবে)।
- বড় প্রোগ্রাম লেখার সময় প্রতিটি ব্লকের শুরু ও শেষ স্পষ্টভাবে চিহ্নিত রাখা জরুরি, কারণ এটি কোড readability বাড়ায় এবং bug কমায়।
- প্রফেশনাল কোডে "একটি statement, একটি স্পষ্ট উদ্দেশ্য" — এই নীতি মেনে চলা হয়। একটি statement-এ অনেক কাজ গুঁজে দেওয়া থেকে বিরত থাকা উচিত।

### Deep Understanding — Statement বনাম Expression

এই পর্যায়ে একটি গুরুত্বপূর্ণ পার্থক্য বোঝা দরকার: **expression** এবং **statement** এক জিনিস নয়।

- একটি **expression** একটি মান (value) তৈরি করে, কিন্তু নিজে থেকে একটি সম্পূর্ণ নির্দেশনা নয়। যেমন, `5 + 3` একটি expression, যা `8` মান তৈরি করে।
- একটি **expression statement** হলো একটি expression-এর শেষে সেমিকোলন যোগ করে সেটিকে একটি সম্পূর্ণ statement বানানো। যেমন, `5 + 3;` একটি বৈধ (যদিও অর্থহীন) statement, কারণ ফলাফলটি কোথাও সংরক্ষিত হচ্ছে না।

```cpp
5 + 3;              // বৈধ statement, কিন্তু ফলাফল হারিয়ে যায় (কোনো ব্যবহারিক উদ্দেশ্য নেই)
int sum = 5 + 3;     // এখানে expression-এর ফলাফল sum ভেরিয়েবলে সংরক্ষিত হচ্ছে
```

এই পার্থক্য বোঝা জরুরি কারণ ভবিষ্যতে function এবং operator নিয়ে কাজ করার সময় এই ধারণাটি বারবার প্রয়োজন হবে।

### Interview Questions

1. **প্রশ্ন:** C++-এ একটি statement কী, এবং এটি expression থেকে কীভাবে ভিন্ন?
   **উত্তর:** Statement হলো একটি সম্পূর্ণ নির্দেশনা যা কম্পাইলারকে একটি কাজ করতে বলে, সাধারণত সেমিকোলন দিয়ে শেষ হয়। Expression একটি মান তৈরি করে কিন্তু নিজে থেকে সম্পূর্ণ নির্দেশনা নয়; একটি expression-এর শেষে সেমিকোলন যোগ করলে সেটি একটি expression statement হয়ে যায়।

2. **প্রশ্ন:** C++ প্রোগ্রাম কোথা থেকে execution শুরু করে?
   **উত্তর:** সবসময় `main` function থেকে, প্রোগ্রামে যতই অন্য function থাকুক না কেন।

3. **প্রশ্ন:** একটি block বা compound statement কী?
   **উত্তর:** একাধিক statement-কে `{ }` দিয়ে ঘিরে একত্রে গ্রুপ করাকে block বলে। এটি একটি নিজস্ব স্কোপ তৈরি করে।

### Practice Problems

1. একটি প্রোগ্রাম লিখুন যা তিনটি ভিন্ন লাইনে তিনটি ভিন্ন বার্তা প্রদর্শন করে, `std::cout` ব্যবহার করে।
2. নিচের কোডে কোথায় ভুল আছে খুঁজে বের করুন এবং ঠিক করুন:
   ```cpp
   int main()
   {
       int x = 10
       std::cout << x;
       return 0;
   }
   ```
3. একটি nested block তৈরি করুন যেখানে বাইরের ব্লকে একটি variable এবং ভেতরের ব্লকে আরেকটি variable ঘোষণা করা হয়েছে।

## 1.2 Comments

### Definition — Comment (কমেন্ট) কী?

**Comment** হলো সোর্স কোডের এমন একটি অংশ, যা কম্পাইলার সম্পূর্ণভাবে উপেক্ষা (ignore) করে। এটি প্রোগ্রামের কোনো কার্যকারিতা প্রভাবিত করে না — এটি শুধুমাত্র মানুষ পড়ার জন্য লেখা হয়, যাতে কোডের উদ্দেশ্য, যুক্তি বা প্রেক্ষাপট বোঝা যায়।

কম্পাইলার কম্পাইলেশনের সময় comment-কে সম্পূর্ণভাবে বাদ দিয়ে দেয় — এটি এক্সিকিউটেবল ফাইলে কোনো প্রভাব ফেলে না।

### কেন Comment গুরুত্বপূর্ণ (Why It Exists)

কোড লেখার কিছুদিন পর, এমনকি নিজের লেখা কোডও অস্পষ্ট মনে হতে পারে। এছাড়া, একটি বাস্তব প্রজেক্টে সাধারণত একাধিক প্রোগ্রামার একসাথে কাজ করে — একজনের লেখা কোড আরেকজনকে পড়তে ও বুঝতে হয়। Comment এই সমস্যার সমাধান করে:

1. **উদ্দেশ্য স্পষ্ট করা** — কোডটি *কী* করছে তা তো কোড নিজেই বলে দেয়, কিন্তু *কেন* এভাবে করা হয়েছে তা বোঝাতে comment দরকার।
2. **জটিল লজিক ব্যাখ্যা করা** — কঠিন algorithm বা business logic বোঝা সহজ করে তোলে।
3. **টিম ওয়ার্কে সহায়তা** — অন্য ডেভেলপাররা দ্রুত কোড বুঝতে পারে।
4. **ভবিষ্যতে নিজের জন্য সহায়ক** — কয়েক মাস পর নিজের লেখা কোডও ভুলে যাওয়া স্বাভাবিক; comment তখন সাহায্য করে।
5. **Debugging-এ সহায়তা** — সাময়িকভাবে কোডের একটি অংশ "বন্ধ" (disable) করে রাখতে comment ব্যবহার করা যায়।

### Single-line Comments (একক-লাইন কমেন্ট)

`//` দিয়ে শুরু করলে, সেই লাইনের বাকি অংশ পুরোটাই comment হিসেবে গণ্য হয়।

```cpp
// এটি একটি single-line comment
int x{ 5 };   // এটিও একটি comment, কোডের পরে লেখা হয়েছে
```

`//` এর পর থেকে লাইনের শেষ পর্যন্ত (নতুন লাইন / newline character পর্যন্ত) সবকিছু কম্পাইলার উপেক্ষা করবে।

### Multi-line Comments (বহু-লাইন কমেন্ট)

`/*` দিয়ে শুরু হয়ে `*/` দিয়ে শেষ হয়। এর মধ্যে যতগুলো লাইন থাকুক না কেন, সবই comment হিসেবে গণ্য হবে।

```cpp
/*
   এটি একটি মাল্টি-লাইন কমেন্ট।
   এখানে একাধিক লাইন লেখা যায়।
   কম্পাইলার এই পুরো অংশটি উপেক্ষা করবে।
*/
int main()
{
    return 0;
}
```

### Header Comments (ফাইল-শীর্ষ কমেন্ট)

প্রফেশনাল কোডে প্রায়ই ফাইলের শুরুতে একটি বড় comment ব্লক থাকে, যেখানে ফাইলের উদ্দেশ্য, লেখক, তারিখ ইত্যাদি তথ্য থাকে:

```cpp
/*
    ফাইলের নাম: main.cpp
    উদ্দেশ্য: একটি সাধারণ ক্যালকুলেটর প্রোগ্রাম
    লেখক: [নাম]
    তারিখ: [তারিখ]
*/

#include <iostream>

int main()
{
    // ...
    return 0;
}
```

### Common Mistakes — Nested Multi-line Comments

একটি গুরুত্বপূর্ণ সতর্কতা: **multi-line comment একে অপরের ভেতরে বসানো (nesting) যায় না।**

```cpp
/* এটি একটি কমেন্ট
   /* এই ভেতরের কমেন্ট শুরু করার চেষ্টা */
   এই অংশটি কমেন্টের বাইরে চলে যাবে, যা এরর তৈরি করবে
*/
```

এখানে কম্পাইলার প্রথম `*/`-কে বাইরের কমেন্টের শেষ হিসেবে ধরে নেবে, এবং তারপরের অংশটুকু সাধারণ কোড হিসেবে পড়ার চেষ্টা করবে, যা সিনট্যাক্স এরর তৈরি করবে।

**সমাধান:** কোডের বড় অংশ সাময়িকভাবে বন্ধ (comment out) করতে চাইলে single-line comment (`//`) ব্যবহার করাই নিরাপদ, অথবা preprocessor directive (`#if 0` ... `#endif`) ব্যবহার করা যায় (এটি পরবর্তী চ্যাপ্টারে আলোচিত হবে)।

### একাধিক উদাহরণ

**উদাহরণ ১ — কোড ব্যাখ্যা করতে Comment:**
```cpp
#include <iostream>

int main()
{
    int radius{ 5 };                          // বৃত্তের ব্যাসার্ধ
    double pi{ 3.14159 };                      // পাই-এর আনুমানিক মান
    double area{ pi * radius * radius };        // বৃত্তের ক্ষেত্রফল গণনা: π × r²
    std::cout << "ক্ষেত্রফল: " << area;
    return 0;
}
```

**উদাহরণ ২ — Debugging-এর জন্য কোড সাময়িকভাবে বন্ধ করা:**
```cpp
#include <iostream>

int main()
{
    std::cout << "স্বাভাবিক আউটপুট" << std::endl;
    // std::cout << "এই লাইনটি সাময়িকভাবে বন্ধ রাখা হয়েছে" << std::endl;
    return 0;
}
```

**উদাহরণ ৩ — Function-এর উদ্দেশ্য ব্যাখ্যা করা (ভবিষ্যতে function শেখার সময় কাজে লাগবে):**
```cpp
// এই function দুইটি সংখ্যা যোগ করে ফেরত দেয়
int add(int a, int b)
{
    return a + b;
}
```

### Common Mistakes (সাধারণ ভুল)

1. **অতিরিক্ত অপ্রয়োজনীয় Comment লেখা** — যা কোড থেকেই স্পষ্ট বোঝা যায়, সেটি আবার comment-এ লেখা:
   ```cpp
   int x{ 5 };   // x-কে 5 এ সেট করা হলো  <- এটি অপ্রয়োজনীয়, কারণ কোডটি নিজেই এটি স্পষ্ট করে
   ```
2. **Comment আপডেট না করা** — কোড পরিবর্তন করার পর comment না পাল্টানো, যার ফলে comment আর সত্য থাকে না এবং বিভ্রান্তি তৈরি করে।
3. **Multi-line comment nest করার চেষ্টা করা**, যা আগেই আলোচিত হয়েছে।
4. **Comment দিয়ে খারাপ কোড ঢাকার চেষ্টা করা** — যদি কোড এতটাই জটিল হয় যে বিশাল comment ছাড়া বোঝা যায় না, তাহলে প্রকৃত সমাধান হলো কোডটি সহজ ও readable করে পুনর্লিখন করা, শুধু comment দিয়ে সমস্যা ঢেকে রাখা নয়।

### Professional Tips (প্রফেশনাল পরামর্শ)

প্রফেশনাল ডেভেলপাররা নিচের নীতিগুলো মেনে চলেন:

1. **"কী" নয়, "কেন" ব্যাখ্যা করুন** — কোড নিজেই বলে দেয় *কী* হচ্ছে; ভালো comment বলে *কেন* এভাবে করা হয়েছে।
   ```cpp
   // খারাপ: x-কে 1 বাড়ানো হলো
   x = x + 1;

   // ভালো: retry কাউন্টার বাড়ানো হলো, যাতে max attempt-এ পৌঁছালে লুপ থামে
   x = x + 1;
   ```
2. **জটিল বা অস্পষ্ট লজিকের ক্ষেত্রেই comment ব্যবহার করুন**, প্রতিটি লাইনে নয়।
3. **Comment-কে কোডের সাথে সিঙ্ক্রোনাইজড রাখুন** — কোড পরিবর্তনের সাথে সাথে সংশ্লিষ্ট comment-ও আপডেট করুন।
4. **Google C++ Style Guide-এর নীতি অনুসারে**, comment গুলো সংক্ষিপ্ত, স্পষ্ট এবং ব্যাকরণগতভাবে সঠিক বাক্যে লেখা উচিত।
5. **TODO Comment** — ভবিষ্যতে করণীয় কাজ চিহ্নিত করতে প্রফেশনাল কোডে প্রায়ই এই ফরম্যাট ব্যবহৃত হয়:
   ```cpp
   // TODO: এই function-এ error handling যোগ করতে হবে
   ```
6. **লম্বা লাইনে Comment-এর অবস্থান বিবেচনা করুন** — ছোট লাইনের ক্ষেত্রে কোডের ডানপাশে comment রাখা যায় (এবং একাধিক লাইনে সেগুলো সমান দূরত্বে সারিবদ্ধ করলে পড়তে সুবিধা হয়), কিন্তু লাইন লম্বা হলে ডানপাশে comment রাখলে পুরো লাইনটি অতিরিক্ত দীর্ঘ ও পড়তে কষ্টকর হয়ে যায়। এমন ক্ষেত্রে comment-টি সংশ্লিষ্ট কোড লাইনের **ঠিক উপরে** আলাদা লাইনে রাখা ভালো।
   ```cpp
   // ভালো (ছোট লাইন, ডানপাশে comment):
   int score{ 100 };   // শুরুর স্কোর

   // ভালো (লম্বা লাইন হলে, উপরে comment):
   // ব্যবহারকারীর মোট ক্রয়মূল্য থেকে ছাড় বাদ দিয়ে চূড়ান্ত মূল্য গণনা করা হচ্ছে
   double finalPrice{ totalPurchaseAmount - totalPurchaseAmount * discountPercentage };
   ```

### কখন Comment ব্যবহার করা উচিত নয় (When Not to Use Comments)

- যখন কোডটি নিজেই যথেষ্ট স্পষ্ট এবং self-explanatory।
- যখন একটি ভালো variable বা function নাম দিয়েই উদ্দেশ্য বোঝানো সম্ভব — অনেক সময় ভালো naming, comment-এর প্রয়োজনীয়তা কমিয়ে দেয়।
  ```cpp
  // খারাপ: comment দিয়ে অস্পষ্ট নাম ঢাকার চেষ্টা
  int d;   // দিনের সংখ্যা

  // ভালো: স্পষ্ট নাম, comment-এর প্রয়োজনই নেই
  int daysElapsed;
  ```
- যখন comment শুধু কোডকে পুনরাবৃত্তি (repeat) করছে, নতুন কোনো তথ্য যোগ করছে না।

### Behind the Scenes — কম্পাইলার Comment কীভাবে হ্যান্ডল করে

কম্পাইলেশন প্রক্রিয়ার একদম প্রথম ধাপে (preprocessing / lexical analysis পর্যায়ে), কম্পাইলার সমস্ত comment খুঁজে বের করে এবং সেগুলোকে সম্পূর্ণভাবে সরিয়ে ফেলে (বা একক স্পেস দিয়ে প্রতিস্থাপন করে), যাতে পরবর্তী ধাপগুলোতে (parsing, semantic analysis) এগুলো কোনো প্রভাব না ফেলে। এই কারণেই comment এক্সিকিউটেবল ফাইলের আকার বা গতির উপর কোনো প্রভাব ফেলে না — এগুলো চূড়ান্ত বাইনারিতে থাকেই না।

### Professional Programmer Notes

বড় প্রফেশনাল প্রজেক্টে, বিশেষভাবে ফরম্যাট করা comment ব্যবহার করে **ডকুমেন্টেশন জেনারেটর** (যেমন Doxygen) ব্যবহার করা হয়, যা স্বয়ংক্রিয়ভাবে API ডকুমেন্টেশন তৈরি করে। যেমন:

```cpp
/**
 * @brief দুইটি সংখ্যা যোগ করে
 * @param a প্রথম সংখ্যা
 * @param b দ্বিতীয় সংখ্যা
 * @return যোগফল
 */
int add(int a, int b)
{
    return a + b;
}
```

এই ধরনের স্ট্রাকচার্ড comment থেকে স্বয়ংক্রিয়ভাবে HTML বা PDF ডকুমেন্টেশন তৈরি করা যায়, যা বড় টিমে অত্যন্ত গুরুত্বপূর্ণ।

### Interview Questions

1. **প্রশ্ন:** Single-line এবং multi-line comment-এর মধ্যে পার্থক্য কী?
   **উত্তর:** Single-line comment (`//`) শুধুমাত্র সেই লাইনের বাকি অংশকে কমেন্ট করে, আর multi-line comment (`/* ... */`) একাধিক লাইন জুড়ে বিস্তৃত হতে পারে। মাল্টি-লাইন কমেন্ট nested হতে পারে না।

2. **প্রশ্ন:** কম্পাইলড প্রোগ্রামের রানটাইম পারফরম্যান্সে comment-এর প্রভাব কী?
   **উত্তর:** কোনো প্রভাব নেই। Comment কম্পাইলেশনের প্রথম ধাপেই সম্পূর্ণভাবে সরিয়ে ফেলা হয়, তাই এটি এক্সিকিউটেবল ফাইলে থাকে না এবং রানটাইম পারফরম্যান্সে কোনো প্রভাব ফেলে না।

3. **প্রশ্ন:** ভালো comment লেখার একটি মূলনীতি কী?
   **উত্তর:** কোড *কী* করছে তা নয়, বরং *কেন* এভাবে করা হয়েছে তা ব্যাখ্যা করা — কারণ কোড নিজেই "কী" প্রশ্নের উত্তর দিয়ে দেয়।

## 1.3 Introduction to Objects and Variables

### Definition — Data ও Value কী?

C++ শেখা শুরু করার আগে দুইটি মৌলিক শব্দ স্পষ্টভাবে বোঝা দরকার, কারণ প্রোগ্রামিং-এর প্রায় প্রতিটি ধারণা এদের উপর ভিত্তি করে তৈরি।

**Data (ডেটা)** হলো এমন যেকোনো তথ্য, যা একটি কম্পিউটার সরাতে (move), প্রক্রিয়া করতে (process), বা সংরক্ষণ (store) করতে পারে। **Value (মান)** হলো একক এক টুকরা ডেটা — যেমন একটি অক্ষর (`a`), একটি সংখ্যা (`5`), বা একটি টেক্সট (`"Hello"`)।

1.1 বিভাগে আমরা দেখেছি প্রোগ্রাম মূলত statement-এর একটি সংগ্রহ, যেগুলো ধারাবাহিকভাবে execute হয়ে একটি নির্দিষ্ট ফলাফল উৎপন্ন করে। এই ফলাফল তৈরি হয় ডেটা নিয়ে কাজ করার (পড়া, পরিবর্তন করা, লেখা) মাধ্যমে। প্রোগ্রাম নিজেও (সোর্স কোড এবং কম্পাইলড উভয় আকারেই) টেকনিক্যালি ডেটা, কারণ এটিও সরানো, প্রক্রিয়া করা ও সংরক্ষণ করা যায় — কিন্তু প্রথাগতভাবে "কোড" শব্দটি প্রোগ্রাম নিজেকে বোঝাতে ব্যবহৃত হয়, আর "ডেটা" শব্দটি সেই তথ্যকে বোঝাতে ব্যবহৃত হয় যা নিয়ে প্রোগ্রাম কাজ করে।

### Definition — Object (অবজেক্ট) কী?

C++-এ **object** শব্দটি সাধারণ অর্থে ব্যবহৃত হয় — এটি মেমোরির এমন একটি অঞ্চল (region) নির্দেশ করে, যা একটি মান (value) সংরক্ষণ করতে পারে। এই সংজ্ঞাটি object-oriented programming-এর "object"-এর চেয়ে বিস্তৃত — C++-এ প্রতিটি variable আসলে একটি object।

> **লক্ষণীয়:** পরবর্তী চ্যাপ্টারগুলোতে "object" শব্দটি class-ভিত্তিক object-অরিয়েন্টেড প্রোগ্রামিং-এর প্রেক্ষাপটেও ব্যবহৃত হবে, কিন্তু এই মৌলিক অধ্যায়ে "object" মানে শুধু "মেমোরিতে সংরক্ষিত একটি মান ধারণকারী স্থান"।

### Definition — Variable (ভেরিয়েবল) কী?

**Variable** হলো একটি **named object** — অর্থাৎ, এমন একটি object যার একটি নাম (identifier) আছে, যার মাধ্যমে প্রোগ্রামার সেই মেমোরি অঞ্চলটিকে নির্দেশ করতে ও ব্যবহার করতে পারেন।

```cpp
int age{ 25 };
```

এখানে `age` একটি variable — এটি মেমোরিতে একটি নির্দিষ্ট স্থান দখল করে আছে, যেখানে মান `25` সংরক্ষিত আছে, এবং আমরা `age` নাম দিয়ে সেই স্থানটি নির্দেশ করতে পারি।

### কেন Variable প্রয়োজন (Why It Exists)

প্রোগ্রাম চালানোর সময় ডেটা সংরক্ষণ ও পরিবর্তন করার প্রয়োজন হয় — যেমন ব্যবহারকারীর ইনপুট, গণনার ফলাফল, বা কোনো অবস্থার তথ্য। যদি প্রতিবার সরাসরি মেমোরি অ্যাড্রেস (যেমন `0x7ffee23a1b4c`) ব্যবহার করতে হতো, তাহলে প্রোগ্রামিং অত্যন্ত কঠিন ও ত্রুটিপূর্ণ হতো। Variable এই সমস্যার সমাধান করে — এটি একটি অর্থপূর্ণ নাম দিয়ে মেমোরি অ্যাক্সেস করার সুযোগ দেয়, যা কোডকে readable এবং maintainable করে তোলে।

### Memory Concept (মেমোরির ধারণা)

একটি কম্পিউটারের **RAM (Random Access Memory)** কে কল্পনা করা যায় বহু ছোট ছোট বাক্স/সেলের একটি বিশাল সারি হিসেবে, যেখানে প্রতিটি বাক্সের একটি ইউনিক ঠিকানা (address) আছে। যখন একটি প্রোগ্রাম চলে, তখন অপারেটিং সিস্টেম সেই প্রোগ্রামকে RAM-এর একটি অংশ বরাদ্দ (allocate) করে দেয়, যেখানে প্রোগ্রামের ডেটা ও ইন্সট্রাকশন সংরক্ষিত থাকে।

যখন আমরা একটি variable ঘোষণা করি, তখন কম্পাইলার/রানটাইম সিস্টেম মেমোরিতে সেই variable-এর টাইপ অনুযায়ী প্রয়োজনীয় পরিমাণ জায়গা বরাদ্দ করে। যেমন, একটি `int` সাধারণত ৪ বাইট (byte) জায়গা নেয় (এটি platform-নির্ভর হতে পারে)।

```
মেমোরি:
+--------+--------+--------+--------+
| Byte 1 | Byte 2 | Byte 3 | Byte 4 |   <- 'age' variable-এর জন্য বরাদ্দকৃত 4 বাইট
+--------+--------+--------+--------+
Address: 0x1000  0x1001  0x1002  0x1003
```

### Data Storage (ডেটা সংরক্ষণ)

একটি variable-এর মধ্যে ডেটা কীভাবে সংরক্ষিত হয় তা নির্ভর করে তার **data type**-এর উপর। প্রতিটি data type নির্দেশ করে:
1. কত বাইট মেমোরি প্রয়োজন
2. সেই বাইট গুলোকে কীভাবে ব্যাখ্যা (interpret) করতে হবে

উদাহরণস্বরূপ, `int` টাইপের একটি variable-এ সংখ্যাটি **binary (দ্বিমিক)** আকারে সংরক্ষিত থাকে। মান `5` মেমোরিতে বাইনারি ফরম্যাটে (`00000000 00000000 00000000 00000101`) সংরক্ষিত থাকে, কিন্তু আমরা প্রোগ্রামে এটি একটি সাধারণ দশমিক সংখ্যা হিসেবেই ব্যবহার করি — কম্পাইলার এই রূপান্তরের কাজ করে দেয়।

### Variable Definition (ভেরিয়েবল ডেফিনিশন)

একটি variable ব্যবহারের আগে তা তৈরি করতে হয় — এই কাজের জন্য ব্যবহৃত হয় একটি বিশেষ ধরনের statement, যাকে বলা হয় **definition statement** (কিছু জায়গায় এটিকে declaration statement-ও বলা হয়; declaration ও definition-এর সূক্ষ্ম টেকনিক্যাল পার্থক্য ভবিষ্যৎ চ্যাপ্টারে আলোচিত হবে)। এই statement কম্পাইলারকে জানায়:
- variable-টির নাম কী
- এর টাইপ কী (যা মেমোরিতে কতটা জায়গা লাগবে এবং কীভাবে ডেটা ব্যাখ্যা করা হবে তা নির্ধারণ করে)

```cpp
int age;         // 'age' নামে একটি int টাইপের variable-এর definition
double price;     // 'price' নামে একটি double টাইপের variable-এর definition
```

এই definition কম্পাইলারকে বলে দেয় প্রয়োজনীয় মেমোরি বরাদ্দ করতে এবং সেই মেমোরির সাথে নামটি সংযুক্ত (associate) করতে। **কম্পাইল-টাইমে** (যখন প্রোগ্রামটি কম্পাইল করা হচ্ছে), এই statement দেখে কম্পাইলার নিজের কাছে নোট রাখে যে আমরা `age` নামে একটি variable চাই, যার data type `int`। এরপর থেকে (কিছু সীমাবদ্ধতাসহ, যা ভবিষ্যৎ চ্যাপ্টারে আলোচিত হবে), কোডে যেখানেই `age` identifier ব্যবহার করা হবে, কম্পাইলার জানবে এটি এই variable-টিকেই নির্দেশ করছে।

গুরুত্বপূর্ণ একটি বিষয় হলো, variable প্রকৃতপক্ষে তৈরি হয় **runtime**-এ (যখন প্রোগ্রামটি চলে), কম্পাইল-টাইমে নয়। যখন প্রোগ্রাম রান হওয়ার সময় একটি defined variable-এর জন্য মেমোরি বরাদ্দ করা হয়, তখন সেটিকে বলা হয় variable **instantiate** হয়েছে — অর্থাৎ, তাকে একটি নির্দিষ্ট মেমোরি অ্যাড্রেস দেওয়া হয়েছে। কম্পাইল-টাইমে শুধু পরিকল্পনা হয় (variable-এর নাম ও টাইপ সংক্রান্ত তথ্য), আর runtime-এ প্রকৃত মেমোরি বরাদ্দ ঘটে।

> **সতর্কতা:** শুধু definition করলে (যেমন উপরের `int age;`) variable-এর মধ্যে কোনো নির্দিষ্ট মান থাকে না — এটি **uninitialized** থাকে, যা 1.6 বিভাগে বিস্তারিত আলোচিত হবে। এই মুহূর্তে গুরুত্বপূর্ণ হলো বোঝা যে definition এবং initialization ভিন্ন জিনিস।

### Data Types-এর সংক্ষিপ্ত পরিচিতি

এই পর্যায়ে বিস্তারিত আলোচনার প্রয়োজন নেই (এটি ভবিষ্যৎ চ্যাপ্টারে বিস্তারিত আলোচিত হবে), তবে প্রাথমিক পরিচিতি জরুরি। C++-এ কিছু সাধারণ built-in (fundamental) data type হলো:

| Data Type | উদ্দেশ্য | উদাহরণ মান |
|---|---|---|
| `int` | পূর্ণসংখ্যা (integer) সংরক্ষণ | `42`, `-7`, `0` |
| `double` | দশমিক সংখ্যা (floating-point) সংরক্ষণ | `3.14`, `-0.5` |
| `char` | একক ক্যারেক্টার সংরক্ষণ | `'A'`, `'z'` |
| `bool` | সত্য/মিথ্যা (true/false) মান সংরক্ষণ | `true`, `false` |

```cpp
int totalStudents{ 30 };
double averageScore{ 78.5 };
char grade{ 'A' };
bool isPassed{ true };
```

প্রতিটি data type এর নিজস্ব আকার (size) এবং সীমা (range) আছে, যা নির্ধারণ করে কী ধরনের মান সেই variable-এ সংরক্ষণ করা যাবে।

### Variable কীভাবে অভ্যন্তরীণভাবে কাজ করে (How Variables Work Internally)

একটি variable ব্যবহার করার সময় প্রকৃতপক্ষে যা ঘটে তা কয়েকটি ধাপে ভাঙা যায়:

1. **Definition-এর সময়:** কম্পাইলার variable-টির নাম, টাইপ, এবং স্কোপ (কোথায় এটি ব্যবহারযোগ্য) সম্পর্কিত তথ্য তার **সিম্বল টেবিল (symbol table)**-এ সংরক্ষণ করে। এটি একটি অভ্যন্তরীণ তালিকা, যা কম্পাইলার কম্পাইলেশনের সময় ব্যবহার করে।
2. **মেমোরি বরাদ্দ:** যখন প্রোগ্রামটি প্রকৃতপক্ষে চলে (runtime), তখন সেই variable-এর জন্য প্রকৃত মেমোরি বরাদ্দ করা হয় (এই চ্যাপ্টারে আলোচিত সাধারণ local variable-এর ক্ষেত্রে এটি **stack**-এ বরাদ্দ হয়, যা ভবিষ্যৎ চ্যাপ্টারে বিস্তারিত আলোচিত হবে)।
3. **নাম থেকে মেমোরি অ্যাড্রেসে রূপান্তর:** কম্পাইলার প্রোগ্রামের প্রতিটি জায়গায় variable-এর নাম ব্যবহারকে তার প্রকৃত মেমোরি অ্যাড্রেসে রূপান্তর করে দেয় — প্রোগ্রামার নামটি ব্যবহার করেন, কিন্তু নেপথ্যে কম্পাইলার সেটিকে অ্যাড্রেসে রূপান্তরিত করে।
4. **মান অ্যাক্সেস ও পরিবর্তন:** যখন আমরা variable-টির নাম ব্যবহার করি (যেমন `std::cout << age;`), কম্পাইলার সেই নির্দিষ্ট মেমোরি অ্যাড্রেস থেকে মান পড়ে নেয়।

এই পুরো প্রক্রিয়াটি প্রোগ্রামারের কাছ থেকে **abstract** (আড়াল) করা থাকে — আমরা শুধু নাম ব্যবহার করি, বাইনারি অ্যাড্রেস নিয়ে চিন্তা করতে হয় না। এটি হাই-লেভেল ভাষার একটি অন্যতম প্রধান সুবিধা।

### একাধিক উদাহরণ

**উদাহরণ ১ — একাধিক Variable ঘোষণা ও ব্যবহার:**
```cpp
#include <iostream>

int main()
{
    int appleCount{ 5 };
    int orangeCount{ 3 };
    int totalFruits{ appleCount + orangeCount };
    std::cout << "মোট ফল: " << totalFruits << std::endl;
    return 0;
}
```
**লাইন-বাই-লাইন ব্যাখ্যা:**
- `int appleCount{ 5 };` — মেমোরিতে একটি নতুন int object তৈরি করে, নাম দেয় `appleCount`, এবং মান `5` দিয়ে ইনিশিয়ালাইজ করে।
- `int orangeCount{ 3 };` — একইভাবে আরেকটি int object তৈরি করে, মান `3`।
- `int totalFruits{ appleCount + orangeCount };` — `appleCount` ও `orangeCount`-এর মান পড়ে, যোগ করে, এবং ফলাফল দিয়ে নতুন `totalFruits` variable ইনিশিয়ালাইজ করে।
- `std::cout << ...` — `totalFruits`-এর বর্তমান মান স্ক্রিনে প্রদর্শন করে।

**উদাহরণ ২ — বিভিন্ন Data Type-এর Variable:**
```cpp
#include <iostream>

int main()
{
    int age{ 20 };
    double height{ 5.9 };
    char initial{ 'R' };
    bool isStudent{ true };

    std::cout << "বয়স: " << age << std::endl;
    std::cout << "উচ্চতা: " << height << std::endl;
    std::cout << "প্রথম অক্ষর: " << initial << std::endl;
    std::cout << "শিক্ষার্থী কিনা: " << isStudent << std::endl;
    return 0;
}
```

**উদাহরণ ৩ — একই টাইপের একাধিক Variable একসাথে ঘোষণা:**
```cpp
int x{ 1 }, y{ 2 }, z{ 3 };   // একই লাইনে একাধিক int variable ঘোষণা
```
যদিও এটি সিনট্যাক্টিকালি বৈধ, প্রফেশনাল কোডে সাধারণত প্রতিটি variable আলাদা লাইনে ঘোষণা করার পরামর্শ দেওয়া হয় (এটি নিচে "Professional Tips"-এ আলোচিত হয়েছে)।

### Common Mistakes (সাধারণ ভুল)

1. **Variable define না করেই ব্যবহার করা:**
   ```cpp
   std::cout << age;   // এরর! 'age' এখনো define করা হয়নি
   int age{ 20 };
   ```
   C++-এ একটি variable তার definition-এর আগে ব্যবহার করা যায় না।

2. **একই নামে দুইবার Variable define করা:**
   ```cpp
   int age{ 20 };
   int age{ 25 };   // এরর! একই স্কোপে একই নামে দুইবার define করা যায় না
   ```

3. **টাইপ ও মানের মধ্যে অসামঞ্জস্য:**
   ```cpp
   int age{ "কুড়ি" };   // এরর! int টাইপের variable-এ টেক্সট (string) মান দেওয়া যাবে না
   ```

4. **Variable নাম ও এর মধ্যে থাকা মান নিয়ে বিভ্রান্তি** — বিগিনাররা প্রায়ই ভুলে যায় যে variable নামটি শুধু একটি লেবেল, প্রকৃত ডেটা মেমোরিতে সংরক্ষিত থাকে।

### Professional Tips (প্রফেশনাল পরামর্শ)

- প্রতিটি variable একটি স্পষ্ট, অর্থবহ নাম দিয়ে define করুন, যা সেই variable-এর উদ্দেশ্য প্রকাশ করে (যেমন `studentCount` এর বদলে শুধু `s` ব্যবহার না করা)।
- একই লাইনে একাধিক variable define করা এড়িয়ে চলুন — প্রতিটি variable আলাদা লাইনে define করলে কোড পড়া সহজ হয় এবং প্রতিটি variable-এর সাথে একটি পৃথক comment যুক্ত করা সহজ হয়।
  ```cpp
  // ভালো প্র্যাকটিস
  int width{ 10 };
  int height{ 20 };

  // এড়িয়ে চলা উচিত
  int width{ 10 }, height{ 20 };
  ```
- একটি variable যতটা সম্ভব দেরিতে (যখন এটি প্রথম প্রয়োজন হবে ঠিক তার কাছাকাছি) define করুন, প্রোগ্রামের শুরুতেই সব variable define করে না রাখা।
- সবসময় variable ইনিশিয়ালাইজ করে define করার চেষ্টা করুন (এই বিষয়টি 1.4 এবং 1.6 বিভাগে বিস্তারিত আলোচিত হবে)।

### Deep Understanding — Object বনাম Variable-এর সূক্ষ্ম পার্থক্য

যদিও এই চ্যাপ্টারে "object" এবং "variable" প্রায় সমার্থকভাবে ব্যবহৃত হচ্ছে, একটি সূক্ষ্ম পার্থক্য মনে রাখা ভালো:

- **Object** হলো একটি বিস্তৃত ধারণা — মেমোরির যেকোনো অঞ্চল যা একটি মান ধারণ করে, তার নাম থাকুক বা না থাকুক।
- **Variable** নির্দিষ্টভাবে একটি **named object** বোঝায়।

C++-এ কিছু object থাকতে পারে যাদের সরাসরি নাম নেই (যেমন temporary object, যা কিছু expression মূল্যায়নের সময় সাময়িকভাবে তৈরি হয়) — এগুলো object কিন্তু variable নয়। এই ধারণাটি এই মুহূর্তে গভীরভাবে বোঝার প্রয়োজন নেই, তবে ভবিষ্যতে function ও expression নিয়ে কাজ করার সময় এটি প্রাসঙ্গিক হয়ে উঠবে।

### Behind the Scenes — Stack Memory-এর প্রাথমিক ধারণা

এই চ্যাপ্টারে আলোচিত সাধারণ local variable গুলো (অর্থাৎ, `main` function-এর ভেতরে ঘোষিত variable) মেমোরির একটি বিশেষ অংশে সংরক্ষিত হয়, যাকে বলা হয় **call stack** বা সংক্ষেপে **stack**। এটি একটি "শেষে-প্রবেশ-প্রথমে-বাহির" (Last-In-First-Out বা LIFO) কাঠামো, যেখানে:

- একটি function শুরু হলে তার local variable গুলোর জন্য stack-এ জায়গা বরাদ্দ হয়।
- function শেষ হলে সেই জায়গা স্বয়ংক্রিয়ভাবে মুক্ত (deallocate) হয়ে যায়।

এই কারণেই একটি function-এর ভেতরে ঘোষিত variable সেই function শেষ হওয়ার পর আর ব্যবহারযোগ্য থাকে না — তাদের মেমোরি ইতিমধ্যে মুক্ত হয়ে গেছে। Stack এবং heap memory-এর বিস্তারিত পার্থক্য ভবিষ্যৎ চ্যাপ্টারে গভীরভাবে আলোচিত হবে।

### Professional Programmer Notes

বাস্তব প্রফেশনাল সফটওয়্যারে, memory-এর সঠিক ব্যবহার অত্যন্ত গুরুত্বপূর্ণ — অপ্রয়োজনীয় variable তৈরি করা, বা প্রয়োজনের চেয়ে বড় data type ব্যবহার করা, প্রোগ্রামের performance এবং memory efficiency-কে প্রভাবিত করতে পারে। বড় স্কেলের সিস্টেমে (যেমন embedded systems বা high-performance computing), প্রতিটি variable-এর memory footprint সচেতনভাবে বিবেচনা করা হয়।

### Interview Questions

1. **প্রশ্ন:** C++-এ "object" এবং "variable"-এর মধ্যে পার্থক্য কী?
   **উত্তর:** Object হলো মেমোরির যেকোনো অঞ্চল যা একটি মান ধারণ করতে পারে। Variable হলো একটি named object — অর্থাৎ, এমন একটি object যার একটি নির্দিষ্ট নাম আছে যা দিয়ে সেটি অ্যাক্সেস করা যায়।

2. **প্রশ্ন:** একটি variable define করলে কম্পাইলার নেপথ্যে কী করে?
   **উত্তর:** কম্পাইলার variable-এর নাম, টাইপ এবং স্কোপ সংক্রান্ত তথ্য তার সিম্বল টেবিলে সংরক্ষণ করে (কম্পাইল-টাইমে), এবং প্রোগ্রাম রান হওয়ার সময় (runtime-এ) সেই টাইপের জন্য প্রয়োজনীয় মেমোরি বরাদ্দ করে — এই মুহূর্তকেই বলা হয় variable-টি instantiate হয়েছে।

3. **প্রশ্ন:** কেন সরাসরি মেমোরি অ্যাড্রেস ব্যবহার না করে variable ব্যবহার করা হয়?
   **উত্তর:** সরাসরি মেমোরি অ্যাড্রেস ব্যবহার করা জটিল এবং ত্রুটিপ্রবণ। Variable একটি অর্থপূর্ণ নাম দিয়ে মেমোরি অ্যাক্সেসের সুযোগ দেয়, যা কোডকে readable, maintainable এবং কম ত্রুটিপূর্ণ করে তোলে।

1. একটি প্রোগ্রাম লিখুন যেখানে চারটি ভিন্ন data type-এর (int, double, char, bool) variable ঘোষণা ও প্রদর্শন করা হবে।
2. ব্যাখ্যা করুন কেন নিচের কোডটি কম্পাইল এরর তৈরি করবে:

   ```cpp
   int main()

   ```
3. দুইটি int variable ঘোষণা করে তাদের গুণফল একটি তৃতীয় variable-এ সংরক্ষণ করুন এবং প্রদর্শন করুন।

## 1.4 Variable Assignment and Initialization

### Definition — Assignment (অ্যাসাইনমেন্ট) কী?

একটি variable ঘোষণা করার পর, তাতে একটি মান বসানোর প্রক্রিয়াকে বলা হয় **assignment**। C++-এ assignment operator হলো `=` (সমান চিহ্ন)।

```cpp
int x;
x = 5;   // assignment: x এখন 5 মান ধারণ করছে
```

লক্ষণীয় বিষয়: এখানে গণিতের "সমান" (equals) চিহ্নের সাথে গুলিয়ে ফেলা উচিত নয়। C++-এ `=` মানে "ডানপাশের মানটি বামপাশের variable-এ কপি করো"।

### Definition — Initialization (ইনিশিয়ালাইজেশন) কী?

**Initialization** হলো একটি variable তৈরি করার *সময়েই* তাকে একটি প্রাথমিক মান দেওয়া। এটি assignment থেকে ভিন্ন, কারণ এটি variable তৈরির মুহূর্তেই ঘটে, তৈরি হওয়ার পরে আলাদাভাবে নয়।

```cpp
int x{ 5 };   // initialization: x তৈরি হওয়ার সাথে সাথেই 5 মান পাচ্ছে
```

### Assignment বনাম Initialization — মূল পার্থক্য

এই দুইটি ধারণা বিগিনারদের কাছে প্রায়ই বিভ্রান্তিকর মনে হয়, তাই একটি স্পষ্ট তুলনা দেখা যাক:

| বৈশিষ্ট্য | Initialization | Assignment |
|---|---|---|
| কখন ঘটে | Variable তৈরির সময় | Variable তৈরি হওয়ার পরে, যেকোনো সময় |
| সিনট্যাক্স | `int x{ 5 };` | `x = 5;` |
| কতবার হতে পারে | একবার (তৈরির সময়) | একাধিকবার (variable-এর জীবদ্দশায় যতবার ইচ্ছা) |
| উদ্দেশ্য | প্রাথমিক মান নির্ধারণ | বিদ্যমান variable-এর মান পরিবর্তন |

```cpp
int x{ 5 };    // initialization — x তৈরি হচ্ছে এবং 5 মান পাচ্ছে
x = 10;         // assignment — x-এর মান পরিবর্তন করে 10 করা হচ্ছে
x = 15;         // আরেকটি assignment — x-এর মান আবার পরিবর্তিত হচ্ছে
```

### কেন এই পার্থক্য গুরুত্বপূর্ণ (Why It Matters)

initialization এবং assignment-এর পার্থক্য বোঝা গুরুত্বপূর্ণ কারণ:
1. কিছু variable টাইপ শুধুমাত্র initialize করা যায়, পরে assign করা যায় না (যেমন `const` variable, যা পরবর্তী চ্যাপ্টারে আলোচিত হবে)।
2. Uninitialized variable ব্যবহার করলে undefined behavior ঘটতে পারে (1.6 বিভাগে বিস্তারিত)।
3. আধুনিক C++-এ সবসময় initialization-কে অগ্রাধিকার দেওয়া হয়, কারণ এটি নিরাপদ এবং bug কম তৈরি করে।

### C++-এ বিভিন্ন Initialization পদ্ধতি

C++ ভাষায় ইতিহাসের বিভিন্ন পর্যায়ে একাধিক initialization সিনট্যাক্স যোগ হয়েছে। প্রতিটি পদ্ধতি জানা জরুরি, কারণ বিভিন্ন কোডবেসে বিভিন্ন স্টাইল দেখা যেতে পারে।

#### ১. Default Initialization (ডিফল্ট ইনিশিয়ালাইজেশন)

```cpp
int x;   // কোনো মান দেওয়া হয়নি
```
এখানে কোনো প্রাথমিক মান নির্ধারণ করা হয়নি। ফলাফল: `x`-এর মধ্যে **অনির্ধারিত (indeterminate)** মান থাকে — এটি মেমোরিতে আগে থেকে থাকা যেকোনো "আবর্জনা" (garbage) মান হতে পারে। এটি 1.6 বিভাগে বিস্তারিত আলোচিত হবে।

#### ২. Copy Initialization (কপি ইনিশিয়ালাইজেশন)

```cpp
int x = 5;
```
এটি C++-এর সবচেয়ে পুরনো এবং C ভাষা থেকে উত্তরাধিকার সূত্রে পাওয়া পদ্ধতি। এখানে `=` চিহ্নের মাধ্যমে মান "কপি" করে variable-এ বসানো হয়। এই সিনট্যাক্স সহজবোধ্য, কিন্তু কিছু নির্দিষ্ট ক্ষেত্রে (যেমন জটিল object তৈরির সময়) এটি কম efficient হতে পারে।

#### ৩. Direct Initialization (ডাইরেক্ট ইনিশিয়ালাইজেশন)

```cpp
int x(5);
```
এখানে বন্ধনী `()` ব্যবহার করে সরাসরি মান দিয়ে initialize করা হয়। `int`-এর মতো fundamental type-এর ক্ষেত্রে এটি copy initialization থেকে performance-এ ভিন্ন নয়; পার্থক্যটি মূলত class type-এর ক্ষেত্রে প্রাসঙ্গিক, যেখানে direct initialization সরাসরি একটি constructor call করে (এই ধারণাটি class নিয়ে কাজ করার সময় আরও স্পষ্ট হবে)। এর কিছু সিনট্যাক্স-সংক্রান্ত সমস্যা আছে (যেমন "most vexing parse" নামক একটি সমস্যা, যা উন্নত বিষয়, ভবিষ্যতে আলোচিত হতে পারে), তাই আধুনিক C++-এ brace initialization প্রাধান্য পায়।

#### ৪. Direct-List Initialization (ডাইরেক্ট-লিস্ট ইনিশিয়ালাইজেশন)

```cpp
int x{ 5 };    // direct-list initialization (brace initialization নামেও পরিচিত)
```

#### ৫. Copy-List Initialization (কপি-লিস্ট ইনিশিয়ালাইজেশন)

```cpp
int x = { 5 };   // copy-list initialization
```

#### ৬. Value Initialization (ভ্যালু ইনিশিয়ালাইজেশন)

```cpp
int y{};       // value initialization — সাধারণত zero-initialization হয় (y = 0)
```

উপরের তিনটি পদ্ধতি (৪, ৫, ৬) একত্রে **list initialization** নামে পরিচিত, কারণ এগুলো সবই braces `{ }` ব্যবহার করে। C++11-এ প্রবর্তিত এই পদ্ধতি আধুনিক C++-এ সর্বাধিক প্রস্তাবিত initialization পদ্ধতি। এর সুবিধাগুলো হলো:

- **Narrowing conversion প্রতিরোধ করে** — যদি এমন একটি মান দেওয়া হয় যা টাইপের সাথে মানানসই নয় এবং তথ্য হারানোর ঝুঁকি থাকে, কম্পাইলার এরর দেখাবে। এই সুরক্ষা তিনটি list-initialization পদ্ধতিতেই (direct-list, copy-list, এবং value) কাজ করে।
  ```cpp
  int x{ 4.5 };     // কম্পাইল এরর! double থেকে int-এ narrowing conversion — তথ্য হারানোর ঝুঁকি
  int x2 = { 4.5 };  // কম্পাইল এরর! copy-list-এও একই সুরক্ষা প্রযোজ্য
  int y = 4.5;        // এটি কম্পাইল হবে (warning সহ), কিন্তু y-এর মান হবে 4 — নীরবে তথ্য হারিয়ে যায়
  ```
- **সব ধরনের initialization-এর জন্য সামঞ্জস্যপূর্ণ (uniform) সিনট্যাক্স প্রদান করে** — এই কারণে list/brace initialization-কে **uniform initialization**-ও বলা হয়।
- **Empty braces `{}` দিয়ে value initialization করা যায়**, যা variable-কে টাইপের ডিফল্ট মান (সাধারণত সংখ্যার ক্ষেত্রে 0) দিয়ে ইনিশিয়ালাইজ করে — একে **zero-initialization** বলা হয়।

> **প্র্যাকটিক্যাল পরামর্শ:** সংক্ষেপে, `int x{ 5 };` (direct-list) আকারটিই সবচেয়ে সাধারণভাবে ব্যবহৃত হয় এবং এই বইয়ে এটিকেই মূলত "brace initialization" নামে উল্লেখ করা হবে। `int x = { 5 };` (copy-list) কার্যত একই সুরক্ষা দেয়, কিন্তু সিনট্যাক্স কিছুটা বেশি verbose, তাই কম ব্যবহৃত হয়। উভয় ফর্মই বিভিন্ন কোডবেসে দেখা যেতে পারে, তাই দুইটিই চেনা জরুরি।

### ছয় ধরনের Initialization — সারসংক্ষেপ সারণী

| Initialization ধরন | উদাহরণ | মন্তব্য |
|---|---|---|
| Default-initialization | `int x;` | বেশিরভাগ ক্ষেত্রে অনির্ধারিত মান থাকে |
| Copy-initialization | `int x = 5;` | সরল, কিন্তু narrowing conversion আটকায় না |
| Direct-initialization | `int x( 5 );` | Parenthesis-initialization নামেও পরিচিত |
| Direct-list-initialization | `int x{ 5 };` | Narrowing conversion নিষিদ্ধ |
| Copy-list-initialization | `int x = { 5 };` | Narrowing conversion নিষিদ্ধ |
| Value-initialization | `int x{};` | সাধারণত zero-initialization ঘটে |

### Modern C++-এ Best Practice

আধুনিক C++ (C++11 এবং পরবর্তী) নির্দেশিকা অনুযায়ী, variable initialize করার সময় **brace initialization (`{ }`)** ব্যবহার করা সর্বোত্তম প্র্যাকটিস, কারণ:
1. এটি narrowing conversion-জনিত ভুল থেকে রক্ষা করে।
2. এটি সব প্রেক্ষাপটে সামঞ্জস্যপূর্ণভাবে কাজ করে (fundamental type, class type, array — সবক্ষেত্রেই)।
3. এটি স্পষ্টভাবে দেখায় যে একটি initialization ঘটছে, assignment নয়।

```cpp
// প্রস্তাবিত (আধুনিক C++ স্টাইল)
int score{ 100 };
double price{ 9.99 };
char grade{ 'A' };
bool isActive{ true };
```

এই বইয়ের বাকি অংশে, যেখানে সম্ভব, brace initialization ব্যবহার করা হবে, যা Google C++ Style Guide এবং আধুনিক প্রফেশনাল কোডিং স্ট্যান্ডার্ডের সাথে সামঞ্জস্যপূর্ণ।

### একাধিক উদাহরণ

**উদাহরণ ১ — ছয় ধরনের Initialization পদ্ধতির তুলনা:**
```cpp
#include <iostream>

int main()
{
    int a;            // default initialization — অনির্ধারিত মান (এড়িয়ে চলা উচিত)
    int b = 5;         // copy initialization
    int c(5);          // direct initialization
    int d{ 5 };          // direct-list initialization (প্রস্তাবিত)
    int e = { 5 };         // copy-list initialization
    int f{};                // value initialization — f = 0

    std::cout << b << " " << c << " " << d << " " << e << " " << f << std::endl;
    return 0;
}
```

**উদাহরণ ২ — Initialization ও পরবর্তী Assignment:**
```cpp
#include <iostream>

int main()
{
    int temperature{ 20 };              // initialization
    std::cout << "শুরুর তাপমাত্রা: " << temperature << std::endl;

    temperature = 25;                    // assignment (মান পরিবর্তন)
    std::cout << "পরিবর্তিত তাপমাত্রা: " << temperature << std::endl;

    temperature = temperature + 5;       // assignment (নিজের মানের উপর ভিত্তি করে পরিবর্তন)
    std::cout << "চূড়ান্ত তাপমাত্রা: " << temperature << std::endl;
    return 0;
}
```
**লাইন-বাই-লাইন ব্যাখ্যা:**
- `int temperature{ 20 };` — একটি নতুন int object তৈরি হয় এবং প্রাথমিক মান 20 দিয়ে initialize হয়।
- `temperature = 25;` — বিদ্যমান object-এর মান পরিবর্তন করে 25 করা হয় (assignment, নতুন কোনো object তৈরি হচ্ছে না)।
- `temperature = temperature + 5;` — ডানপাশের expression (`temperature + 5`, অর্থাৎ `25 + 5 = 30`) প্রথমে মূল্যায়িত হয়, তারপর সেই ফলাফল `temperature`-এ assign হয়।

**উদাহরণ ৩ — Narrowing Conversion প্রতিরোধ:**
```cpp
#include <iostream>

int main()
{
    // int x{ 3.7 };   // কম্পাইল এরর! narrowing conversion ধরা পড়ে
    int y = 3.7;         // কম্পাইল হয়, কিন্তু y = 3 (তথ্য নীরবে হারিয়ে যায়)
    std::cout << y << std::endl;
    return 0;
}
```

### Common Mistakes (সাধারণ ভুল)

1. **`=` কে গাণিতিক "সমান" ভাবা** — গণিতে `x = x + 1` অসম্ভব একটি সমীকরণ, কিন্তু প্রোগ্রামিং-এ এটি সম্পূর্ণ বৈধ — এটি বলছে "x-এর বর্তমান মানের সাথে 1 যোগ করে আবার x-এ সংরক্ষণ করো"।

2. **Variable ঘোষণা করে initialize না করা:**
   ```cpp
   int count;   // এখানে count-এর মান অনির্ধারিত
   std::cout << count;   // undefined behavior — 1.6 বিভাগে বিস্তারিত
   ```

3. **Copy initialization এবং assignment গুলিয়ে ফেলা:**
   ```cpp
   int x = 5;   // এটি initialization (যদিও '=' চিহ্ন ব্যবহৃত হয়েছে), assignment নয়, কারণ x এখানেই প্রথমবার তৈরি হচ্ছে
   ```
   এই বিভ্রান্তির কারণ হলো copy initialization-এও `=` চিহ্ন ব্যবহৃত হয়, যদিও এটি প্রকৃতপক্ষে initialization।

4. **Narrowing conversion উপেক্ষা করা:**
   ```cpp
   int total = 9.99;   // silently truncate হয়ে total = 9 হয়ে যায় — বিপজ্জনক, কারণ কোনো এরর/ওয়ার্নিং সহজে চোখে পড়ে না
   ```

### Professional Tips (প্রফেশনাল পরামর্শ)

- সবসময় variable ঘোষণার সময়েই initialize করুন — কখনো "খালি" variable ঘোষণা করে রাখবেন না।
- Brace initialization (`{ }`) ব্যবহার করুন, বিশেষত এমন ক্ষেত্রে যেখানে টাইপ মিসম্যাচের ঝুঁকি থাকতে পারে।
- যদি একটি variable-এর প্রাথমিক মান নির্দিষ্ট না থাকে কিন্তু ডিফল্ট (যেমন 0) দিয়ে শুরু করতে চান, `int x{};` ব্যবহার করুন — এটি স্পষ্টভাবে বোঝায় যে এটি ইচ্ছাকৃতভাবে খালি/শূন্য রাখা হয়েছে।
- Google C++ Style Guide-সহ অধিকাংশ আধুনিক স্টাইল গাইড brace initialization-কে প্রস্তাবিত পদ্ধতি হিসেবে নির্দেশ করে।

### Deep Understanding — কেন Brace Initialization "Uniform" বলা হয়

C++11-এর আগে, বিভিন্ন প্রসঙ্গে (fundamental type, array, class object) initialize করার জন্য ভিন্ন ভিন্ন সিনট্যাক্স প্রয়োজন হতো, যা ভাষাকে অসামঞ্জস্যপূর্ণ করে তুলেছিল। Brace initialization এই সমস্যার সমাধান করে — এটি প্রায় সবক্ষেত্রেই একইভাবে কাজ করে:

```cpp
int x{ 5 };                        // fundamental type
int arr[]{ 1, 2, 3 };               // array
// MyClass obj{ arg1, arg2 };       // class object (ভবিষ্যৎ চ্যাপ্টারে আলোচিত হবে)
```

এই সামঞ্জস্যতার কারণেই একে "uniform initialization" বলা হয় — একটি একক সিনট্যাক্স, যা প্রায় সব প্রসঙ্গে কাজ করে।

### Behind the Scenes — Narrowing Conversion কীভাবে ধরা পড়ে

যখন কম্পাইলার brace initialization প্রক্রিয়া করে, তখন এটি উৎস মানের (source value) টাইপ এবং লক্ষ্য variable-এর (target variable) টাইপ তুলনা করে দেখে কোনো সম্ভাব্য তথ্য ক্ষতি (data loss) হতে পারে কিনা। যদি এমন ঝুঁকি থাকে (যেমন `double` থেকে `int`-এ রূপান্তর, যেখানে দশমিক অংশ হারিয়ে যেতে পারে), কম্পাইলার এটিকে **compile-time error** হিসেবে চিহ্নিত করে, প্রোগ্রাম কম্পাইলই হতে দেয় না। এটি copy বা direct initialization-এর তুলনায় brace initialization-কে উল্লেখযোগ্যভাবে নিরাপদ করে তোলে, কারণ এই ধরনের ভুল রানটাইমে গিয়ে আবিষ্কারের বদলে কম্পাইল-টাইমেই ধরা পড়ে।

### Interview Questions

1. **প্রশ্ন:** Initialization এবং assignment-এর মধ্যে মূল পার্থক্য কী?
   **উত্তর:** Initialization ঘটে variable তৈরির মুহূর্তেই, প্রাথমিক মান নির্ধারণের জন্য। Assignment ঘটে তৈরি হওয়া বিদ্যমান variable-এর মান পরিবর্তনের জন্য, এবং এটি একাধিকবার ঘটতে পারে।

2. **প্রশ্ন:** কেন আধুনিক C++-এ brace initialization (`{ }`) প্রস্তাবিত?
   **উত্তর:** কারণ এটি narrowing conversion (যেমন double থেকে int-এ তথ্য হারিয়ে যাওয়া) কম্পাইল-টাইমেই ধরে ফেলে, এবং এটি একটি সামঞ্জস্যপূর্ণ (uniform) সিনট্যাক্স প্রদান করে যা প্রায় সব প্রসঙ্গে কাজ করে।

3. **প্রশ্ন:** `int x{};` এর ফলাফল কী হবে?
   **উত্তর:** এটি value initialization — `x`-এর মান হবে `0` (int টাইপের ডিফল্ট মান)।

### Practice Problems

1. চারটি ভিন্ন পদ্ধতিতে (default, copy, direct, brace) একটি করে int variable ঘোষণা করুন এবং তাদের পার্থক্য ব্যাখ্যা করুন।
2. নিচের কোডে কী সমস্যা আছে এবং কেন তা ব্যাখ্যা করুন:
   ```cpp
   int total{ 15.75 };
   ```
3. একটি variable-কে প্রথমে `10` দিয়ে initialize করুন, তারপর তিনবার assignment-এর মাধ্যমে এর মান পরিবর্তন করুন এবং প্রতিবার প্রদর্শন করুন।

## 1.5 Introduction to iostream: cout, cin, and endl

### Definition — Input/Output (I/O) ধারণা

একটি প্রোগ্রামকে বাস্তবে কার্যকর হতে হলে বাইরের জগতের সাথে যোগাযোগ করতে হয় — ব্যবহারকারীর কাছ থেকে তথ্য গ্রহণ করা (**input**) এবং ফলাফল প্রদর্শন করা (**output**)। C++-এ এই কাজের জন্য ব্যবহৃত হয় **iostream** লাইব্রেরি।

### iostream Library

`iostream` (input-output stream) হলো C++ স্ট্যান্ডার্ড লাইব্রেরির একটি অংশ, যা কনসোল (console) এর মাধ্যমে ইনপুট গ্রহণ ও আউটপুট প্রদর্শনের সুবিধা প্রদান করে। এটি ব্যবহার করতে হলে প্রোগ্রামের শুরুতে এটি include করতে হয়:

```cpp
#include <iostream>
```

### Header File (হেডার ফাইল) কী?

**Header file** হলো এমন একটি ফাইল, যেখানে function, class, বা variable-এর ঘোষণা (declaration) থাকে, যা প্রোগ্রামে ব্যবহার করার জন্য প্রয়োজন। `#include <iostream>` লেখার মাধ্যমে আমরা কম্পাইলারকে বলি `iostream` হেডার ফাইলের কন্টেন্ট আমাদের প্রোগ্রামে যুক্ত করতে, যাতে আমরা `std::cout`, `std::cin`-এর মতো টুল ব্যবহার করতে পারি।

`< >` (angle brackets) ব্যবহার করা হয় স্ট্যান্ডার্ড লাইব্রেরি হেডার ফাইলের জন্য, আর `" "` (quotation marks) ব্যবহার করা হয় নিজের তৈরি করা হেডার ফাইলের জন্য (এই বিষয়টি ভবিষ্যৎ চ্যাপ্টারে বিস্তারিত আলোচিত হবে)।

### std::cout — আউটপুট প্রদর্শন

**`std::cout`** ("character output" এর সংক্ষিপ্ত রূপ) একটি **object**, যা কনসোলে (সাধারণত টার্মিনাল বা কমান্ড প্রম্পট) টেক্সট প্রদর্শন করতে ব্যবহৃত হয়। এটি ব্যবহার করা হয় **insertion operator (`<<`)** এর সাথে।

```cpp
std::cout << "হ্যালো, বিশ্ব!";
```

এখানে `<<` অপারেটরটি বোঝায় "ডানপাশের ডেটা `std::cout`-এ পাঠাও (insert করো)"।

**একাধিক আইটেম একসাথে প্রদর্শন:**
```cpp
int age{ 25 };
std::cout << "বয়স: " << age << " বছর";
```
এখানে `<<` অপারেটর একাধিকবার ব্যবহার (chain) করা যায়, যা একাধিক ভিন্ন ধরনের ডেটা (টেক্সট, variable, সংখ্যা) একসাথে প্রদর্শন করার সুযোগ দেয়।

### একাধিক Output Statement এবং লাইন বিভাজনের প্রয়োজনীয়তা

একটি গুরুত্বপূর্ণ বিষয় প্রথমেই স্পষ্ট বোঝা দরকার: **আলাদা আলাদা `std::cout` স্টেটমেন্ট নিজে থেকে আউটপুটকে আলাদা লাইনে ভাগ করে না।**

```cpp
#include <iostream>

int main()
{
    std::cout << "Hi!";
    std::cout << "আমার নাম রাহাত।";
    return 0;
}
```

**আউটপুট:**
```
Hi!আমার নাম রাহাত।
```

দুইটি আলাদা `std::cout` স্টেটমেন্ট থাকা সত্ত্বেও, আউটপুট একই লাইনে জোড়া লেগে গেছে — কোনো স্পেস বা লাইন-ব্রেক ছাড়াই। এর কারণ, `std::cout` শুধু যা বলা হয়েছে ঠিক তাই প্রিন্ট করে, নিজে থেকে কোনো অতিরিক্ত ফাঁকা জায়গা বা নতুন লাইন যোগ করে না। যদি আউটপুটকে আলাদা আলাদা লাইনে দেখাতে হয়, তাহলে স্পষ্টভাবে একটি **newline (নতুন লাইন)** আউটপুট করতে হবে — এই কাজেই `std::endl` বা `'\n'` ব্যবহৃত হয়, যা এখন আলোচনা করা হচ্ছে।

### std::endl — নতুন লাইনে যাওয়া

**`std::endl`** ("end line" এর সংক্ষিপ্ত রূপ) কার্সারকে পরবর্তী লাইনে নিয়ে যায় এবং আউটপুট বাফার **flush** করে (অর্থাৎ, যা কিছু এখনো প্রদর্শিত হয়নি তা তৎক্ষণাৎ প্রদর্শন করে)।

```cpp
std::cout << "প্রথম লাইন" << std::endl;
std::cout << "দ্বিতীয় লাইন" << std::endl;
```

**বিকল্প: `'\n'` (newline character)**

```cpp
std::cout << "প্রথম লাইন" << '\n';
std::cout << "দ্বিতীয় লাইন" << '\n';
```

`'\n'` শুধু নতুন লাইনে যায়, কিন্তু বাফার flush করে না — এই কারণে এটি সাধারণত `std::endl`-এর চেয়ে বেশি efficient, বিশেষত যখন বহুবার নতুন লাইনে যাওয়ার প্রয়োজন হয় (যেমন একটি লুপের ভেতরে)। আধুনিক C++ প্র্যাকটিসে, পারফরম্যান্স গুরুত্বপূর্ণ হলে `'\n'` প্রস্তাবিত, তবে শেখার পর্যায়ে উভয়ই ব্যবহার করা যেতে পারে।

### std::cin — ইনপুট গ্রহণ

**`std::cin`** ("character input" এর সংক্ষিপ্ত রূপ) ব্যবহারকারীর কাছ থেকে ইনপুট গ্রহণ করতে ব্যবহৃত হয়। এটি ব্যবহার করা হয় **extraction operator (`>>`)** এর সাথে।

```cpp
int age{};
std::cout << "আপনার বয়স লিখুন: ";
std::cin >> age;
std::cout << "আপনার বয়স: " << age;
```

এখানে `>>` অপারেটরটি বোঝায় "ব্যবহারকারীর ইনপুট থেকে ডেটা বের করে (extract করে) ডানপাশের variable-এ রাখো"।

**একাধিক ইনপুট একসাথে গ্রহণ:**
```cpp
int x{}, y{};
std::cout << "দুইটি সংখ্যা লিখুন: ";
std::cin >> x >> y;
```
এখানে ব্যবহারকারী স্পেস বা এন্টার দিয়ে আলাদা করে দুইটি সংখ্যা লিখতে পারবেন, যা যথাক্রমে `x` এবং `y`-এ সংরক্ষিত হবে।

### `std::` প্রিফিক্স কেন প্রয়োজন

`std::cout`, `std::cin`, `std::endl` — প্রতিটির আগে `std::` লেখা থাকে, কারণ এগুলো **`std` namespace**-এর অন্তর্গত। **Namespace** হলো একটি নামকরণ ব্যবস্থা, যা বিভিন্ন লাইব্রেরির identifier-দের মধ্যে নামের সংঘর্ষ (naming collision) প্রতিরোধ করে।

```cpp
std::cout << "উদাহরণ";   // std namespace-এর cout ব্যবহার করা হচ্ছে
```

কিছু পুরনো কোডে `using namespace std;` লেখা দেখা যায়, যা প্রতিবার `std::` লেখার প্রয়োজনীয়তা দূর করে। কিন্তু **এই প্র্যাকটিস প্রফেশনাল কোডে সুপারিশ করা হয় না**, কারণ এটি নামের সংঘর্ষের ঝুঁকি বাড়ায়, বিশেষত বড় প্রজেক্টে যেখানে একাধিক লাইব্রেরি একসাথে ব্যবহৃত হয়। এই বইয়ে সবসময় সরাসরি `std::` প্রিফিক্স ব্যবহার করা হবে, যা Google C++ Style Guide-এর সাথেও সামঞ্জস্যপূর্ণ।

### Output Formatting (আউটপুট ফরম্যাটিং)

`std::cout` বিভিন্ন ডেটা টাইপ স্বয়ংক্রিয়ভাবে সঠিকভাবে ফরম্যাট করে প্রদর্শন করে:

```cpp
#include <iostream>

int main()
{
    std::cout << 42 << std::endl;          // int
    std::cout << 3.14 << std::endl;         // double
    std::cout << 'A' << std::endl;          // char
    std::cout << true << std::endl;         // bool — আউটপুট হবে 1 (0 = false, 1 = true)
    std::cout << "টেক্সট" << std::endl;      // string literal
    return 0;
}
```

লক্ষণীয়, `bool` টাইপের মান `true`/`false` টেক্সট হিসেবে না দেখিয়ে ডিফল্টভাবে `1`/`0` হিসেবে দেখায়। এটি পরিবর্তন করার একটি উপায় আছে (`std::boolalpha`), যা ভবিষ্যৎ চ্যাপ্টারে আলোচিত হতে পারে।

### একাধিক উদাহরণ

**উদাহরণ ১ — সম্পূর্ণ Input-Output প্রোগ্রাম:**
```cpp
#include <iostream>

int main()
{
    std::cout << "আপনার নাম লিখুন: ";
    // এই সাধারণ উদাহরণে string ইনপুট এড়ানো হয়েছে, শুধু সংখ্যাগত ইনপুট দেখানো হচ্ছে
    int birthYear{};
    std::cout << "আপনার জন্মসাল লিখুন: ";
    std::cin >> birthYear;

    int currentYear{ 2026 };
    int age{ currentYear - birthYear };

    std::cout << "আপনার আনুমানিক বয়স: " << age << " বছর" << std::endl;
    return 0;
}
```
**লাইন-বাই-লাইন ব্যাখ্যা:**
- `std::cout << "আপনার জন্মসাল লিখুন: ";` — ব্যবহারকারীকে নির্দেশনা প্রদর্শন করে।
- `std::cin >> birthYear;` — ব্যবহারকারীর টাইপ করা সংখ্যা `birthYear`-এ সংরক্ষিত হয়।
- `int age{ currentYear - birthYear };` — বিয়োগফল গণনা করে নতুন variable-এ সংরক্ষিত হয়।
- শেষ লাইনে ফলাফল প্রদর্শিত হয়।

**উদাহরণ ২ — একাধিক ইনপুট গ্রহণ:**
```cpp
#include <iostream>

int main()
{
    int length{}, width{};
    std::cout << "আয়তক্ষেত্রের দৈর্ঘ্য ও প্রস্থ লিখুন: ";
    std::cin >> length >> width;

    int area{ length * width };
    std::cout << "ক্ষেত্রফল: " << area << std::endl;
    return 0;
}
```

**উদাহরণ ৩ — `'\n'` বনাম `std::endl`:**
```cpp
#include <iostream>

int main()
{
    std::cout << "লাইন ১" << '\n';        // দ্রুততর, বাফার flush করে না
    std::cout << "লাইন ২" << std::endl;    // বাফার flush করে, তুলনামূলক ধীর
    return 0;
}
```

### Common Mistakes (সাধারণ ভুল)

1. **`<<` এবং `>>` অপারেটর গুলিয়ে ফেলা:**
   ```cpp
   std::cout >> "ভুল";   // এরর! cout এর সাথে >> নয়, << ব্যবহার হয়
   std::cin << age;        // এরর! cin এর সাথে << নয়, >> ব্যবহার হয়
   ```
   মনে রাখার সহজ উপায়: তীরচিহ্নটি ডেটা প্রবাহের দিক নির্দেশ করে — `cout <<` মানে ডেটা প্রোগ্রাম থেকে বেরিয়ে যাচ্ছে (আউটপুট), `cin >>` মানে ডেটা প্রোগ্রামে প্রবেশ করছে (ইনপুট)।

2. **`std::` প্রিফিক্স ভুলে যাওয়া:**
   ```cpp
   cout << "ভুল";   // এরর! কম্পাইলার জানে না cout কোথা থেকে এসেছে
   ```

3. **`#include <iostream>` না লেখা:**
   ```cpp
   int main()
   {
       std::cout << "এরর হবে";   // এরর! iostream include করা হয়নি
       return 0;
   }
   ```

4. **টাইপ-মিসম্যাচড ইনপুট গ্রহণ করা** — যদি একটি `int` variable-এর জন্য ব্যবহারকারী টেক্সট টাইপ করেন, `std::cin` **fail state**-এ চলে যায়, এবং variable-এর মান অনির্ধারিত থেকে যায়। এই সমস্যা সমাধানের কৌশল (input validation) ভবিষ্যৎ চ্যাপ্টারে আলোচিত হবে।

5. **ফরওয়ার্ড স্ল্যাশ `'/n'` কে ব্যাকস্ল্যাশ `'\n'` ভেবে ভুল করা** — এটি একটি বিশেষভাবে বিপজ্জনক ভুল, কারণ এটি কম্পাইল হয়ে যায় (শুধু একটি warning সহ), কিন্তু সম্পূর্ণ ভুল আউটপুট দেয়:
   ```cpp
   std::cout << "টেক্সট" << '/n';   // ভুল! এটি newline নয়, বরং একটি multi-character literal
   ```
   এখানে `'/n'` আসলে দুইটি ক্যারেক্টার (`/` এবং `n`) নিয়ে গঠিত একটি অবৈধ multi-character literal, নতুন লাইন নয়। এটি প্রায়ই একটি অদ্ভুত সংখ্যা (যেমন `12142`) প্রিন্ট করে, যা প্রত্যাশিত নতুন লাইনের বদলে দেখা যায়। সবসময় ব্যাকস্ল্যাশ (`\`) ব্যবহার করুন, ফরওয়ার্ড স্ল্যাশ (`/`) নয়।

6. **`std::endl` অতিরিক্ত ব্যবহার করা**, যেখানে `'\n'` যথেষ্ট এবং বেশি efficient — বিশেষত লুপের ভেতরে বারবার আউটপুট করার সময় এই পার্থক্য পারফরম্যান্সে লক্ষণীয় হতে পারে।

### Professional Tips (প্রফেশনাল পরামর্শ)

- সাধারণ ক্ষেত্রে `'\n'` ব্যবহার করুন, এবং শুধুমাত্র তখনই `std::endl` ব্যবহার করুন যখন সত্যিই বাফার তৎক্ষণাৎ flush করা প্রয়োজন (যেমন প্রোগ্রাম ক্র্যাশ করার আগে শেষ বার্তা নিশ্চিতভাবে প্রদর্শনের জন্য)।
- কখনো `using namespace std;` ব্যবহার করবেন না প্রফেশনাল কোডে — সবসময় `std::` প্রিফিক্স স্পষ্টভাবে লিখুন।
- ব্যবহারকারীকে ইনপুট দেওয়ার আগে সবসময় স্পষ্ট নির্দেশনা (prompt) প্রদর্শন করুন, যাতে ব্যবহারকারী জানেন কী ইনপুট দিতে হবে।
- একাধিক সম্পর্কিত আউটপুট স্টেটমেন্ট একসাথে chain করে লিখুন, যা কোডকে আরও readable করে তোলে।

### Deep Understanding — Stream (স্ট্রিম) ধারণা

`cout` এবং `cin` প্রকৃতপক্ষে **stream object** — এগুলো ডেটার একটি "প্রবাহ" (flow) প্রতিনিধিত্ব করে। `std::cout` একটি **output stream**, যা ডেটাকে প্রোগ্রাম থেকে বাইরে (কনসোলে) পাঠায়। `std::cin` একটি **input stream**, যা ডেটাকে বাইরে (কীবোর্ড) থেকে প্রোগ্রামে নিয়ে আসে।

এই "stream" ধারণাটি একটি নদীর প্রবাহের সাথে তুলনা করা যায় — ডেটা একমুখীভাবে প্রবাহিত হয়, এবং `<<`/`>>` অপারেটর সেই প্রবাহের দিক নির্দেশ করে। এই একই stream ধারণা পরবর্তীতে ফাইল I/O (`fstream`) এবং string stream (`sstream`) নিয়ে কাজ করার সময়ও প্রযোজ্য হবে, যা ভবিষ্যৎ চ্যাপ্টারে আলোচিত হবে।

### Behind the Scenes — Buffer (বাফার) কীভাবে কাজ করে

যখন আমরা `std::cout << "কিছু টেক্সট";` লিখি, তখন টেক্সটটি সরাসরি স্ক্রিনে না গিয়ে প্রথমে একটি **buffer** (অস্থায়ী মেমোরি এলাকা) তে জমা হয়। এই বাফারিং সিস্টেমের কারণ হলো পারফরম্যান্স — স্ক্রিনে বারবার সরাসরি লেখা (যা একটি ধীর অপারেশন) এড়িয়ে, ডেটা জমিয়ে রেখে একসাথে প্রদর্শন করা বেশি efficient।

`std::endl` এই বাফারকে জোরপূর্বক **flush** করে — অর্থাৎ, বাফারে জমে থাকা সবকিছু তৎক্ষণাৎ স্ক্রিনে প্রদর্শন করে দেয়। `'\n'` শুধু একটি newline character যোগ করে, বাফার flush-এর অনুরোধ করে না।

একটি গুরুত্বপূর্ণ বিষয় হলো, `std::cout` নিজে থেকেই নিয়মিত বিরতিতে (periodically) স্বয়ংক্রিয়ভাবে flush হওয়ার জন্য ডিজাইন করা — এটি efficient ভাবে নিজে থেকেই বাফার flush করে, প্রোগ্রামারের manual হস্তক্ষেপ ছাড়াই। এই কারণেই `std::endl` ব্যবহার করে বারবার explicit ভাবে flush করা প্রায়ই **অপ্রয়োজনীয় (redundant)** — সিস্টেম এমনিতেই এই কাজটি efficient ভাবে করে দেয়। এটিই মূল কারণ কেন `'\n'` সাধারণভাবে প্রস্তাবিত: এটি অপ্রয়োজনীয় flush request এড়িয়ে সিস্টেমকে নিজের মতো করে flush করতে দেয়।

### Professional Programmer Notes

বাস্তব প্রফেশনাল সফটওয়্যারে, কনসোল-ভিত্তিক I/O (যেমন `cout`/`cin`) সাধারণত শুধুমাত্র ছোট ইউটিলিটি প্রোগ্রাম, ডিবাগিং, বা লার্নিং পার্পাসে ব্যবহৃত হয়। বড় স্কেল সফটওয়্যারে (যেমন GUI অ্যাপ্লিকেশন বা ওয়েব সার্ভার), ডেটা সাধারণত গ্রাফিক্যাল ইন্টারফেস, নেটওয়ার্ক, বা ফাইলের মাধ্যমে ইনপুট/আউটপুট হয়। তবে, `iostream`-এর মূল ধারণা (stream, buffer, insertion/extraction operator) সেসব ক্ষেত্রেও প্রযোজ্য থাকে।

### Interview Questions

1. **প্রশ্ন:** `std::cout` এবং `std::cin`-এর মধ্যে পার্থক্য কী?
   **উত্তর:** `std::cout` একটি output stream, যা `<<` অপারেটরের মাধ্যমে ডেটা কনসোলে প্রদর্শন করে। `std::cin` একটি input stream, যা `>>` অপারেটরের মাধ্যমে ব্যবহারকারীর কাছ থেকে ডেটা গ্রহণ করে।

2. **প্রশ্ন:** `std::endl` এবং `'\n'`-এর মধ্যে পার্থক্য কী, এবং কোনটি সাধারণত প্রস্তাবিত?
   **উত্তর:** উভয়ই নতুন লাইনে নিয়ে যায়, কিন্তু `std::endl` অতিরিক্তভাবে আউটপুট বাফার flush করে, যা তুলনামূলক ধীর। `'\n'` শুধু নতুন লাইনে যায়, বাফার flush করে না। সাধারণ ক্ষেত্রে `'\n'` বেশি efficient এবং প্রস্তাবিত, `std::endl` শুধু প্রয়োজনে ব্যবহার করা উচিত।

3. **প্রশ্ন:** প্রফেশনাল কোডে `using namespace std;` এড়িয়ে চলার কারণ কী?
   **উত্তর:** এটি নামের সংঘর্ষের (naming collision) ঝুঁকি বাড়ায়, বিশেষত বড় প্রজেক্টে একাধিক লাইব্রেরি একসাথে ব্যবহৃত হলে। সরাসরি `std::` প্রিফিক্স ব্যবহার করা কোডকে স্পষ্ট ও নিরাপদ রাখে।

## 1.6 Uninitialized Variables and Undefined Behavior

### Definition — Uninitialized Variable কী?

একটি variable যখন ঘোষণা করা হয় কিন্তু কোনো প্রাথমিক মান দেওয়া হয় না (default initialization), তখন সেই variable-কে **uninitialized** বলা হয়।

```cpp
int x;   // uninitialized — x-এর মধ্যে কী আছে তা অনির্ধারিত
```

গুরুত্বপূর্ণ বিষয় হলো, "uninitialized" মানে এই নয় যে variable-টি "খালি" বা "শূন্য" — বরং এর মানে হলো, মেমোরির সেই অংশে *আগে থেকেই যা কিছু ছিল*, সেটাই থেকে যায়। এটি হতে পারে যেকোনো এলোমেলো (garbage) বাইনারি প্যাটার্ন, যা পূর্ববর্তী কোনো প্রোগ্রাম বা প্রক্রিয়া রেখে গেছে।

### কেন Uninitialized Variable বিপজ্জনক

যখন একটি variable ঘোষণা করা হয়, কম্পাইলার/অপারেটিং সিস্টেম শুধু মেমোরিতে একটি জায়গা "বরাদ্দ" (reserve) করে — কিন্তু সেই জায়গাটি পরিষ্কার (clear) করে না। ফলে, যদি সেই জায়গায় আগে অন্য কোনো ডেটা থেকে থাকে, নতুন variable-টি সেই পুরনো ডেটাকেই "উত্তরাধিকার" (inherit) হিসেবে পেয়ে যায়।

```cpp
#include <iostream>

int main()
{
    int x;                       // uninitialized
    std::cout << x << std::endl;  // অনির্ধারিত মান প্রদর্শন করবে — প্রতিবার ভিন্ন হতে পারে!
    return 0;
}
```

এই প্রোগ্রামটি প্রতিবার রান করলে ভিন্ন ভিন্ন মান দেখাতে পারে, অথবা কখনো কখনো একই মান দেখাতে পারে (নির্দিষ্ট সিস্টেম ও কম্পাইলারের উপর নির্ভর করে) — কিন্তু এর উপর নির্ভর করা কখনোই নিরাপদ নয়।

### Definition — Undefined Behavior (UB) কী?

**Undefined Behavior (UB)** বলতে বোঝায় এমন কোডের আচরণ, যা C++ ভাষার স্ট্যান্ডার্ড অনুযায়ী **সংজ্ঞায়িত করা নেই** — অর্থাৎ, কম্পাইলার এবং প্রোগ্রামকে *যেকোনো কিছু* করার অনুমতি দেওয়া হয়েছে যখন এই ধরনের কোড এক্সিকিউট করা হয়। UB-যুক্ত কোড নিচের যেকোনো একটি উপসর্গ (symptom) দেখাতে পারে:

- প্রতিবার রান করলে **ভিন্ন ভিন্ন ফলাফল** দিতে পারে
- **প্রতিবারই একই ভুল ফলাফল** সামঞ্জস্যপূর্ণভাবে দিতে পারে (কাকতালীয়ভাবে সবসময় একই "ভুল" মান)
- **অসামঞ্জস্যপূর্ণভাবে আচরণ করতে পারে** — কখনো সঠিক ফলাফল দেয়, কখনো দেয় না
- প্রথমে ঠিকঠাক কাজ করছে বলে মনে হতে পারে, কিন্তু পরবর্তীতে প্রোগ্রামের অন্য কোনো অংশে ভুল ফলাফল প্রকাশ পেতে পারে
- প্রোগ্রাম ক্র্যাশ করতে পারে, সাথে সাথে অথবা পরে
- **এক কম্পাইলার/প্ল্যাটফর্মে কাজ করতে পারে, কিন্তু অন্যটিতে না** — এমনকি একই কোড ভিন্ন কম্পাইলার বা অপারেটিং সিস্টেমে ভিন্ন ফলাফল দিতে পারে, কারণ কম্পাইলারও ধরে নেয় UB কখনো ঘটবে না এবং সেই অনুযায়ী optimization করে

Uninitialized variable ব্যবহার করা undefined behavior-এর সবচেয়ে সাধারণ উদাহরণগুলোর একটি — এবং প্রায়ই এটিই একজন C++ শিক্ষার্থীর মুখোমুখি হওয়া প্রথম undefined behavior-এর উদাহরণ।

### কেন Undefined Behavior এত বিপজ্জনক

Undefined behavior-এর সবচেয়ে ভয়ংকর দিক হলো এর **অনির্ভরযোগ্যতা (unpredictability)**। একটি প্রোগ্রাম যেটিতে UB আছে:

1. **ডেভেলপমেন্টের সময় ঠিকঠাক কাজ করতে পারে**, কিন্তু production-এ (ভিন্ন হার্ডওয়্যার, ভিন্ন কম্পাইলার, ভিন্ন optimization level-এ) ব্যর্থ হতে পারে।
2. **মাঝে মাঝে কাজ করতে পারে, মাঝে মাঝে না** — যা bug খুঁজে বের করা অত্যন্ত কঠিন করে তোলে।
3. **কম্পাইলার আপডেট করলে ভিন্ন আচরণ করতে পারে**, কারণ নতুন কম্পাইলার ভার্সন ভিন্নভাবে optimize করতে পারে।

এই কারণেই প্রফেশনাল C++ ডেভেলপমেন্টে undefined behavior সম্পূর্ণভাবে এড়িয়ে চলা একটি সর্বোচ্চ অগ্রাধিকারের বিষয়।

### Memory-related Problems (মেমোরি-সংক্রান্ত সমস্যা)

Uninitialized variable ছাড়াও, undefined behavior-এর সাথে সম্পর্কিত আরও কিছু সাধারণ মেমোরি সমস্যা রয়েছে, যেগুলোর গভীর আলোচনা ভবিষ্যৎ চ্যাপ্টারে হবে, কিন্তু প্রাথমিক পরিচিতি এখানে গুরুত্বপূর্ণ:

- **Uninitialized memory read** — যা আমরা এই বিভাগে আলোচনা করছি।
- **Out-of-bounds access** — নির্ধারিত সীমার বাইরে মেমোরি অ্যাক্সেস করার চেষ্টা (array নিয়ে কাজ করার সময় প্রাসঙ্গিক হবে)।
- **Dangling reference/pointer** — এমন মেমোরি ব্যবহার করার চেষ্টা যা ইতিমধ্যে মুক্ত (deallocate) হয়ে গেছে (এই ধারণাটি pointer ও reference নিয়ে কাজ করার সময় বিস্তারিত আলোচিত হবে)।

এই মুহূর্তে, বিগিনার হিসেবে সবচেয়ে গুরুত্বপূর্ণ হলো এই প্যাটার্নটি মনে রাখা: **"সবসময় ব্যবহারের আগে initialize করুন।"**

### কীভাবে প্রফেশনাল প্রোগ্রামাররা এই সমস্যা এড়ান

1. **সবসময় ঘোষণার সময়েই variable initialize করুন:**
   ```cpp
   int x{ 0 };    // নিরাপদ — স্পষ্ট প্রাথমিক মান
   int y{};        // নিরাপদ — value initialization, y = 0
   ```

2. **কম্পাইলার ওয়ার্নিং চালু রাখুন এবং মনোযোগ দিন** — আধুনিক কম্পাইলার (GCC, Clang, MSVC) সাধারণত uninitialized variable ব্যবহারের ক্ষেত্রে ওয়ার্নিং দেখায়, যদি সঠিক ফ্ল্যাগ (যেমন `-Wall -Wextra`) ব্যবহার করা হয়।

3. **Static analysis টুল ব্যবহার করুন** — বড় প্রজেক্টে, স্বয়ংক্রিয় টুল (যেমন Clang-Tidy, Cppcheck) কোড বিশ্লেষণ করে সম্ভাব্য uninitialized variable ব্যবহার চিহ্নিত করে দিতে পারে।

4. **Sanitizer ব্যবহার করুন** — ডেভেলপমেন্টের সময়, বিশেষ টুল (যেমন AddressSanitizer, MemorySanitizer) রানটাইমে মেমোরি-সংক্রান্ত সমস্যা শনাক্ত করতে সাহায্য করে।

### একাধিক উদাহরণ

**উদাহরণ ১ — Uninitialized Variable-এর বিপদ প্রদর্শন:**
```cpp
#include <iostream>

int main()
{
    int x;   // uninitialized
    // x-এর মান কী হবে তা অনিশ্চিত — এটি প্রোগ্রাম চালানোর প্রতিটি বার ভিন্ন হতে পারে
    std::cout << "x-এর মান: " << x << std::endl;   // অনির্ধারিত আউটপুট — এড়িয়ে চলা উচিত
    return 0;
}
```

**উদাহরণ ২ — সঠিক এবং নিরাপদ পদ্ধতি:**
```cpp
#include <iostream>

int main()
{
    int x{ 0 };   // সঠিকভাবে initialize করা হয়েছে
    std::cout << "x-এর মান: " << x << std::endl;   // সবসময় নির্ভরযোগ্যভাবে 0 প্রদর্শন করবে
    return 0;
}
```

**উদাহরণ ৩ — Uninitialized Variable ব্যবহার করে গণনা (কেন এটি বিপজ্জনক):**
```cpp
#include <iostream>

int main()
{
    int total;                  // uninitialized!
    total = total + 10;          // total-এর 'পুরনো' অনির্ধারিত মানের সাথে 10 যোগ হচ্ছে — ফলাফল অনির্ভরযোগ্য
    std::cout << total << std::endl;
    return 0;
}
```
এই উদাহরণটি দেখায় কীভাবে একটি ছোট ভুল (initialize করতে ভুলে যাওয়া) পুরো গণনার ফলাফলকে অনির্ভরযোগ্য করে তুলতে পারে।

### Common Mistakes (সাধারণ ভুল)

1. **শুধু ঘোষণা করে ভুলে যাওয়া যে initialize করা হয়নি:**
   ```cpp
   int score;
   // ... অনেক লাইন কোড পরে ...
   std::cout << score;   // ভুলে যাওয়া হয়েছে যে score initialize করা হয়নি
   ```

2. **"সাধারণত কাজ করে" এই ধারণায় নির্ভর করা** — কিছু সিস্টেমে/কম্পাইলারে, ডিবাগ মোডে uninitialized variable প্রায়ই একটি নির্দিষ্ট (যেমন 0) মান দেখাতে পারে, যা প্রোগ্রামারকে ভুলভাবে বিশ্বাস করায় যে কোডটি "ঠিক আছে"। কিন্তু release/optimized build-এ বা ভিন্ন সিস্টেমে এই আচরণ সম্পূর্ণ ভিন্ন হতে পারে।

3. **Conditional logic-এ uninitialized variable ব্যবহার করা** — যেমন `if` কন্ডিশনে ব্যবহৃত হলে, প্রোগ্রামের সম্পূর্ণ execution path অনির্ভরযোগ্য হয়ে যেতে পারে (এই ধারণা `if` statement শেখার পর আরও স্পষ্ট হবে)।

### Professional Tips (প্রফেশনাল পরামর্শ)

- **কোনো ব্যতিক্রম ছাড়াই, সবসময় variable initialize করুন** — এমনকি যদি মনে হয় "এটা তো এমনিতেই পরে assign হয়ে যাবে," ভবিষ্যতে কোড পরিবর্তনের সময় এই ধারণা ভুল প্রমাণিত হতে পারে।
- কম্পাইল করার সময় সবসময় সর্বোচ্চ ওয়ার্নিং লেভেল চালু রাখুন (`-Wall -Wextra -Werror` এর মতো ফ্ল্যাগ GCC/Clang-এ), যাতে সম্ভাব্য সমস্যা কম্পাইল-টাইমেই ধরা পড়ে।
- কোড রিভিউ-এর সময় uninitialized variable-এর সম্ভাবনা বিশেষভাবে যাচাই করুন — এটি একটি সহজে মিস হয়ে যাওয়া কিন্তু গুরুতর সমস্যা।
- "Undefined behavior ধরে নিয়ে কখনো কোড লিখবেন না" — অর্থাৎ, এমন কোনো আচরণের উপর নির্ভর করবেন না যা ভাষার স্ট্যান্ডার্ড দ্বারা স্পষ্টভাবে সংজ্ঞায়িত নয়, এমনকি যদি সেটি বর্তমানে "কাজ করছে" বলে মনে হয়।

### Deep Understanding — কেন কম্পাইলার Uninitialized Variable-কে "0" দিয়ে পূরণ করে দেয় না

একটি স্বাভাবিক প্রশ্ন হলো: কম্পাইলার কেন প্রতিটি variable-কে স্বয়ংক্রিয়ভাবে 0 দিয়ে পূরণ করে দেয় না, যা এই পুরো সমস্যাই এড়িয়ে যেত?

এর একটি সুনির্দিষ্ট ঐতিহাসিক কারণ আছে: এই আচরণ **C ভাষা থেকে উত্তরাধিকার সূত্রে পাওয়া একটি পারফরম্যান্স অপটিমাইজেশন**, যখন কম্পিউটার এখনকার তুলনায় অনেক ধীর ছিল। একটি concrete উদাহরণ দিয়ে বোঝা যাক: ধরা যাক একটি প্রোগ্রামের একটি ফাইল থেকে ১,০০,০০০টি মান read করার প্রয়োজন — এই ক্ষেত্রে প্রোগ্রামার ১,০০,০০০টি variable তৈরি করবেন, তারপর ফাইলের ডেটা দিয়ে সেগুলো পূরণ করবেন। যদি C++ প্রতিটি variable তৈরির সময় স্বয়ংক্রিয়ভাবে সেগুলোকে ডিফল্ট মান দিয়ে initialize করত, তাহলে এর ফলে ১,০০,০০০টি অতিরিক্ত initialization ঘটত (যা ধীরগতির) — অথচ কোনো লাভ ছাড়াই, কারণ সেই মানগুলো যেভাবেই হোক ফাইলের প্রকৃত ডেটা দিয়ে ওভাররাইট (overwrite) হয়ে যেত।

এই নির্দিষ্ট উদাহরণটি আরও বৃহত্তর একটি C++ দর্শনের সাথে সামঞ্জস্যপূর্ণ: **"আপনি যা ব্যবহার করেন না, তার জন্য মূল্য দিতে হবে না" (zero-overhead principle)**। প্রতিটি variable স্বয়ংক্রিয়ভাবে শূন্য দিয়ে পূরণ করা একটি অতিরিক্ত রানটাইম কাজ, যা প্রতিটি variable তৈরির সময় ঘটবে — এমনকি যেসব ক্ষেত্রে প্রোগ্রামার নিজেই সাথে সাথে একটি ভিন্ন মান দিয়ে সেটি initialize করবেন বা যেখানে মানটি শীঘ্রই ওভাররাইট হয়ে যাবে (যেমন উপরের ফাইল-reading উদাহরণে)। উচ্চ-পারফরম্যান্স প্রয়োজনীয়তার (যেমন গেম ইঞ্জিন, অপারেটিং সিস্টেম) ক্ষেত্রে, এই "অপ্রয়োজনীয়" অতিরিক্ত কাজ উল্লেখযোগ্য পারফরম্যান্স ক্ষতি করতে পারে যদি এটি লক্ষ লক্ষ বার ঘটে।

এই কারণেই C++ প্রোগ্রামারকে দায়িত্ব দেয় সচেতনভাবে সিদ্ধান্ত নেওয়ার — যদি প্রয়োজন হয়, initialize করুন; যদি সত্যিই পারফরম্যান্স-ক্রিটিক্যাল কোনো কারণে না চান (যা অত্যন্ত বিরল এবং উন্নত ব্যবহারকারীদের জন্য), তাহলে না করুন। কিন্তু বিগিনার হিসেবে, এবং প্রায় সব সাধারণ ক্ষেত্রেই, **সবসময় initialize করা উচিত**।

### Behind the Scenes — Undefined Behavior এবং Compiler Optimization

একটি আরও গভীর এবং কিছুটা প্রতিক্রিয়াশীল (counter-intuitive) দিক হলো: কম্পাইলার ধরে নেয় যে প্রোগ্রামে undefined behavior কখনোই ঘটবে না। এই অনুমানের ভিত্তিতে, কম্পাইলার আক্রমণাত্মক (aggressive) optimization করে। যদি একটি কোড পথ কেবল তখনই পৌঁছানো যায় যখন UB ইতিমধ্যে ঘটে গেছে, কম্পাইলার সেই পুরো কোড পথটিকেই "অসম্ভব" ধরে নিয়ে সম্পূর্ণভাবে বাদ দিয়ে দিতে পারে — যার ফলে প্রোগ্রামের আচরণ প্রোগ্রামারের প্রত্যাশার সাথে সম্পূর্ণ সাংঘর্ষিক হয়ে যেতে পারে। এই কারণেই অভিজ্ঞ C++ ডেভেলপাররা বলে থাকেন, "Undefined behavior মানে আক্ষরিক অর্থে *যেকোনো কিছু* ঘটতে পারে" — এটি একটি অতিরঞ্জন নয়, বরং প্রযুক্তিগত বাস্তবতা।

### Professional Programmer Notes

বড় সফটওয়্যার কোম্পানিতে, undefined behavior-জনিত bug থেকে বাঁচতে একাধিক স্তরের সুরক্ষা ব্যবস্থা থাকে:

1. **Compiler warning as error** — কোনো ওয়ার্নিং থাকলে কম্পাইলেশনই ব্যর্থ হয়ে যায়, যাতে ডেভেলপার বাধ্য হন সমস্যা সমাধান করতে।
2. **Continuous Integration (CI) পাইপলাইনে static analyzer চালানো** — প্রতিটি কোড পরিবর্তনের সময় স্বয়ংক্রিয়ভাবে বিশ্লেষণ করা হয়।
3. **Sanitizer-সহ টেস্ট চালানো** — বিশেষভাবে তৈরি বিল্ডে টেস্ট চালিয়ে রানটাইম মেমোরি সমস্যা শনাক্ত করা হয়।
4. **কোড রিভিউ কালচার** — টিমের সদস্যরা একে অপরের কোড পর্যালোচনা করে সম্ভাব্য সমস্যা চিহ্নিত করেন, initialize করা হয়েছে কিনা তা একটি সাধারণ চেকপয়েন্ট।

### Interview Questions

1. **প্রশ্ন:** Uninitialized variable কী, এবং এটি কেন বিপজ্জনক?
   **উত্তর:** এটি এমন একটি variable যা ঘোষণা করা হয়েছে কিন্তু কোনো প্রাথমিক মান দেওয়া হয়নি, ফলে এতে মেমোরিতে আগে থেকে থাকা অনির্ধারিত (garbage) মান থেকে যায়। এটি বিপজ্জনক কারণ এই মানের উপর নির্ভর করে করা যেকোনো গণনা বা সিদ্ধান্ত অনির্ভরযোগ্য এবং অপ্রত্যাশিত ফলাফল দিতে পারে।

2. **প্রশ্ন:** Undefined behavior কী?
   **উত্তর:** Undefined behavior হলো এমন কোডের আচরণ যা C++ ভাষার স্ট্যান্ডার্ড দ্বারা সংজ্ঞায়িত করা নেই। এই ধরনের কোড এক্সিকিউট হলে প্রোগ্রাম যেকোনো কিছু করতে পারে — সঠিক ফলাফল দিতে পারে, ভুল ফলাফল দিতে পারে, ক্র্যাশ করতে পারে, অথবা সম্পূর্ণ অপ্রত্যাশিত আচরণ দেখাতে পারে।

3. **প্রশ্ন:** কীভাবে একজন প্রোগ্রামার undefined behavior-এর ঝুঁকি কমাতে পারেন?
   **উত্তর:** সবসময় variable initialize করে, কম্পাইলার ওয়ার্নিং চালু রেখে ও মনোযোগ দিয়ে, static analysis টুল ব্যবহার করে, এবং কোনো অনির্ধারিত আচরণের উপর নির্ভর না করে কোড লিখে।

### Practice Problems

1. একটি প্রোগ্রাম লিখুন যেখানে ইচ্ছাকৃতভাবে একটি uninitialized variable ব্যবহার করা হয়েছে, তারপর সেটিকে সঠিকভাবে initialize করে ঠিক করুন।
2. ব্যাখ্যা করুন কেন "প্রোগ্রামটি চলার সময় ঠিকঠাক আউটপুট দিয়েছে" এই তথ্যটি প্রমাণ করে না যে কোডে undefined behavior নেই।
3. তিনটি ভিন্ন পদ্ধতি তালিকাভুক্ত করুন যা একজন প্রফেশনাল প্রোগ্রামার uninitialized variable-জনিত bug এড়াতে ব্যবহার করতে পারেন।

## 1.7 Keywords and Naming Identifiers

### Definition — Keyword কী?

**Keyword** হলো এমন শব্দ, যেগুলো C++ ভাষার সিনট্যাক্সে বিশেষ, সংরক্ষিত (reserved) অর্থ বহন করে। এই শব্দগুলো ভাষার কাঠামোর অংশ, তাই এগুলো variable, function, বা অন্য কোনো identifier-এর নাম হিসেবে ব্যবহার করা যায় না।

C++-এ প্রায় ৯৫টিরও বেশি keyword আছে (ভাষার ভার্সন অনুযায়ী সংখ্যা কিছুটা ভিন্ন হতে পারে)। এই চ্যাপ্টার পর্যন্ত আমরা যেসব keyword ব্যবহার করেছি তার কয়েকটি:

```cpp
int      double    char      bool
return   true      false
```

কিছু অতিরিক্ত সাধারণ keyword, যা ভবিষ্যৎ চ্যাপ্টারগুলোতে ব্যবহৃত হবে:

```cpp
if       else      while     for
class    const     void      switch
```

### কেন Keyword সংরক্ষিত রাখা হয়

Keyword গুলো ভাষার **ব্যাকরণ (grammar)**-এর অংশ — কম্পাইলার এই শব্দগুলো দেখলে জানে যে এখানে একটি বিশেষ ভাষাগত কাঠামো (যেমন একটি টাইপ ঘোষণা, একটি শর্তাধীন স্টেটমেন্ট) আসছে। যদি প্রোগ্রামারদের keyword-কেও identifier হিসেবে ব্যবহারের অনুমতি দেওয়া হতো, তাহলে কম্পাইলারের পক্ষে বোঝা অসম্ভব হয়ে যেত একটি নির্দিষ্ট শব্দ ভাষার কাঠামো নির্দেশ করছে, নাকি প্রোগ্রামারের দেওয়া একটি নাম।

```cpp
int int{ 5 };   // এরর! 'int' একটি keyword, এটি variable-এর নাম হিসেবে ব্যবহার করা যাবে না
```

### Definition — Identifier কী?

**Identifier** হলো প্রোগ্রামার-নির্ধারিত নাম, যা variable, function, class, বা অন্য যেকোনো প্রোগ্রাম-উপাদান শনাক্ত করতে ব্যবহৃত হয়।

```cpp
int studentAge{ 20 };   // 'studentAge' একটি identifier
void calculateTotal();   // 'calculateTotal' একটি identifier
```

### Naming Rules (নামকরণের নিয়ম) — বাধ্যতামূলক

C++ ভাষার নিয়ম অনুযায়ী, একটি identifier-এর নাম অবশ্যই নিচের নিয়মগুলো মেনে চলতে হবে (এগুলো লঙ্ঘন করলে কম্পাইল এরর হবে):

1. **শুধুমাত্র অক্ষর (letter), সংখ্যা (digit), এবং আন্ডারস্কোর (`_`) ব্যবহার করা যাবে।** অন্য কোনো বিশেষ ক্যারেক্টার (যেমন `@`, `#`, `-`, স্পেস) ব্যবহার করা যাবে না।
   ```cpp
   int student_age;    // বৈধ
   int student-age;     // এরর! হাইফেন অনুমোদিত নয়
   int student age;     // এরর! স্পেস অনুমোদিত নয়
   ```

2. **নামের প্রথম ক্যারেক্টার অবশ্যই একটি অক্ষর বা আন্ডারস্কোর হতে হবে, সংখ্যা দিয়ে শুরু করা যাবে না।**
   ```cpp
   int age1;    // বৈধ
   int 1age;     // এরর! সংখ্যা দিয়ে শুরু করা যাবে না
   ```

3. **Case-sensitive** — বড় হাতের ও ছোট হাতের অক্ষর ভিন্ন হিসেবে গণ্য হয়।
   ```cpp
   int age;
   int Age;    // এটি 'age' থেকে সম্পূর্ণ ভিন্ন একটি identifier
   int AGE;    // এটিও ভিন্ন
   ```

4. **কোনো C++ keyword ব্যবহার করা যাবে না।**
   ```cpp
   int class;   // এরর! 'class' একটি reserved keyword
   ```

5. **দুইটি আন্ডারস্কোর (`__`) দিয়ে শুরু হওয়া নাম, অথবা একটি আন্ডারস্কোর দিয়ে শুরু হয়ে বড় হাতের অক্ষর দিয়ে চলতে থাকা নাম (যেমন `_Foo`), C++ স্ট্যান্ডার্ড লাইব্রেরির জন্য সংরক্ষিত** — এগুলো টেকনিক্যালি ব্যবহার করা গেলেও, প্রফেশনাল কোডে এড়িয়ে চলা উচিত, কারণ এগুলো লাইব্রেরির সাথে সংঘর্ষ তৈরি করতে পারে।
   ```cpp
   int __count;   // এড়িয়ে চলা উচিত — যদিও কিছু কম্পাইলারে কম্পাইল হতে পারে
   ```

### Valid বনাম Conventional — একটি গুরুত্বপূর্ণ পার্থক্য

উপরের নিয়মগুলো পড়ার পর একটি identifier-কে তিনটি ভিন্ন শ্রেণীতে ফেলা যায়:

1. **বৈধ এবং প্রথাগত (valid and conventional)** — নিয়ম মেনেছে, এবং প্রফেশনাল naming convention-ও অনুসরণ করেছে। যেমন `studentAge`।
2. **বৈধ কিন্তু অপ্রথাগত (valid but unconventional)** — কম্পাইল হবে (নিয়ম ভঙ্গ হয়নি), কিন্তু প্রফেশনাল স্টাইল অনুসরণ করেনি। যেমন `Student_Age` (বড় হাতের অক্ষর দিয়ে শুরু এবং আন্ডারস্কোর মিশ্রিত — কম্পাইল হবে, কিন্তু কোনো প্রতিষ্ঠিত convention অনুসরণ করছে না) অথবা `_count` (আন্ডারস্কোর দিয়ে শুরু — বৈধ, কিন্তু সাধারণত এড়িয়ে চলা হয়)।
3. **অবৈধ (invalid)** — নিয়ম ভঙ্গ হয়েছে, তাই কম্পাইল এররই হবে। যেমন `2ndPlace` (সংখ্যা দিয়ে শুরু) বা `class` (keyword)।

এই পার্থক্যটি গুরুত্বপূর্ণ, কারণ "কম্পাইল হওয়া" এবং "ভালো কোড হওয়া" — এই দুইটি এক জিনিস নয়। একটি identifier টেকনিক্যালি বৈধ হলেও, তা যদি প্রতিষ্ঠিত convention অনুসরণ না করে, তাহলে এটি এখনও এড়িয়ে চলা উচিত।

### Naming Conventions (নামকরণের প্রথা/রীতি) — ঐচ্ছিক কিন্তু গুরুত্বপূর্ণ

উপরের নিয়মগুলো *বাধ্যতামূলক* (নাহলে কম্পাইল এরর), কিন্তু **naming convention** হলো এমন কিছু প্রথাগত রীতি, যা কম্পাইলার বাধ্যতামূলক করে না, কিন্তু কোডকে সুসংগত, readable এবং প্রফেশনাল করে তোলে।

সবচেয়ে সাধারণ কয়েকটি convention:

1. **camelCase** — প্রথম শব্দ ছোট হাতের অক্ষরে শুরু, পরবর্তী প্রতিটি শব্দ বড় হাতের অক্ষরে শুরু।
   ```cpp
   int studentAge;
   double totalPrice;
   ```

2. **snake_case** — প্রতিটি শব্দ ছোট হাতের অক্ষরে, আন্ডারস্কোর দিয়ে আলাদা করা।
   ```cpp
   int student_age;
   double total_price;
   ```

3. **PascalCase** — প্রতিটি শব্দের প্রথম অক্ষর বড় হাতের — সাধারণত class/type-এর নামের জন্য ব্যবহৃত হয়।
   ```cpp
   class StudentRecord { /* ... */ };
   ```

### Google C++ Style Guide অনুসারে Naming Convention

এই বইয়ে আমরা **Google C++ Style Guide**-এর নীতি অনুসরণ করব, যা প্রফেশনাল ইন্ডাস্ট্রিতে ব্যাপকভাবে গৃহীত একটি স্ট্যান্ডার্ড। এর মূল নির্দেশনাগুলো:

| উপাদান | Convention | উদাহরণ |
|---|---|---|
| Variable | `snake_case` (বা প্রজেক্ট-নির্দিষ্ট camelCase) | `student_age`, `total_price` |
| Function | `PascalCase` অথবা `camelCase` | `CalculateTotal()`, `calculateTotal()` |
| Class/Struct | `PascalCase` | `StudentRecord`, `BankAccount` |
| Constant | `kPascalCase` (k দিয়ে শুরু) | `kMaxStudents`, `kPi` |
| Namespace | `snake_case` (সংক্ষিপ্ত, ছোট হাতের) | `my_project` |

> **লক্ষণীয়:** বিভিন্ন কোম্পানি ও প্রজেক্ট নিজস্ব স্টাইল গাইড ব্যবহার করে, এবং variable naming-এর ক্ষেত্রে `camelCase` ও `snake_case` — দুইটিই ব্যাপকভাবে ব্যবহৃত হয়। এই বইয়ে আমরা সাধারণত `camelCase` ব্যবহার করব variable-এর জন্য (যেমন LearnCpp.com-এর কনভেনশন অনুসরণ করে), কারণ এটি বিগিনারদের কাছে বহুল পরিচিত এবং পঠনযোগ্য। মূল নীতিটি মনে রাখা জরুরি: **সামঞ্জস্যতা (consistency)** — একটি প্রজেক্টের মধ্যে যেকোনো একটি স্টাইল বেছে নিয়ে সেটিতে অবিচল থাকা।

### Professional Naming Style — গুরুত্বপূর্ণ নীতিমালা

1. **অর্থবহ নাম ব্যবহার করুন।**
   ```cpp
   // খারাপ
   int x;
   int a, b, c;

   // ভালো
   int studentCount;
   int width, height, depth;
   ```

2. **অতিরিক্ত সংক্ষিপ্ত বা অস্পষ্ট নাম এড়িয়ে চলুন**, তবে লুপ কাউন্টারের মতো সাধারণভাবে স্বীকৃত ছোট নাম (যেমন `i`, `j` লুপে) গ্রহণযোগ্য।
3. **নামের দৈর্ঘ্য variable-এর ব্যবহারের পরিসর (scope) অনুযায়ী নির্ধারণ করুন** — একটি ছোট লুপে সাময়িকভাবে ব্যবহৃত variable-এর জন্য ছোট নাম গ্রহণযোগ্য, কিন্তু ব্যাপকভাবে ব্যবহৃত একটি variable-এর নাম অবশ্যই স্পষ্ট ও বর্ণনামূলক হতে হবে।
4. **বুলিয়ান (`bool`) variable-এর নামে প্রশ্নবোধক গঠন ব্যবহার করুন** (যেমন `is`, `has`, `can` দিয়ে শুরু করা), যা সেই variable-এর উদ্দেশ্য তাৎক্ষণিকভাবে স্পষ্ট করে।
   ```cpp
   bool isValid{ true };
   bool hasPermission{ false };
   bool canEdit{ true };
   ```
5. **সংক্ষিপ্ত রূপ (abbreviation) এড়িয়ে চলুন**, যদি না সেগুলো সর্বজনস্বীকৃত হয় (যেমন `id`, `url`)।

### একাধিক উদাহরণ

**উদাহরণ ১ — সঠিক ও ভুল Identifier নামের তুলনা:**
```cpp
// বৈধ identifier
int score{ 100 };
double _temperature{ 36.6 };
char grade1{ 'A' };

// অবৈধ identifier (কম্পাইল এরর হবে)
// int 1st_score{ 90 };     // সংখ্যা দিয়ে শুরু
// double class{ 5.0 };      // keyword ব্যবহার
// char my grade{ 'B' };     // স্পেস ব্যবহার
```

**উদাহরণ ২ — প্রফেশনাল বনাম অপ্রফেশনাল নামকরণ:**
```cpp
#include <iostream>

int main()
{
    // অপ্রফেশনাল (অস্পষ্ট নাম)
    int a{ 25 };
    int b{ 50000 };

    // প্রফেশনাল (স্পষ্ট, অর্থবহ নাম)
    int employeeAge{ 25 };
    int annualSalary{ 50000 };

    std::cout << employeeAge << " " << annualSalary << std::endl;
    return 0;
}
```

**উদাহরণ ৩ — Case-sensitivity প্রদর্শন:**
```cpp
#include <iostream>

int main()
{
    int count{ 5 };
    int Count{ 10 };   // সম্পূর্ণ ভিন্ন variable, যদিও নাম প্রায় একই দেখতে

    std::cout << count << " " << Count << std::endl;   // আউটপুট: 5 10
    return 0;
}
```

### Common Mistakes (সাধারণ ভুল)

1. **Keyword-কে identifier হিসেবে ব্যবহারের চেষ্টা করা:**
   ```cpp
   int return{ 5 };   // এরর!
   ```

2. **অস্পষ্ট, অর্থহীন নাম ব্যবহার করা**, যা কোড পড়াকে কঠিন করে তোলে:
   ```cpp
   int x1, x2, x3;   // এই নামগুলো থেকে কিছুই বোঝা যায় না
   ```

3. **একই প্রজেক্টে অসামঞ্জস্যপূর্ণভাবে বিভিন্ন naming convention মিশিয়ে ব্যবহার করা:**
   ```cpp
   int student_age;    // snake_case
   int TotalScore;      // PascalCase — একই ধরনের variable-এর জন্য ভিন্ন স্টাইল, অসামঞ্জস্যপূর্ণ
   ```

4. **Case-sensitivity ভুলে যাওয়া**, যার ফলে ভুলবশত দুইটি ভিন্ন variable তৈরি হয়ে যাওয়া, যেখানে প্রোগ্রামার একটিই variable বোঝাতে চেয়েছিলেন।

### Professional Tips (প্রফেশনাল পরামর্শ)

- প্রতিটি নতুন প্রজেক্ট শুরু করার আগে একটি নির্দিষ্ট naming convention বেছে নিন এবং পুরো প্রজেক্টে তা সামঞ্জস্যপূর্ণভাবে অনুসরণ করুন।
- টিমে কাজ করলে, টিমের প্রতিষ্ঠিত style guide অনুসরণ করুন — ব্যক্তিগত পছন্দের চেয়ে টিম-ওয়াইড সামঞ্জস্যতা বেশি গুরুত্বপূর্ণ।
- নামকরণে সময় ব্যয় করা মূল্যবান বিনিয়োগ — ভালো নাম ভবিষ্যতে কোড বোঝা এবং maintain করা অনেক সহজ করে তোলে।
- IDE-এর অটো-কমপ্লিট ফিচার ব্যবহার করুন, যা দীর্ঘ কিন্তু অর্থবহ নাম ব্যবহারকে সহজ করে তোলে (টাইপ করার বাড়তি পরিশ্রম কমিয়ে দেয়)।

### Deep Understanding — কেন Naming এত গুরুত্বপূর্ণ Software Engineering-এ

একটি প্রচলিত উক্তি আছে: *"প্রোগ্রামিং-এ দুইটি কঠিন জিনিস আছে: cache invalidation এবং নামকরণ (naming things)।"* এই উক্তিটি অতিরঞ্জিত মনে হলেও, এর পেছনে গভীর সত্য আছে। একটি প্রোগ্রামের কোড শুধু একবার লেখা হয়, কিন্তু বহুবার পড়া হয় — নিজের দ্বারা, টিমমেট দ্বারা, এবং ভবিষ্যতে maintain করার সময়। ভালো নামকরণ কোডকে **self-documenting** করে তোলে — অর্থাৎ, কোডটি নিজেই তার উদ্দেশ্য ব্যাখ্যা করে, অতিরিক্ত comment-এর প্রয়োজন কমিয়ে দেয় (যা 1.2 বিভাগে আলোচিত হয়েছে)।

### Behind the Scenes — Identifier কীভাবে Symbol Table-এ সংরক্ষিত হয়

যখন কম্পাইলার একটি identifier দেখে, এটি সেই নামটিকে তার **symbol table**-এ যুক্ত করে, সাথে তার টাইপ, স্কোপ এবং মেমোরি লোকেশন সংক্রান্ত তথ্য। কম্পাইলেশনের পরবর্তী ধাপগুলোতে, যখনই সেই identifier-টি ব্যবহৃত হয়, কম্পাইলার এই টেবিল দেখে নিশ্চিত করে যে এটি সঠিক প্রসঙ্গে সঠিকভাবে ব্যবহৃত হচ্ছে। যদি একই স্কোপে দুইটি identifier একই নামে ঘোষণা করার চেষ্টা করা হয় (যেমন 1.3 বিভাগে আলোচিত হয়েছে), কম্পাইলার এই টেবিল পরীক্ষা করেই দ্বন্দ্ব শনাক্ত করে এবং এরর দেখায়।

### Interview Questions

1. **প্রশ্ন:** Keyword এবং identifier-এর মধ্যে পার্থক্য কী?
   **উত্তর:** Keyword হলো ভাষার সংরক্ষিত শব্দ, যেগুলোর একটি নির্দিষ্ট ভাষাগত অর্থ আছে এবং এগুলো identifier হিসেবে ব্যবহার করা যায় না। Identifier হলো প্রোগ্রামার-নির্ধারিত নাম, যা variable, function ইত্যাদি শনাক্ত করতে ব্যবহৃত হয়।

2. **প্রশ্ন:** C++ identifier নামকরণের তিনটি বাধ্যতামূলক নিয়ম বলুন।
   **উত্তর:** (১) শুধুমাত্র অক্ষর, সংখ্যা এবং আন্ডারস্কোর ব্যবহার করা যাবে, (২) প্রথম ক্যারেক্টার সংখ্যা হতে পারবে না, (৩) কোনো C++ keyword ব্যবহার করা যাবে না। (এছাড়া identifier case-sensitive।)

3. **প্রশ্ন:** Naming rule এবং naming convention-এর মধ্যে পার্থক্য কী?
   **উত্তর:** Naming rule হলো ভাষার বাধ্যতামূলক নিয়ম, যা লঙ্ঘন করলে কম্পাইল এরর হয়। Naming convention হলো একটি ঐচ্ছিক কিন্তু প্রফেশনালভাবে গুরুত্বপূর্ণ প্রথা (যেমন camelCase বা snake_case), যা কোডকে সুসংগত ও readable করে তোলে, কিন্তু না মানলে কম্পাইল এরর হয় না।

### Practice Problems

1. নিচের identifier নামগুলোর মধ্যে কোনগুলো বৈধ এবং কোনগুলো অবৈধ তা চিহ্নিত করুন, এবং অবৈধ হলে কারণ ব্যাখ্যা করুন: `2ndPlace`, `total_score`, `class`, `_isValid`, `my-variable`।
2. একটি ছোট প্রোগ্রাম লিখুন যেখানে camelCase convention ব্যবহার করে অন্তত চারটি ভিন্ন variable ঘোষণা করা হয়েছে, প্রতিটির নাম যথাযথভাবে তার উদ্দেশ্য প্রকাশ করে।
3. ব্যাখ্যা করুন কেন `int data;` এর তুলনায় `int studentExamScore;` একটি ভালো নামকরণ পছন্দ।

## 1.8 Whitespace and Basic Formatting

### Definition — Whitespace কী?

**Whitespace** বলতে বোঝায় এমন ক্যারেক্টার যা কোনো দৃশ্যমান প্রতীক প্রদর্শন করে না, কিন্তু স্থান দখল করে — যেমন স্পেস, ট্যাব (tab), এবং নতুন লাইন (newline)।

C++ কম্পাইলার বেশিরভাগ ক্ষেত্রে whitespace-কে উপেক্ষা করে — অর্থাৎ, কতগুলো স্পেস বা কতগুলো নতুন লাইন ব্যবহার করা হয়েছে তা সাধারণত প্রোগ্রামের কার্যকারিতাকে প্রভাবিত করে না।

```cpp
int x{5};
int    y   {   10   };
```

উপরের দুইটি লাইন কম্পাইলারের কাছে কার্যত সমতুল্য (functionally equivalent), যদিও দ্বিতীয়টি পড়তে অস্বস্তিকর।

### কেন Whitespace গুরুত্বপূর্ণ (যদিও কম্পাইলার এটি উপেক্ষা করে)

যদিও কম্পাইলারের জন্য whitespace গুরুত্বহীন, **মানুষের জন্য এটি অত্যন্ত গুরুত্বপূর্ণ**। সুসংগঠিত whitespace ব্যবহার কোডকে অনেক বেশি readable করে তোলে, যা সরাসরি প্রভাব ফেলে:

1. কোড কত দ্রুত বোঝা যায়
2. bug খুঁজে বের করা কত সহজ হয়
3. অন্য ডেভেলপার (বা ভবিষ্যতের নিজে) কত সহজে কোড maintain করতে পারবেন

### Indentation (ইনডেন্টেশন)

**Indentation** হলো কোডের প্রতিটি লাইনের শুরুতে নির্দিষ্ট পরিমাণ স্পেস/ট্যাব যোগ করে সেই লাইনের "স্তর" (nesting level) নির্দেশ করা। এটি ভিজ্যুয়ালি দেখায় কোন কোড ব্লকের অন্তর্গত।

```cpp
int main()
{
    int x{ 5 };            // এক লেভেল ইনডেন্ট — main এর ভেতরে
    if (x > 0)
    {
        std::cout << x;    // দুই লেভেল ইনডেন্ট — main এবং if এর ভেতরে
    }
    return 0;
}
```

**সঠিক ইনডেন্টেশন ছাড়া একই কোড:**
```cpp
int main()
{
int x{ 5 };
if (x > 0)
{
std::cout << x;
}
return 0;
}
```
দ্বিতীয় সংস্করণটি কম্পাইল হবে (কারণ কম্পাইলার whitespace উপেক্ষা করে), কিন্তু কোনো কোড ব্লক কোথায় শুরু ও শেষ হচ্ছে তা বোঝা অনেক কঠিন।

### Indentation-এর জন্য Space বনাম Tab

এটি প্রোগ্রামিং কমিউনিটিতে একটি দীর্ঘদিনের বিতর্কিত বিষয়। উভয় পদ্ধতিরই সুবিধা-অসুবিধা আছে:

- **Space:** সব এডিটর/আইডিই-তে একইভাবে দেখা যায় — কোড ঠিক যেভাবে ইচ্ছা সেভাবেই align হয়, এডিটর বা তার সেটিংস যাই হোক না কেন।
- **Tab:** ইনডেন্টেশনের জন্য বিশেষভাবে ডিজাইন করা ক্যারেক্টার, এবং প্রতিটি ডেভেলপার নিজস্ব পছন্দ অনুযায়ী ইনডেন্টেশনের প্রস্থ (width) কনফিগার করতে পারেন।

এই বিতর্কে বাস্তবিকপক্ষে **কোনো একক "সঠিক" উত্তর নেই** — এটি অনেকটা "কেক ভালো নাকি পাই ভালো" এই তর্কের মতো, শেষ পর্যন্ত এটি ব্যক্তিগত পছন্দের বিষয়। উভয় পদ্ধতিই ব্যাপকভাবে ব্যবহৃত হয়, এবং যেকোনোটি বেছে নেওয়াই যুক্তিসঙ্গত। যদি ট্যাব ব্যবহার করেন, তাহলে সাধারণত প্রতি ট্যাবকে ৪ স্পেসের সমান প্রস্থে সেট করার পরামর্শ দেওয়া হয় (কিছু IDE ডিফল্টভাবে ৩ স্পেস ব্যবহার করে, যা এটিও গ্রহণযোগ্য)।

**গুরুত্বপূর্ণ বিষয়টি হলো সামঞ্জস্যতা, পদ্ধতি নয়:** যেকোনো একটি পদ্ধতি বেছে নিয়ে পুরো প্রজেক্টে সামঞ্জস্যপূর্ণভাবে ব্যবহার করা — মিশিয়ে ব্যবহার করা (কিছু লাইনে স্পেস, কিছু লাইনে ট্যাব) সমস্যা তৈরি করতে পারে, কারণ বিভিন্ন এডিটরে এগুলো ভিন্নভাবে প্রদর্শিত হতে পারে। এই বইয়ে, Google C++ Style Guide অনুসরণ করে, আমরা **স্পেস** ব্যবহার করব, প্রতি ইনডেন্ট লেভেলে ২টি স্পেস — তবে এটি একটি বেছে নেওয়া কনভেনশন, সার্বজনীন নিয়ম নয়।

### Brace Placement Style (ব্রেস বসানোর স্টাইল)

Opening brace `{` কোথায় বসবে তা নিয়ে কয়েকটি জনপ্রিয় স্টাইল আছে:

**Allman style (নতুন লাইনে brace):**
```cpp
int main()
{
    std::cout << "হ্যালো";
}
```

**K&R / "one true brace" style (একই লাইনে brace):**
```cpp
int main() {
    std::cout << "হ্যালো";
}
```

উভয় স্টাইলই ব্যাপকভাবে ব্যবহৃত হয় — গুরুত্বপূর্ণ বিষয় হলো, যে স্টাইলই বেছে নেওয়া হোক না কেন, পুরো প্রজেক্টে তা **সামঞ্জস্যপূর্ণভাবে** অনুসরণ করা। এই বইয়ে আমরা Allman style ব্যবহার করছি (যেমনটি এখন পর্যন্ত সব উদাহরণে দেখা গেছে), কারণ এটি ব্লকের শুরু ও শেষ ভিজ্যুয়ালি স্পষ্টভাবে আলাদা করে দেখায়, যা বিগিনারদের জন্য সহায়ক।

### Line Length (লাইনের দৈর্ঘ্য)

খুব লম্বা কোড লাইন পড়া কঠিন করে তোলে, বিশেষত যখন এটি স্ক্রিনের প্রস্থের বাইরে চলে যায়। প্রফেশনাল স্টাইল গাইড সাধারণত একটি সর্বোচ্চ লাইন দৈর্ঘ্য নির্ধারণ করে (Google C++ Style Guide অনুযায়ী সাধারণত ৮০ ক্যারেক্টার)।

```cpp
// খুব দীর্ঘ লাইন (এড়িয়ে চলা উচিত)
int result{ someVeryLongFunctionName(argumentOne, argumentTwo, argumentThree, argumentFour) };

// ভেঙে লেখা (readable)
int result{ someVeryLongFunctionName(
    argumentOne, argumentTwo, argumentThree, argumentFour) };
```

**একটি লম্বা লাইন operator দিয়ে ভাগ করার নিয়ম:** যদি একটি লম্বা লাইন কোনো operator-এ (যেমন `<<` বা `+`) ভেঙে একাধিক লাইনে লিখতে হয়, তাহলে সেই operator-টি **বর্তমান লাইনের শেষে না রেখে পরবর্তী লাইনের শুরুতে** রাখা উচিত। এতে স্পষ্টভাবে বোঝা যায় যে পরবর্তী লাইনটি আগের লাইনেরই ধারাবাহিকতা, এবং operator গুলো বামপাশে সারিবদ্ধ (align) করা সহজ হয়, যা পড়তে সুবিধাজনক।

```cpp
// প্রস্তাবিত: operator পরের লাইনের শুরুতে
std::cout << "নাম: " << name
          << ", বয়স: " << age
          << ", শহর: " << city << std::endl;

// এড়িয়ে চলা উচিত: operator লাইনের শেষে
std::cout << "নাম: " << name <<
    ", বয়স: " << age <<
    ", শহর: " << city << std::endl;
```

### Whitespace ব্যবহারের সাধারণ নীতি

1. **Operator-এর চারপাশে স্পেস ব্যবহার করুন:**
   ```cpp
   int sum{ a + b };   // ভালো
   int sum{a+b};        // পড়তে কষ্টকর, যদিও বৈধ
   ```

2. **Comma-এর পরে স্পেস ব্যবহার করুন, আগে নয়:**
   ```cpp
   std::cout << x << ", " << y;   // ভালো
   ```

3. **সম্পর্কিত কোডের মাঝে খালি লাইন দিয়ে ভিজ্যুয়াল গ্রুপিং করুন, কিন্তু অতিরিক্ত ব্যবহার এড়িয়ে চলুন:**
   ```cpp
   int width{ 10 };
   int height{ 20 };

   int area{ width * height };
   std::cout << area;
   ```

### একাধিক উদাহরণ

**উদাহরণ ১ — একই কোডের ভালো ও খারাপ ফরম্যাটিং:**
```cpp
// খারাপ ফরম্যাটিং
#include <iostream>
int main(){int x{5};int y{10};std::cout<<x+y;return 0;}

// ভালো ফরম্যাটিং
#include <iostream>

int main()
{
    int x{ 5 };
    int y{ 10 };
    std::cout << x + y;
    return 0;
}
```
উভয় কোডই কার্যকরীভাবে সম্পূর্ণ অভিন্ন — কিন্তু দ্বিতীয়টি অনেক বেশি readable।

**উদাহরণ ২ — সামঞ্জস্যপূর্ণ ইনডেন্টেশনসহ Nested Block:**
```cpp
#include <iostream>

int main()
{
    int x{ 10 };
    if (x > 5)
    {
        std::cout << "x 5 এর চেয়ে বড়" << std::endl;
        if (x > 8)
        {
            std::cout << "x 8 এর চেয়েও বড়" << std::endl;
        }
    }
    return 0;
}
```
প্রতিটি nesting level-এ ইনডেন্টেশন বৃদ্ধি পাচ্ছে, যা কোডের কাঠামো স্পষ্টভাবে ভিজ্যুয়ালি প্রকাশ করে।

**উদাহরণ ৩ — লম্বা Expression ভেঙে লেখা:**
```cpp
#include <iostream>

int main()
{
    int total{
        10 + 20 + 30 + 40 + 50
    };
    std::cout << total;
    return 0;
}
```

### Common Mistakes (সাধারণ ভুল)

1. **অসামঞ্জস্যপূর্ণ ইনডেন্টেশন** — কিছু লাইনে ২ স্পেস, কিছু লাইনে ৪ স্পেস ব্যবহার করা, যা কোডকে বিশৃঙ্খল দেখায়।
2. **Tab এবং Space মিশিয়ে ব্যবহার করা** — এটি বিভিন্ন এডিটরে ভিন্নভাবে প্রদর্শিত হতে পারে, এবং কোডের ভিজ্যুয়াল কাঠামো নষ্ট করে দিতে পারে।
3. **একই লাইনে অনেক statement গুঁজে দেওয়া**, যা পড়া কঠিন করে তোলে:
   ```cpp
   int x{5}; int y{10}; std::cout << x + y;   // এড়িয়ে চলা উচিত
   ```
4. **Operator-এর চারপাশে অসামঞ্জস্যপূর্ণভাবে স্পেস ব্যবহার করা**, যেমন কখনো `a+b`, কখনো `a + b`।

### Professional Tips (প্রফেশনাল পরামর্শ)

- একটি **code formatter** টুল ব্যবহার করুন (যেমন `clang-format`), যা স্বয়ংক্রিয়ভাবে কোডকে একটি নির্দিষ্ট স্টাইল গাইড অনুসারে ফরম্যাট করে দেয় — এটি প্রফেশনাল টিমে অত্যন্ত সাধারণ প্র্যাকটিস।
- IDE-তে "format on save" ফিচার সক্রিয় করুন, যাতে প্রতিবার ফাইল সংরক্ষণের সময় স্বয়ংক্রিয়ভাবে সঠিক ফরম্যাটিং প্রয়োগ হয়।
- টিমে কাজ করার সময়, ব্যক্তিগত পছন্দের চেয়ে টিমের প্রতিষ্ঠিত ফরম্যাটিং স্ট্যান্ডার্ড মেনে চলা বেশি গুরুত্বপূর্ণ।
- মনে রাখবেন, ফরম্যাটিং কখনোই বিষয়গত (subjective) স্বাদের প্রশ্ন নয় শুধু — এটি সরাসরি কোড maintainability এবং টিম প্রোডাক্টিভিটির সাথে সম্পর্কিত।

### Deep Understanding — Whitespace-এর সীমাবদ্ধতা

যদিও বেশিরভাগ ক্ষেত্রে whitespace গুরুত্বহীন, কয়েকটি ব্যতিক্রম আছে যা এই মৌলিক পর্যায়ে জেনে রাখা ভালো:

1. **String literal-এর ভেতরে whitespace গুরুত্বপূর্ণ:**
   ```cpp
   std::cout << "হ্যালো   বিশ্ব";   // এখানে স্পেসগুলো অক্ষত থাকবে, প্রদর্শিত হবে
   ```
2. **কিছু টোকেনের মধ্যে whitespace বাধ্যতামূলক**, যেমন দুইটি keyword বা identifier-এর মধ্যে অন্তত একটি স্পেস প্রয়োজন, নাহলে সেগুলো একটি একক টোকেন হিসেবে ভুল পার্স হতে পারে:
   ```cpp
   int x;    // 'int' এবং 'x' এর মাঝে স্পেস আবশ্যক
   ```

এই ব্যতিক্রমগুলো ছাড়া, সাধারণ কোড স্ট্রাকচারে whitespace-এর পরিমাণ প্রোগ্রামারের স্বাধীনতা এবং readability-এর জন্য একটি টুল।

### Behind the Scenes — Lexer কীভাবে Whitespace হ্যান্ডল করে

কম্পাইলেশনের **lexical analysis (tokenization)** ধাপে, লেক্সার (lexer) সোর্স কোডকে টোকেনে ভাঙে। Whitespace সাধারণত টোকেনগুলোর মধ্যে **বিভাজক (separator)** হিসেবে কাজ করে — এটি লেক্সারকে বলে দেয় একটি টোকেন কোথায় শেষ হচ্ছে এবং পরেরটি কোথায় শুরু হচ্ছে। কিন্তু whitespace নিজে কোনো টোকেন হিসেবে গণ্য হয় না (স্ট্রিং লিটারেলের ভেতরে ব্যতীত) — এই কারণেই কম্পাইলেশনের পরবর্তী ধাপগুলোতে (parsing, semantic analysis) whitespace-এর কোনো প্রভাব থাকে না।

### Professional Programmer Notes

বাস্তব সফটওয়্যার ইন্ডাস্ট্রিতে, কোড ফরম্যাটিং প্রায়ই স্বয়ংক্রিয় টুল দ্বারা প্রয়োগ করা হয়, এবং এটি Continuous Integration (CI) পাইপলাইনের অংশ হতে পারে — অর্থাৎ, যদি কোনো কোড টিমের নির্ধারিত ফরম্যাটিং স্ট্যান্ডার্ড অনুসরণ না করে, সেই কোড merge করার আগে স্বয়ংক্রিয়ভাবে প্রত্যাখ্যাত হতে পারে। এটি নিশ্চিত করে যে পুরো কোডবেস জুড়ে সামঞ্জস্যপূর্ণ স্টাইল বজায় থাকে, প্রতিটি ডেভেলপারের ব্যক্তিগত পছন্দ নির্বিশেষে।

## 1.9 Introduction to Literals and Operators

### Definition — Literal কী?

**Literal** (একে **literal constant**-ও বলা হয়) হলো এমন একটি মান, যা সরাসরি সোর্স কোডে লেখা থাকে — এটি কোনো variable বা গণনার ফলাফল নয়, বরং একটি "কাঁচা" (raw), স্থির মান, যা সরাসরি প্রোগ্রামে বসানো হয়।

```cpp
int x{ 5 };        // 5 একটি integer literal
double y{ 3.14 };   // 3.14 একটি floating-point literal
```

এখানে `5` এবং `3.14` — উভয়ই literal, কারণ এগুলো সরাসরি কোডে লেখা মান, কোনো variable থেকে আসা নয়।

### কেন Literal-কে "Constant" বলা হয়

Literal এবং variable উভয়েরই একটি মান ও একটি টাইপ আছে, কিন্তু একটি গুরুত্বপূর্ণ পার্থক্য আছে: variable-এর মান initialization ও assignment-এর মাধ্যমে সেট ও পরিবর্তন করা যায়, কিন্তু একটি literal-এর মান **স্থির (fixed)** এবং কখনো পরিবর্তন করা যায় না — literal `5` সবসময় `5`-ই থাকবে। এই কারণেই literal-কে "constant" বলা হয়।

এই পার্থক্যের একটি গভীর কারণ আছে মেমোরির দৃষ্টিকোণ থেকে। যখন কম্পাইলার একটি literal দেখে, এটি সেই মানটিকে সরাসরি এক্সিকিউটেবল ফাইলে এম্বেড (embed) করে দেয়। যেহেতু এক্সিকিউটেবল ফাইল একবার তৈরি হওয়ার পর তা প্রোগ্রাম চলাকালীন পরিবর্তন করা যায় না, তাই literal-এর মানও পরিবর্তন করা অসম্ভব। অন্যদিকে, একটি variable-এর মান মেমোরিতে (RAM-এ) সংরক্ষিত থাকে, এবং প্রোগ্রাম চলাকালীন RAM-এর মান পরিবর্তনযোগ্য — তাই variable-এর মান পরিবর্তন করা সম্ভব।

### কেন Literal প্রয়োজন

প্রোগ্রামে অনেক সময় নির্দিষ্ট, পূর্ব-নির্ধারিত মান প্রয়োজন হয় — যেমন গাণিতিক ধ্রুবক (`3.14159` for π), নির্দিষ্ট সীমা (`100` for maximum score), অথবা টেক্সট বার্তা (`"ত্রুটি ঘটেছে"`)। Literal এই মানগুলো সরাসরি কোডে প্রকাশ করার উপায় প্রদান করে।

### Literal-এর প্রকারভেদ

#### ১. Integer Literals (পূর্ণসংখ্যা লিটারেল)

```cpp
int a{ 42 };       // দশমিক (decimal) — ডিফল্ট
int b{ 0x2A };      // hexadecimal (হেক্সাডেসিমেল) — 0x প্রিফিক্স, মান 42-এর সমান
int c{ 052 };       // octal (অক্টাল) — 0 প্রিফিক্স, মান 42-এর সমান
int d{ 0b101010 };  // binary (বাইনারি) — 0b প্রিফিক্স (C++14+), মান 42-এর সমান
```

C++14 থেকে, বড় সংখ্যা পড়তে সহজ করতে **digit separator** (`'`) ব্যবহার করা যায়:
```cpp
int million{ 1'000'000 };   // পড়তে সহজ, মান 1000000-এর সমান
```

#### ২. Floating-Point Literals (দশমিক লিটারেল)

```cpp
double pi{ 3.14159 };
double avogadro{ 6.022e23 };   // scientific notation — 6.022 × 10²³
float temp{ 36.6f };            // 'f' suffix float টাইপ নির্দেশ করে (নাহলে ডিফল্ট double)
```

#### ৩. Character Literals (ক্যারেক্টার লিটারেল)

একক ক্যারেক্টার সবসময় একক কোটেশন (`' '`) দিয়ে ঘেরা থাকে:
```cpp
char grade{ 'A' };
char newline{ '\n' };    // escape sequence — newline ক্যারেক্টার
char tab{ '\t' };         // escape sequence — tab ক্যারেক্টার
char backslash{ '\\' };   // escape sequence — একটি একক backslash
```

#### ৪. String Literals (স্ট্রিং লিটারেল)

একাধিক ক্যারেক্টারের সিকোয়েন্স সবসময় দ্বৈত কোটেশন (`" "`) দিয়ে ঘেরা থাকে:
```cpp
const char* message{ "হ্যালো, বিশ্ব!" };
```
> **লক্ষণীয়:** String literal-এর প্রকৃত টাইপ (`const char*` বা `std::string`) এবং বিস্তারিত ব্যবহার ভবিষ্যৎ চ্যাপ্টারে গভীরভাবে আলোচিত হবে। এই মুহূর্তে গুরুত্বপূর্ণ হলো এটি চেনা যে দ্বৈত কোটেশনের ভেতরের টেক্সট একটি string literal।

#### ৫. Boolean Literals (বুলিয়ান লিটারেল)

```cpp
bool isReady{ true };
bool isFinished{ false };
```

### Definition — Operator কী?

**Operator** হলো একটি বিশেষ প্রতীক (symbol), যা এক বা একাধিক মান (operand) নিয়ে একটি নির্দিষ্ট গণনা বা পরিবর্তন সম্পাদন করে এবং একটি ফলাফল উৎপন্ন করে।

```cpp
int sum{ 5 + 3 };   // '+' একটি operator, 5 এবং 3 এর operand
```

### Arithmetic Operators (গাণিতিক অপারেটর)

| Operator | নাম | উদাহরণ | ফলাফল |
|---|---|---|---|
| `+` | যোগ (Addition) | `5 + 3` | `8` |
| `-` | বিয়োগ (Subtraction) | `5 - 3` | `2` |
| `*` | গুণ (Multiplication) | `5 * 3` | `15` |
| `/` | ভাগ (Division) | `10 / 3` | `3` (integer division-এ দশমিক অংশ বাদ যায়) |
| `%` | ভাগশেষ (Modulo/Remainder) | `10 % 3` | `1` |

**Integer division নিয়ে গুরুত্বপূর্ণ সতর্কতা:**
```cpp
int result{ 10 / 3 };     // ফলাফল: 3, দশমিক অংশ (.333...) বাদ পড়ে যায়
double result2{ 10.0 / 3 };   // ফলাফল: 3.33333..., কারণ কমপক্ষে একটি operand double
```
যখন উভয় operand `int` হয়, ফলাফলও `int` হয় — দশমিক অংশ সম্পূর্ণভাবে বাদ পড়ে যায় (round হয় না, truncate হয়)। এটি একটি অত্যন্ত সাধারণ বিগিনার ভুলের উৎস।

### Comparison Operators (তুলনা অপারেটর)

| Operator | নাম | উদাহরণ | ফলাফল |
|---|---|---|---|
| `==` | সমান কিনা | `5 == 5` | `true` |
| `!=` | অসমান কিনা | `5 != 3` | `true` |
| `>` | বড় কিনা | `5 > 3` | `true` |
| `<` | ছোট কিনা | `5 < 3` | `false` |
| `>=` | বড় বা সমান কিনা | `5 >= 5` | `true` |
| `<=` | ছোট বা সমান কিনা | `5 <= 3` | `false` |

**গুরুত্বপূর্ণ সতর্কতা — `=` বনাম `==`:**
```cpp
int x{ 5 };
if (x = 3)   // ভুল! এটি assignment (x-কে 3 বানিয়ে দিচ্ছে), তুলনা নয়
if (x == 3)  // সঠিক! এটি তুলনা করছে x এর মান 3 এর সমান কিনা
```
এটি একটি অত্যন্ত সাধারণ এবং বিপজ্জনক ভুল, কারণ প্রথম কোডটি কম্পাইল হয়ে যায় (কম্পাইল এরর দেয় না), কিন্তু সম্পূর্ণ ভিন্ন আচরণ করে।

### Logical Operators (লজিক্যাল অপারেটর)

| Operator | নাম | ব্যাখ্যা |
|---|---|---|
| `&&` | Logical AND | উভয় শর্ত সত্য হলে সত্য |
| `\|\|` | Logical OR | যেকোনো একটি শর্ত সত্য হলে সত্য |
| `!` | Logical NOT | শর্তের বিপরীত মান |

```cpp
bool a{ true };
bool b{ false };

bool result1{ a && b };   // false — উভয়ই true নয়
bool result2{ a || b };   // true — অন্তত একটি true
bool result3{ !a };        // false — a এর বিপরীত
```

### Operators-এর সংক্ষিপ্ত পরিচিতি — Assignment Operator পুনরালোচনা

1.4 বিভাগে আমরা `=` (assignment operator) নিয়ে ইতিমধ্যে আলোচনা করেছি। এটিও একটি operator, যা ডানপাশের মান বামপাশের variable-এ কপি করে।

### একাধিক উদাহরণ

**উদাহরণ ১ — বিভিন্ন প্রকার Literal একসাথে ব্যবহার:**
```cpp
#include <iostream>

int main()
{
    int age{ 25 };                  // integer literal
    double height{ 5.9 };            // floating-point literal
    char grade{ 'A' };                // character literal
    bool isStudent{ true };           // boolean literal
    const char* name{ "রহিম" };       // string literal

    std::cout << name << " এর বয়স " << age << ", উচ্চতা " << height << std::endl;
    return 0;
}
```

**উদাহরণ ২ — গাণিতিক ও তুলনা Operator একসাথে ব্যবহার:**
```cpp
#include <iostream>

int main()
{
    int a{ 15 };
    int b{ 4 };

    std::cout << "যোগ: " << (a + b) << std::endl;
    std::cout << "বিয়োগ: " << (a - b) << std::endl;
    std::cout << "গুণ: " << (a * b) << std::endl;
    std::cout << "ভাগ: " << (a / b) << std::endl;      // integer division
    std::cout << "ভাগশেষ: " << (a % b) << std::endl;

    std::cout << "a > b কিনা: " << (a > b) << std::endl;   // 1 (true)
    return 0;
}
```

**উদাহরণ ৩ — Logical Operator ব্যবহার করে জটিল শর্ত তৈরি:**
```cpp
#include <iostream>

int main()
{
    int age{ 20 };
    bool hasID{ true };

    bool canEnter{ (age >= 18) && hasID };
    std::cout << "প্রবেশ করতে পারবে কিনা: " << canEnter << std::endl;
    return 0;
}
```

### Common Mistakes (সাধারণ ভুল)

1. **Integer division-এর ফলাফল ভুল বোঝা:**
   ```cpp
   double average{ 7 / 2 };   // ভুল! ফলাফল 3.0 (integer division প্রথমে হয়, তারপর double-এ রূপান্তরিত হয়)
   double average2{ 7.0 / 2 };   // সঠিক! ফলাফল 3.5
   ```

2. **`=` এবং `==` গুলিয়ে ফেলা**, যা আগেই আলোচিত হয়েছে — এটি C++-এ সবচেয়ে সাধারণ ভুলগুলোর একটি।

3. **Character literal-এ ডবল কোটেশন ব্যবহার করা:**
   ```cpp
   char grade{ "A" };   // এরর! এটি একটি string literal, character literal নয় — একক কোটেশন প্রয়োজন
   char grade2{ 'A' };   // সঠিক
   ```

4. **Modulo operator (`%`) floating-point টাইপে ব্যবহার করার চেষ্টা করা:**
   ```cpp
   double result{ 5.5 % 2 };   // এরর! % শুধুমাত্র integer টাইপের জন্য প্রযোজ্য
   ```

### Professional Tips (প্রফেশনাল পরামর্শ)

- Integer division-এর ফলাফল প্রয়োজন হলে সচেতনভাবে অন্তত একটি operand-কে floating-point টাইপে রূপান্তর করুন (যেমন `7.0 / 2` অথবা `static_cast<double>(7) / 2`, এই cast ধারণাটি ভবিষ্যৎ চ্যাপ্টারে বিস্তারিত আলোচিত হবে)।
- জটিল শর্ত লেখার সময় বন্ধনী (`()`) ব্যবহার করে স্পষ্টতা বাড়ান, এমনকি যদি operator precedence অনুযায়ী বন্ধনী বাধ্যতামূলক নাও হয়।
- Comparison operator ব্যবহারের সময় সবসময় সতর্ক থাকুন যাতে ভুলবশত assignment operator ব্যবহার না হয়ে যায়। কিছু প্রোগ্রামার এই ভুল এড়াতে "Yoda condition" (যেমন `3 == x` এর বদলে `x == 3`) ব্যবহার করেন, যদিও আধুনিক কম্পাইলার ওয়ার্নিং এই সমস্যা অনেকাংশে কমিয়ে দিয়েছে।

### Deep Understanding — Operand এবং Operator-এর সম্পর্ক

একটি operator যে মানগুলোর উপর কাজ করে, তাদের বলা হয় **operand**। Operator-কে operand-এর সংখ্যা (arity) অনুযায়ী শ্রেণীবদ্ধ করা যায়:

- **Nullary operator** — শূন্য (০টি) operand নিয়ে কাজ করে।
- **Unary operator** — একটি operand নিয়ে কাজ করে (যেমন `!a`, যেখানে `!` শুধু `a`-এর উপর কাজ করছে)।
- **Binary operator** — দুইটি operand নিয়ে কাজ করে (যেমন `a + b`, এখানে `+` অপারেটরের বাম (left) operand `a` এবং ডান (right) operand `b`)। `<<` এবং `>>` (insertion ও extraction অপারেটর, 1.5 বিভাগে আলোচিত) — এরাও binary operator, যেখানে বামদিকে `std::cout`/`std::cin` এবং ডানদিকে আউটপুট/ইনপুট করা মান থাকে।
- **Ternary operator** — তিনটি operand নিয়ে কাজ করে (C++-এ একমাত্র ternary operator হলো `?:`, যা ভবিষ্যৎ চ্যাপ্টারে আলোচিত হবে)।

### Behind the Scenes — Literal ব্যবহারের Performance Angle

আগেই আলোচনা করা হয়েছে যে literal-এর মান সরাসরি এক্সিকিউটেবল ফাইলে এম্বেড থাকে। এর একটি ব্যবহারিক ফলাফল হলো, literal ব্যবহার করা কিছু পরিস্থিতিতে variable ব্যবহারের চেয়ে সামান্য দ্রুত হতে পারে — কারণ মানটি সরাসরি কোডে "হার্ডকোড" থাকে, প্রোগ্রাম চলাকালীন কোনো মেমোরি লুকআপের (lookup) প্রয়োজন হয় না, যেখানে একটি variable-এর মান পড়তে হলে প্রথমে তার মেমোরি অ্যাড্রেসে গিয়ে মান fetch করতে হয়।

### Professional Programmer Notes

প্রফেশনাল কোডে, সরাসরি সংখ্যা (যেমন `42`, `3.14`) কোডের মধ্যে ছড়িয়ে ছিটিয়ে ব্যবহার করাকে বলা হয় **"magic number"** ব্যবহার, যা এড়িয়ে চলা উচিত। এর পরিবর্তে, নামযুক্ত constant ব্যবহার করা প্রফেশনাল প্র্যাকটিস (এই ধারণা `const` কীওয়ার্ড নিয়ে ভবিষ্যৎ চ্যাপ্টারে বিস্তারিত আলোচিত হবে):

```cpp
// এড়িয়ে চলা উচিত (magic number)
double area{ 3.14159 * radius * radius };

// প্রস্তাবিত (named constant)
const double pi{ 3.14159 };
double area{ pi * radius * radius };
```

### Interview Questions

1. **প্রশ্ন:** Literal কী, এবং এটি variable থেকে কীভাবে ভিন্ন?
   **উত্তর:** Literal হলো একটি স্থির মান যা সরাসরি সোর্স কোডে লেখা থাকে (যেমন `5`, `"হ্যালো"`)। Variable একটি named object, যার মান পরিবর্তনযোগ্য এবং যা রানটাইমে গণনা বা ইনপুটের মাধ্যমে নির্ধারিত হতে পারে।

2. **প্রশ্ন:** `int` টাইপের দুইটি operand দিয়ে division করলে কী সমস্যা হতে পারে?
   **উত্তর:** ফলাফল integer division হয়, যেখানে দশমিক অংশ সম্পূর্ণভাবে বাদ পড়ে যায় (truncate হয়, round হয় না)। ফলাফল যদি একটি সঠিক দশমিক মান হওয়া প্রয়োজন হয়, অন্তত একটি operand-কে floating-point টাইপে রূপান্তর করতে হবে।

3. **প্রশ্ন:** কেন `if (x = 5)` একটি বিপজ্জনক ভুল, এবং কম্পাইলার কেন এটি সরাসরি এরর হিসেবে ধরে না?
   **উত্তর:** এখানে `=` (assignment) ব্যবহৃত হয়েছে, `==` (comparison) নয় — এটি x-কে 5 এ পরিবর্তন করে দিচ্ছে এবং সেই assignment-এর ফলাফল (যা 5, একটি truthy মান) শর্ত হিসেবে ব্যবহৃত হচ্ছে। কম্পাইলার এরর দেয় না কারণ সিনট্যাক্সটি বৈধ — assignment একটি বৈধ expression যার একটি মান আছে, তাই এটি if condition-এ ব্যবহারযোগ্য, যদিও এটি প্রোগ্রামারের উদ্দেশ্য নাও হতে পারে।

## 1.10 Introduction to Expressions

### Definition — Expression কী?

**Expression** হলো literal, variable, operator এবং function call-এর এমন একটি সমন্বয়, যা মূল্যায়িত (evaluate) হয়ে একটি একক মান (single value) উৎপন্ন করে।

```cpp
5 + 3          // একটি expression, যা মূল্যায়িত হয়ে 8 তৈরি করে
x              // একটি variable-ও একটি expression (মূল্যায়িত হয়ে তার বর্তমান মান দেয়)
(a + b) * c     // একটি জটিল expression
```

1.1 বিভাগে আমরা expression এবং statement-এর পার্থক্য সংক্ষেপে আলোচনা করেছিলাম — এই বিভাগে আমরা expression-এর ধারণা আরও গভীরভাবে অনুসন্ধান করব।

### Expression বনাম Statement — পুনরালোচনা ও গভীর বিশ্লেষণ

| বৈশিষ্ট্য | Expression | Statement |
|---|---|---|
| ফলাফল | একটি মান উৎপন্ন করে | একটি সম্পূর্ণ কাজ সম্পন্ন করে |
| সেমিকোলন | নিজে থেকে সেমিকোলন প্রয়োজন নেই | সাধারণত সেমিকোলন দিয়ে শেষ হয় |
| ব্যবহার | অন্য expression বা statement-এর অংশ হতে পারে | একটি সম্পূর্ণ, স্বতন্ত্র নির্দেশনা |
| উদাহরণ | `5 + 3`, `x * 2`, `a > b` | `int x{ 5 };`, `return 0;` |

গুরুত্বপূর্ণ বিষয়: **একটি expression-এর শেষে সেমিকোলন যোগ করলে সেটি একটি expression statement-এ পরিণত হয়** (1.1 বিভাগে আলোচিত)।

```cpp
5 + 3;   // এটি একটি expression statement (যদিও ফলাফল ব্যবহৃত হচ্ছে না, তাই বাস্তবে অর্থহীন)
```

একটি গুরুত্বপূর্ণ বিষয় স্পষ্ট বোঝা দরকার: **একটি expression একা কখনো কম্পাইল করা যায় না** — expression সবসময় কোনো না কোনো statement-এর অংশ হিসেবেই মূল্যায়িত হয়।

```cpp
x = 5   // এটি একা কম্পাইল করার চেষ্টা করলে এরর হবে (সম্ভবত "সেমিকোলন অনুপস্থিত" এই মর্মে)
x = 5;   // কিন্তু সেমিকোলন যোগ করলে এটি একটি সম্পূর্ণ statement, যা কম্পাইল হয়
```

### Subexpression, Full Expression, এবং Compound Expression

কখনো কখনো একটি expression-এর নির্দিষ্ট অংশ নিয়ে আলাদাভাবে কথা বলার প্রয়োজন হয়। এই উদ্দেশ্যে কয়েকটি সংশ্লিষ্ট পরিভাষা ব্যবহৃত হয়:

- **Subexpression (উপ-expression)** হলো এমন একটি expression, যা আরেকটি বড় expression-এর একটি operand হিসেবে ব্যবহৃত হয়। যেমন, `x = 4 + 5` — এই সম্পূর্ণ expression-এর subexpression গুলো হলো `x` এবং `4 + 5`।
- **Full expression** হলো এমন একটি expression, যা নিজে কোনো বড় expression-এর subexpression নয়। উপরের `x = 4 + 5` নিজে একটি full expression (এটি অন্য কোনো বড় expression-এর অংশ নয়)। একইভাবে `2` এবং `2 + 3` — এরাও প্রত্যেকে full expression, যদি এরা নিজে থেকেই সম্পূর্ণ থাকে (অন্য কোনো expression-এর অংশ না হয়)।
- **Compound expression** হলো এমন একটি expression, যেখানে দুই বা ততোধিক operator ব্যবহৃত হয়েছে। যেমন `x = 4 + 5` একটি compound expression, কারণ এতে দুইটি operator ব্যবহৃত হয়েছে (`=` এবং `+`)। কিন্তু `2` বা `2 + 3` কোনোটিই compound expression নয়, কারণ এদের প্রতিটিতে একটির বেশি operator নেই।

এই পরিভাষাগুলো এখনই মুখস্থ করার প্রয়োজন নেই, তবে ভবিষ্যতে জটিল expression নিয়ে আলোচনার সময় এগুলো কাজে লাগবে।

### Expression কীভাবে কাজ করে (How Expressions Work)

একটি expression মূল্যায়িত হওয়ার সময়, C++ কম্পাইলার/রানটাইম সিস্টেম একটি নির্দিষ্ট ক্রম অনুসরণ করে ধাপে ধাপে ফলাফল বের করে। এই প্রক্রিয়াকে বলা হয় **evaluation**।

```cpp
int result{ 2 + 3 * 4 };
```

এখানে, `2 + 3 * 4` expression-টি মূল্যায়িত হওয়ার সময় **operator precedence (অপারেটরের অগ্রাধিকার)** অনুসরণ করা হয় — গুণ (`*`) এর অগ্রাধিকার যোগ (`+`) এর চেয়ে বেশি, তাই প্রথমে `3 * 4 = 12` গণনা হবে, তারপর `2 + 12 = 14`। ফলাফল: `result = 14`, `20` নয়।

### Operator Precedence এবং Associativity (অপারেটরের অগ্রাধিকার ও দিক)

C++-এ প্রতিটি operator-এর একটি নির্দিষ্ট **precedence (অগ্রাধিকার)** আছে, যা নির্ধারণ করে একটি জটিল expression-এ কোন অপারেশন আগে সম্পাদিত হবে। এছাড়া, একই precedence-এর একাধিক operator থাকলে **associativity (দিকনির্দেশ — বাম থেকে ডানে, নাকি ডান থেকে বামে)** নির্ধারণ করে তাদের ক্রম।

সংক্ষিপ্ত সাধারণ নীতি (এই চ্যাপ্টারে আলোচিত operator-এর জন্য):

1. বন্ধনী `()` সর্বোচ্চ অগ্রাধিকার পায়
2. গুণ (`*`), ভাগ (`/`), ভাগশেষ (`%`) — সমান অগ্রাধিকার, বাম থেকে ডানে মূল্যায়িত হয়
3. যোগ (`+`), বিয়োগ (`-`) — সমান অগ্রাধিকার, বাম থেকে ডানে মূল্যায়িত হয়, কিন্তু গুণ/ভাগ/ভাগশেষের চেয়ে কম অগ্রাধিকার

```cpp
int result1{ 10 - 4 + 2 };    // বাম থেকে ডানে: (10 - 4) + 2 = 8
int result2{ 2 + 3 * 4 - 1 };  // গুণ প্রথমে: 2 + 12 - 1 = 13
```

**বন্ধনী দিয়ে স্পষ্টতা নিশ্চিত করা:**
```cpp
int result{ (2 + 3) * 4 };   // বন্ধনী precedence override করে: 5 * 4 = 20
```

> **গুরুত্বপূর্ণ পরামর্শ:** যদিও operator precedence-এর নিয়ম মুখস্থ করা সম্ভব, প্রফেশনাল প্র্যাকটিসে জটিল expression-এ **স্পষ্টভাবে বন্ধনী ব্যবহার করা** সবসময় প্রস্তাবিত — এটি কোডকে অস্পষ্টতামুক্ত এবং readable রাখে, এমনকি যদি বন্ধনী প্রযুক্তিগতভাবে প্রয়োজনীয় না-ও হয়।

### Expression-এর প্রকারভেদ

1. **Literal expression** — শুধুমাত্র একটি literal
   ```cpp
   42
   ```
2. **Variable expression** — একটি variable-এর মান
   ```cpp
   x
   ```
3. **Arithmetic expression** — গাণিতিক operator সমৃদ্ধ
   ```cpp
   a + b * c
   ```
4. **Comparison expression** — তুলনামূলক operator সমৃদ্ধ, ফলাফল `bool`
   ```cpp
   a > b
   ```
5. **Logical expression** — লজিক্যাল operator সমৃদ্ধ
   ```cpp
   (a > 0) && (b > 0)
   ```
6. **Assignment expression** — assignment operator সমৃদ্ধ (এটিও একটি expression, কারণ এর একটি মান আছে — assign করা মানটিই)
   ```cpp
   x = 5   // এই expression-এর মান হলো 5
   ```

### একটি গুরুত্বপূর্ণ Deep Insight — Assignment নিজেও একটি Expression

C++-এ একটি চমকপ্রদ কিন্তু গুরুত্বপূর্ণ বিষয় হলো, assignment (`=`) নিজেও একটি expression, যার একটি মান আছে (assign হওয়া মানটিই)। এই কারণেই নিচের কোডটি বৈধ:

```cpp
int x, y;
x = y = 5;   // ডান থেকে বামে: প্রথমে y = 5 (মান 5), তারপর x = (y = 5 এর ফলাফল, যা 5)
```

এই একই কারণেই 1.9 বিভাগে আলোচিত `if (x = 5)` ভুলটি কম্পাইল এরর দেয় না — `x = 5` একটি বৈধ expression, যার মান `5`, যা `if` কন্ডিশনে ব্যবহারযোগ্য।

### Expression মূল্যায়নের ধাপ-ভিত্তিক উদাহরণ

আসুন একটি জটিল expression ধাপে ধাপে বিশ্লেষণ করি:

```cpp
int result{ (5 + 3) * 2 - 4 / 2 };
```

**ধাপে ধাপে মূল্যায়ন:**
1. বন্ধনীর ভেতরে প্রথমে: `5 + 3 = 8`
2. এখন expression: `8 * 2 - 4 / 2`
3. গুণ ও ভাগ বাম থেকে ডানে (একই precedence): `8 * 2 = 16`, তারপর `4 / 2 = 2`
4. এখন expression: `16 - 2`
5. বিয়োগ: `16 - 2 = 14`

**চূড়ান্ত ফলাফল:** `result = 14`

### একাধিক উদাহরণ

**উদাহরণ ১ — বিভিন্ন Expression একসাথে ব্যবহার ও প্রদর্শন:**
```cpp
#include <iostream>

int main()
{
    int a{ 10 };
    int b{ 3 };

    std::cout << "a + b = " << (a + b) << std::endl;
    std::cout << "a - b = " << (a - b) << std::endl;
    std::cout << "a এবং b এর তুলনা (a > b): " << (a > b) << std::endl;
    std::cout << "জটিল expression: " << (a * 2 + b * 3) << std::endl;
    return 0;
}
```

**উদাহরণ ২ — Nested Expression এবং বন্ধনীর ভূমিকা:**
```cpp
#include <iostream>

int main()
{
    int x{ 4 };
    int y{ 2 };
    int z{ 3 };

    int result1{ x + y * z };        // 4 + (2*3) = 10, precedence অনুযায়ী
    int result2{ (x + y) * z };       // (4+2)*3 = 18, বন্ধনী দিয়ে override

    std::cout << result1 << " " << result2 << std::endl;
    return 0;
}
```

**উদাহরণ ৩ — Chained Assignment Expression:**
```cpp
#include <iostream>

int main()
{
    int a{}, b{}, c{};
    a = b = c = 100;   // তিনটি variable-ই 100 মান পাচ্ছে, ডান থেকে বামে মূল্যায়িত হয়ে

    std::cout << a << " " << b << " " << c << std::endl;
    return 0;
}
```

### Common Mistakes (সাধারণ ভুল)

1. **Operator precedence ভুল ধরে নেওয়া:**
   ```cpp
   int result{ 10 + 5 * 2 };   // ফলাফল 30 নয়, বরং 20 (10 + 10) — গুণ আগে হয়
   ```

2. **Integer division-এর প্রভাব ভুলে যাওয়া জটিল expression-এ:**
   ```cpp
   double avg{ (a + b) / 2 };   // যদি a, b উভয়ই int, তাহলে integer division ঘটবে, দশমিক অংশ হারিয়ে যাবে
   ```

3. **অতিরিক্ত জটিল expression একটি লাইনে গুঁজে দেওয়া**, যা readability কমিয়ে দেয় এবং bug-প্রবণ করে তোলে:
   ```cpp
   int result{ a * b + c / d - e % f * (g + h) };   // পড়া কঠিন, ভুল হওয়ার সম্ভাবনা বেশি
   ```

4. **বন্ধনী ব্যবহার না করে জটিল precedence-এর উপর নির্ভর করা**, যা কোডকে অস্পষ্ট করে তোলে, এমনকি যদি প্রযুক্তিগতভাবে সঠিক ফলাফল আসে।

### Professional Tips (প্রফেশনাল পরামর্শ)

- জটিল expression-এ সবসময় স্পষ্টভাবে বন্ধনী ব্যবহার করুন, precedence-এর উপর অন্ধভাবে নির্ভর না করে।
- একটি অত্যন্ত জটিল expression-কে একাধিক ছোট, স্পষ্ট নামযুক্ত intermediate variable-এ ভেঙে ফেলুন — এটি readability এবং debugging উভয়ই সহজ করে তোলে।
  ```cpp
  // জটিল, কম readable
  int result{ (a + b) * (c - d) / (e + 1) };

  // ভাঙা, বেশি readable
  int sum{ a + b };
  int diff{ c - d };
  int denominator{ e + 1 };
  int result{ sum * diff / denominator };
  ```
- Expression-এর ফলাফল দ্রুত মানসিকভাবে যাচাই করার অভ্যাস করুন, বিশেষত ডিবাগিং-এর সময়।

### Deep Understanding — Expression-এর মান বনাম Side Effect

কিছু expression শুধু একটি মান উৎপন্ন করে (যেমন `5 + 3`), কিন্তু কিছু expression-এর একটি অতিরিক্ত প্রভাবও থাকে, যাকে বলা হয় **side effect** — অর্থাৎ, expression মূল্যায়নের পাশাপাশি প্রোগ্রামের অবস্থার (state) কোনো পরিবর্তন ঘটে।

```cpp
x = 5;   // এই expression-এর মান 5, কিন্তু এর একটি side effect-ও আছে: x-এর মান পরিবর্তিত হয়েছে
```

Assignment expression-এর side effect আছে (variable-এর মান পরিবর্তন), কিন্তু সাধারণ arithmetic expression-এর (যেমন `5 + 3`) কোনো side effect নেই — এটি শুধু একটি মান উৎপন্ন করে, কোনো state পরিবর্তন করে না। এই পার্থক্যটি ভবিষ্যতে function এবং জটিল control flow নিয়ে কাজ করার সময় গুরুত্বপূর্ণ হয়ে উঠবে।

### Behind the Scenes — Expression Tree

কম্পাইলার একটি জটিল expression-কে প্রায়ই একটি **expression tree** (বা অংশ হিসেবে Abstract Syntax Tree) হিসেবে প্রতিনিধিত্ব করে, যেখানে প্রতিটি operator একটি নোড (node), এবং তার operand গুলো সেই নোডের চাইল্ড (child)। যেমন, `2 + 3 * 4` এর জন্য:

```
        +
       / \
      2   *
         / \
        3   4
```

কম্পাইলার এই ট্রি-কে "নিচে থেকে উপরে" (bottom-up) মূল্যায়ন করে — প্রথমে সবচেয়ে গভীরের অপারেশন (`3 * 4`), তারপর উপরের অপারেশন (`2 + 12`)। এই কাঠামোগত পদ্ধতিই নিশ্চিত করে যে operator precedence সঠিকভাবে অনুসরণ করা হয়, প্রোগ্রামারের সরাসরি হস্তক্ষেপ ছাড়াই।

### Professional Programmer Notes

জটিল সফটওয়্যার সিস্টেমে, বিশেষত সংখ্যাগত (numerical) গণনা-নির্ভর অ্যাপ্লিকেশনে (যেমন ফিনান্সিয়াল সফটওয়্যার, বৈজ্ঞানিক সিমুলেশন), expression-এর সঠিক মূল্যায়ন ক্রম অত্যন্ত গুরুত্বপূর্ণ — সামান্য ভুল ক্রম বিশাল আর্থিক বা বৈজ্ঞানিক পরিণতি ডেকে আনতে পারে। এই কারণেই প্রফেশনাল কোড রিভিউতে জটিল গাণিতিক expression বিশেষ মনোযোগ দিয়ে পরীক্ষা করা হয়, এবং প্রায়ই ইউনিট টেস্ট লেখা হয় নির্দিষ্ট প্রান্তিক (edge case) মান দিয়ে যাচাই করার জন্য।

### Interview Questions

1. **প্রশ্ন:** Expression এবং expression statement-এর মধ্যে পার্থক্য কী?
   **উত্তর:** Expression হলো এমন একটি সমন্বয় যা মূল্যায়িত হয়ে একটি মান উৎপন্ন করে (যেমন `5 + 3`)। Expression statement হলো একটি expression-এর শেষে সেমিকোলন যোগ করে সেটিকে একটি সম্পূর্ণ statement বানানো (যেমন `5 + 3;`)।

2. **প্রশ্ন:** `2 + 3 * 4` এর ফলাফল কী হবে, এবং কেন?
   **উত্তর:** ফলাফল `14`, কারণ operator precedence অনুযায়ী গুণ (`*`) যোগ (`+`) এর আগে মূল্যায়িত হয় — প্রথমে `3 * 4 = 12`, তারপর `2 + 12 = 14`।

3. **প্রশ্ন:** কেন assignment (`=`) একটি expression হিসেবে বিবেচিত হয়, শুধু একটি statement নয়?
   **উত্তর:** কারণ assignment-এর একটি মান আছে (assign হওয়া মানটিই), যা chained assignment (যেমন `x = y = 5`) সম্ভব করে তোলে, এবং এটি অন্য expression বা condition-এর অংশ হিসেবে ব্যবহারযোগ্য।

### Practice Problems

1. নিচের expression গুলোর ফলাফল হাতে-কলমে গণনা করুন, operator precedence মেনে: `5 + 2 * 3 - 1`, `(5 + 2) * (3 - 1)`, `10 / 2 + 3 * 2`।
2. একটি জটিল expression লিখুন (কমপক্ষে তিনটি ভিন্ন operator ব্যবহার করে), তারপর সেটিকে একাধিক ছোট, নামযুক্ত intermediate variable ব্যবহার করে পুনর্লিখন করুন।
3. ব্যাখ্যা করুন কেন `x = 5` একটি বৈধ expression, এবং এর মূল্যায়িত মান কী।

## 1.11 Developing Your First Program

### ভূমিকা — এখন পর্যন্ত শেখা সবকিছু একত্রিত করা

এই বিভাগে, আমরা এখন পর্যন্ত শেখা সবগুলো ধারণা — statement, comment, variable, initialization, iostream, naming, formatting, literal, operator, এবং expression — একত্রিত করে একটি সম্পূর্ণ, বাস্তব-জীবন-ঘনিষ্ঠ প্রোগ্রাম তৈরি করব। এই প্রক্রিয়ায় আমরা একটি প্রফেশনাল প্রোগ্রামিং workflow-ও অনুসরণ করব: পরিকল্পনা, লেখা, কম্পাইল, রান, ডিবাগ, এবং উন্নতি।

### একটি টুকরো একবারে — Incremental Development-এর গুরুত্ব

নতুন প্রোগ্রামাররা প্রায়ই একটি সাধারণ ভুল করেন: পুরো প্রোগ্রামটি একবারে লিখে ফেলার চেষ্টা করেন, এবং তারপর একগাদা এরর দেখে হতাশ হয়ে পড়েন। একটি অনেক ভালো কৌশল হলো: **একবারে একটি ছোট অংশ যোগ করুন, নিশ্চিত করুন সেটি কম্পাইল হচ্ছে, এবং সেটি পরীক্ষা করুন। তারপরই পরবর্তী অংশে এগোন।**

এই বিভাগে আমরা ঠিক এই কৌশলটিই অনুসরণ করব — প্রোগ্রামটি ধাপে ধাপে তৈরি হবে, প্রতিটি ধাপের পর কম্পাইল ও টেস্ট করে। এই পদ্ধতি অনুসরণ করার সময়, নিজে হাতে-কলমে প্রোগ্রাম করার সময় প্রতিটি প্রোগ্রাম নিজে **টাইপ করার** চেষ্টা করুন, কপি-পেস্ট না করে — টাইপ করার প্রক্রিয়া সিনট্যাক্স মনে রাখতে এবং সাধারণ টাইপো-জনিত এরর নিজে অভিজ্ঞতা করে শিখতে সাহায্য করে।

> **একটি স্মরণীয় উক্তি:** *"একটি প্রোগ্রাম একবার লিখে ফেললেই বোঝা যায়, প্রথমবার কীভাবে লেখা উচিত ছিল।"* এর অর্থ হলো, সর্বোত্তম সমাধান প্রায়ই প্রথমেই স্পষ্ট থাকে না, এবং যেকোনো সমস্যার প্রথম সমাধান সাধারণত ততটা ভালো হয় না যতটা হতে পারত। যখন আমরা একটি প্রোগ্রাম কীভাবে কাজ করানো যায় তা খুঁজে বের করায় মনোযোগী থাকি, তখন এমন কোডে অনেক সময় বিনিয়োগ করা বুদ্ধিমানের কাজ নয় যা হয়তো আমরা রাখবই না। তাই আমরা শর্টকাট নিই — error handling ও comment বাদ দিই, ডিবাগিং-এর জন্য অস্থায়ী কোড যোগ করি। ফলে আমাদের প্রাথমিক সমাধান প্রায়ই ততটা সুগঠিত, ত্রুটি-প্রতিরোধী, readable, বা সংক্ষিপ্ত হয় না যতটা হতে পারত — এবং এটিই স্বাভাবিক।

### ধাপ ১ — প্রোগ্রামের পরিকল্পনা (Planning)

কোনো কোড লেখার আগে, একজন প্রফেশনাল প্রোগ্রামার প্রথমে প্রোগ্রামটি *কী* করবে তা স্পষ্টভাবে চিন্তা করেন। আমাদের প্রথম প্রোগ্রামের লক্ষ্য: **একটি সাধারণ ক্যালকুলেটর, যা ব্যবহারকারীর কাছ থেকে দুইটি সংখ্যা নেবে এবং তাদের যোগফল, বিয়োগফল, গুণফল ও ভাগফল প্রদর্শন করবে।**

**প্রয়োজনীয় ধাপ চিহ্নিতকরণ:**
1. ব্যবহারকারীকে দুইটি সংখ্যা ইনপুট দিতে বলা
2. সেই সংখ্যা দুইটি গ্রহণ করা
3. চারটি গাণিতিক অপারেশন সম্পাদন করা
4. ফলাফল স্পষ্টভাবে প্রদর্শন করা

### ধাপ ২ — সোর্স কোড লেখা (Writing Source Code)

পরিকল্পনা অনুযায়ী, এখন আমরা কোড লিখব:

```cpp
#include <iostream>

int main()
{
    // ব্যবহারকারীর কাছ থেকে দুইটি সংখ্যা গ্রহণ
    double firstNumber{};
    double secondNumber{};

    std::cout << "প্রথম সংখ্যাটি লিখুন: ";
    std::cin >> firstNumber;

    std::cout << "দ্বিতীয় সংখ্যাটি লিখুন: ";
    std::cin >> secondNumber;

    // চারটি গাণিতিক অপারেশন সম্পাদন
    double sum{ firstNumber + secondNumber };
    double difference{ firstNumber - secondNumber };
    double product{ firstNumber * secondNumber };
    double quotient{ firstNumber / secondNumber };

    // ফলাফল প্রদর্শন
    std::cout << "\n--- ফলাফল ---" << std::endl;
    std::cout << "যোগফল: " << sum << std::endl;
    std::cout << "বিয়োগফল: " << difference << std::endl;
    std::cout << "গুণফল: " << product << std::endl;
    std::cout << "ভাগফল: " << quotient << std::endl;

    return 0;
}
```

### সম্পূর্ণ প্রোগ্রামের লাইন-বাই-লাইন ব্যাখ্যা

- **`#include <iostream>`** — I/O ফাংশনালিটি (`cout`, `cin`) ব্যবহারের জন্য প্রয়োজনীয় হেডার যুক্ত করা হচ্ছে।
- **`int main()`** — প্রোগ্রামের entry point, যেখান থেকে execution শুরু হবে।
- **`double firstNumber{};` এবং `double secondNumber{};`** — দুইটি `double` টাইপের variable ঘোষণা করা হচ্ছে, value initialization (`{}`) দিয়ে, যাতে তারা uninitialized অবস্থায় না থাকে (1.6 বিভাগে আলোচিত নীতি অনুসরণ করে)। `double` ব্যবহার করা হয়েছে `int`-এর বদলে, যাতে দশমিক সংখ্যাও গ্রহণ করা যায় এবং ভাগফল সঠিকভাবে গণনা করা যায় (1.9 বিভাগে আলোচিত integer division সমস্যা এড়াতে)।
- **`std::cout << "..."; std::cin >> firstNumber;`** — ব্যবহারকারীকে নির্দেশনা দেখানো এবং তার ইনপুট গ্রহণ করা হচ্ছে (1.5 বিভাগে আলোচিত পদ্ধতি অনুসরণ করে)।
- **চারটি গাণিতিক variable ঘোষণা** — প্রতিটি অপারেশনের ফলাফল একটি স্পষ্ট নামযুক্ত variable-এ সংরক্ষণ করা হচ্ছে, যা readability বাড়ায় (1.10 বিভাগের "intermediate variable" পরামর্শ অনুসরণ করে)।
- **ফলাফল প্রদর্শনকারী `std::cout` স্টেটমেন্ট গুলো** — প্রতিটি ফলাফল স্পষ্ট লেবেলসহ প্রদর্শিত হচ্ছে।

### ধাপ ৩ — Compiling (কম্পাইল করা)

সোর্স কোড লেখার পর, এটি একটি এক্সিকিউটেবল প্রোগ্রামে রূপান্তরিত করতে হবে। একটি টার্মিনাল/কমান্ড লাইন থেকে, GCC কম্পাইলার ব্যবহার করে (একটি সাধারণ উদাহরণ):

```bash
g++ -Wall -Wextra -std=c++20 -o calculator calculator.cpp
```

এই কমান্ডের অংশগুলোর ব্যাখ্যা:
- `g++` — GNU C++ কম্পাইলার চালানো হচ্ছে
- `-Wall -Wextra` — সর্বোচ্চ ওয়ার্নিং লেভেল চালু করা হচ্ছে (1.6 বিভাগে আলোচিত প্রফেশনাল প্র্যাকটিস অনুযায়ী)
- `-std=c++20` — C++20 স্ট্যান্ডার্ড ব্যবহার করার নির্দেশ (আধুনিক C++ ফিচারের জন্য)
- `-o calculator` — আউটপুট এক্সিকিউটেবল ফাইলের নাম `calculator` নির্ধারণ করা হচ্ছে
- `calculator.cpp` — সোর্স ফাইলের নাম

যদি কোনো সিনট্যাক্স এরর থাকে, কম্পাইলার এই ধাপে এরর বার্তা দেখাবে, এবং এক্সিকিউটেবল ফাইল তৈরি হবে না।

### ধাপ ৪ — Running (রান করা)

কম্পাইলেশন সফল হলে, প্রোগ্রামটি রান করা যায়:

```bash
./calculator
```

**প্রত্যাশিত আউটপুট (উদাহরণ):**
```
প্রথম সংখ্যাটি লিখুন: 10
দ্বিতীয় সংখ্যাটি লিখুন: 3

--- ফলাফল ---
যোগফল: 13
বিয়োগফল: 7
গুণফল: 30
ভাগফল: 3.33333
```

### ধাপ ৫ — Debugging (ডিবাগিং)

ধরা যাক, প্রথম প্রচেষ্টায় আমরা ভুলবশত `double` এর বদলে `int` ব্যবহার করেছিলাম:

```cpp
int firstNumber{};
int secondNumber{};
// ...
int quotient{ firstNumber / secondNumber };   // বাগযুক্ত সংস্করণ
```

এই ভুল সংস্করণে, `10 / 3` এর ফলাফল হতো `3` (integer division-এর কারণে), `3.33333` নয় — এটি একটি **logical bug** (কম্পাইল এরর নয়, কিন্তু ভুল ফলাফল)।

**ডিবাগিং প্রক্রিয়া:**
1. **সমস্যা শনাক্তকরণ:** আউটপুট প্রত্যাশিত ফলাফলের সাথে মিলছে না — ভাগফল ভুল দেখাচ্ছে।
2. **কারণ অনুসন্ধান:** কোড পর্যালোচনা করে দেখা যায় `int` টাইপ ব্যবহৃত হয়েছে ভাগের জন্য, যা integer division ঘটাচ্ছে (1.9 বিভাগে আলোচিত সমস্যা)।
3. **সমাধান প্রয়োগ:** `int`-কে `double`-এ পরিবর্তন করা হয়।
4. **পুনরায় যাচাই:** কোড আবার কম্পাইল ও রান করে নিশ্চিত করা হয় সমস্যা সমাধান হয়েছে।

এই প্রক্রিয়াটি প্রফেশনাল ডিবাগিং workflow-এর একটি সরলীকৃত উদাহরণ: **পর্যবেক্ষণ → কারণ অনুসন্ধান → সমাধান → যাচাই**।

### ধাপ ৬ — প্রোগ্রামের উন্নতি (Improving the Program)

একটি কার্যকরী প্রোগ্রাম লেখার পরেও, প্রফেশনাল প্রোগ্রামাররা প্রায়ই তা আরও উন্নত করার সুযোগ খোঁজেন। প্রোগ্রাম "কাজ করছে" মানেই কাজ শেষ নয় (যদি না প্রোগ্রামটি একবার ব্যবহার করে ফেলে দেওয়ার মতো সাময়িক কিছু হয়)। এই "cleanup" ধাপে সাধারণত যা করা হয়:

- অস্থায়ী/ডিবাগিং কোড সরিয়ে ফেলা (বা comment out করা)
- প্রয়োজনীয় comment যোগ করা
- এজ কেস (edge case) ও এরর হ্যান্ডলিং যোগ করা
- কোড ফরম্যাটিং ঠিক করা
- best practice গুলো মানা হয়েছে কিনা নিশ্চিত করা
- পুনরাবৃত্তিমূলক (redundant) লজিক একত্রিত করা, অথবা একাধিক statement সংক্ষিপ্ত করা

আমাদের ক্যালকুলেটরের কিছু সম্ভাব্য উন্নতি (এই মুহূর্তে সম্পূর্ণ প্রয়োগ না করা হলেও, ধারণাগতভাবে গুরুত্বপূর্ণ):

1. **Zero-division সমস্যা:** যদি ব্যবহারকারী দ্বিতীয় সংখ্যা হিসেবে `0` দেন, ভাগফল গণনা একটি সমস্যা তৈরি করবে (division by zero)। এই সমস্যার সমাধান `if` statement দিয়ে করা সম্ভব, যা পরবর্তী চ্যাপ্টারে আলোচিত হবে।
2. **Named constant ব্যবহার:** যদি প্রোগ্রামে কোনো নির্দিষ্ট ধ্রুবক মান (যেমন সর্বোচ্চ সীমা) প্রয়োজন হতো, তা named constant হিসেবে ঘোষণা করা উচিত হতো, magic number না রেখে (1.9 বিভাগে আলোচিত)।
3. **কোড পুনর্ব্যবহারযোগ্যতা (reusability):** যদি এই গণনাগুলো প্রোগ্রামের একাধিক জায়গায় প্রয়োজন হতো, সেগুলোকে আলাদা function-এ ভাগ করা যেত (function ভবিষ্যৎ চ্যাপ্টারে আলোচিত হবে)।

> **গুরুত্বপূর্ণ নীতি:** নতুন প্রোগ্রামাররা প্রায়ই পারফরম্যান্স অপটিমাইজেশনের দিকে বেশি মনোযোগ দেন, যেখানে তাদের **maintainability (রক্ষণাবেক্ষণযোগ্যতা)**-র দিকে মনোযোগ দেওয়া উচিত। একটি ছোট প্রোগ্রামে কয়েক মিলিসেকেন্ড দ্রুত চালানোর চেষ্টা করার চেয়ে, কোডটি স্পষ্ট, readable, এবং ভবিষ্যতে সহজে পরিবর্তনযোগ্য রাখা অনেক বেশি গুরুত্বপূর্ণ — বিশেষত এই প্রাথমিক শেখার পর্যায়ে।

### Professional Programming Workflow — সংক্ষিপ্ত সারাংশ

আমাদের এই প্রোগ্রাম তৈরির প্রক্রিয়া একটি সাধারণ কিন্তু গুরুত্বপূর্ণ প্রফেশনাল workflow অনুসরণ করেছে:

```
পরিকল্পনা → কোড লেখা → কম্পাইল → রান → পরীক্ষা → ডিবাগ (প্রয়োজনে) → উন্নতি
```

এই চক্রটি (বিশেষত শেষ চারটি ধাপ) একটি বাস্তব সফটওয়্যার প্রজেক্টে বারবার পুনরাবৃত্ত হয়, যতক্ষণ না প্রোগ্রামটি সব প্রয়োজনীয়তা পূরণ করে এবং নির্ভরযোগ্যভাবে কাজ করে।

### একটি গুরুত্বপূর্ণ শিক্ষা — অপ্রয়োজনীয় Intermediate Variable এড়ানো

একটি সমস্যার একাধিক সঠিক সমাধান থাকতে পারে, কিন্তু কিছু সমাধান অন্যগুলোর চেয়ে ভালো। ধরা যাক, আমরা একটি সংখ্যা নিয়ে সেটিকে দ্বিগুণ করে দেখাতে চাই। নিচে তিনটি ভিন্ন পদ্ধতি তুলনা করা হলো, সবচেয়ে দুর্বল থেকে সবচেয়ে ভালো পদ্ধতির দিকে:

**পদ্ধতি ১ (দুর্বল) — মূল ইনপুট ওভাররাইট করা:**
```cpp
#include <iostream>

int main()
{
    std::cout << "একটি সংখ্যা লিখুন: ";
    int num{};
    std::cin >> num;

    num = num * 2;   // num-কে দ্বিগুণ করে num-এই আবার সংরক্ষণ করা হচ্ছে
    std::cout << "দ্বিগুণ মান: " << num << std::endl;
    return 0;
}
```
এই পদ্ধতির সমস্যা হলো, `num`-এর মূল মান (ব্যবহারকারীর ইনপুট) হারিয়ে যাচ্ছে — assignment-এর পর `num` আর ব্যবহারকারীর দেওয়া মূল সংখ্যাটি ধারণ করে না। যদি প্রোগ্রামটি পরবর্তীতে মূল ইনপুট আবার ব্যবহার করতে চায় (যেমন এটিকে তিনগুণও দেখাতে), তা আর সম্ভব নয়।

**পদ্ধতি ২ (মাঝারি) — একটি নতুন Variable ব্যবহার করা:**
```cpp
#include <iostream>

int main()
{
    std::cout << "একটি সংখ্যা লিখুন: ";
    int num{};
    std::cin >> num;

    int doubledNum{ num * 2 };   // ফলাফলের জন্য একটি নতুন variable
    std::cout << "দ্বিগুণ মান: " << doubledNum << std::endl;
    return 0;
}
```
এটি আগের সমস্যাটি সমাধান করে — `num`-এর মূল মান অক্ষত থাকে। কিন্তু এর একটি ছোট খুঁত আছে: `doubledNum` নামের একটি variable তৈরি করা হয়েছে, যা শুধুমাত্র একবার ব্যবহৃত হচ্ছে। প্রতিটি অতিরিক্ত variable প্রোগ্রামে সামান্য জটিলতা যোগ করে, যদিও তা সামান্যই।

**পদ্ধতি ৩ (সেরা) — সরাসরি Expression ব্যবহার করা:**
```cpp
#include <iostream>

int main()
{
    std::cout << "একটি সংখ্যা লিখুন: ";
    int num{};
    std::cin >> num;

    std::cout << "দ্বিগুণ মান: " << num * 2 << std::endl;   // সরাসরি expression ব্যবহার
    return 0;
}
```
এখানে যখন `std::cout` execute হয়, তখন `num * 2` expression-টি সরাসরি মূল্যায়িত হয় এবং ফলাফল প্রিন্ট হয় — কোনো অতিরিক্ত intermediate variable-এর প্রয়োজন হয় না, এবং `num`-এর মূল মানও অক্ষত থাকে। এই পদ্ধতিটিই সবচেয়ে ভালো, কারণ এটি সংক্ষিপ্ত, এবং কোনো অপ্রয়োজনীয় জটিলতা যোগ করে না।

> **মূলনীতি:** একটি মান শুধুমাত্র একবার ব্যবহারের জন্য একটি পৃথক variable তৈরি করার প্রয়োজন সবসময় নেই। যদি একটি গণনার ফলাফল ঠিক যেখানে প্রয়োজন সেখানেই সরাসরি ব্যবহার করা যায় (একটি expression হিসেবে), তাহলে আলাদা variable তৈরি না করাই ভালো। এটি কোডকে সংক্ষিপ্ত রাখে, প্রোগ্রামে ভেরিয়েবলের সংখ্যা কমায়, এবং মূল ইনপুট ডেটা অক্ষত রাখে যদি ভবিষ্যতে তা আবার প্রয়োজন হয়।

### একাধিক অতিরিক্ত উদাহরণ

**উদাহরণ ১ — একটি সহজ তাপমাত্রা রূপান্তরকারী (এই চ্যাপ্টারের সবগুলো ধারণা প্রয়োগ করে):**
```cpp
// ফাইলের নাম: temperature_converter.cpp
// উদ্দেশ্য: সেলসিয়াস থেকে ফারেনহাইট রূপান্তর

#include <iostream>

int main()
{
    double celsius{};

    std::cout << "সেলসিয়াস তাপমাত্রা লিখুন: ";
    std::cin >> celsius;

    // ফরমুলা: F = C * 9/5 + 32
    double fahrenheit{ celsius * 9.0 / 5.0 + 32.0 };

    std::cout << celsius << " সেলসিয়াস = " << fahrenheit << " ফারেনহাইট" << std::endl;
    return 0;
}
```

**উদাহরণ ২ — একটি সাধারণ বৃত্তের ক্ষেত্রফল ও পরিধি গণনাকারী:**
```cpp
#include <iostream>

int main()
{
    const double pi{ 3.14159 };   // named constant, magic number এড়িয়ে
    double radius{};

    std::cout << "বৃত্তের ব্যাসার্ধ লিখুন: ";
    std::cin >> radius;

    double area{ pi * radius * radius };
    double circumference{ 2 * pi * radius };

    std::cout << "ক্ষেত্রফল: " << area << std::endl;
    std::cout << "পরিধি: " << circumference << std::endl;
    return 0;
}
```

### Common Mistakes (সাধারণ ভুল) — সম্পূর্ণ প্রোগ্রাম লেখার সময়

1. **পরিকল্পনা ছাড়াই সরাসরি কোড লেখা শুরু করা**, যা প্রায়ই অগোছালো, ভুল-প্রবণ কোডের দিকে নিয়ে যায়।
2. **একসাথে অনেক ফিচার যোগ করার চেষ্টা করা**, ছোট ছোট ধাপে পরীক্ষা না করে — এতে কোনো সমস্যা দেখা দিলে কোন অংশে সমস্যা তা খুঁজে বের করা কঠিন হয়ে পড়ে।
3. **ডেটা টাইপ সঠিকভাবে নির্বাচন না করা** (যেমন integer division-এর সমস্যা এড়াতে `double` ব্যবহার না করা)।
4. **এজ কেস (edge case) বিবেচনা না করা**, যেমন division by zero-এর সম্ভাবনা।
5. **প্রতিটি ছোট পরিবর্তনের পর কম্পাইল ও টেস্ট না করা** — একসাথে অনেক পরিবর্তন করে তারপর কম্পাইল করলে, কোনো এরর হলে তার সঠিক উৎস খুঁজে বের করা কঠিন হয়ে পড়ে।

### Professional Tips (প্রফেশনাল পরামর্শ)

- **ছোট ছোট ধাপে কোড লিখুন এবং প্রতিটি ধাপের পর কম্পাইল ও টেস্ট করুন** — এই অভ্যাস "incremental development" নামে পরিচিত, এবং এটি বড় বড় bug একসাথে জমে যাওয়া প্রতিরোধ করে।
- **সবসময় সর্বোচ্চ ওয়ার্নিং লেভেল দিয়ে কম্পাইল করুন**, এবং প্রতিটি ওয়ার্নিং গুরুত্বসহকারে বিবেচনা করুন।
- **প্রোগ্রাম লেখার আগে সংক্ষিপ্তভাবে পরিকল্পনা করুন** — কী কী ধাপ প্রয়োজন, কী কী variable দরকার, কী ধরনের ইনপুট/আউটপুট প্রত্যাশিত।
- **বিভিন্ন ইনপুট দিয়ে প্রোগ্রাম পরীক্ষা করুন**, শুধুমাত্র "স্বাভাবিক" ইনপুট নয়, বরং সীমান্তবর্তী (boundary) এবং অস্বাভাবিক ইনপুটও (যেমন 0, নেগেটিভ সংখ্যা) বিবেচনা করুন।

### Deep Understanding — কেন "First Working Version" এবং "Final Polished Version" আলাদা

বাস্তব সফটওয়্যার ডেভেলপমেন্টে, একটি প্রোগ্রামের প্রথম কার্যকরী সংস্করণ (first working version) খুব কমই চূড়ান্ত, সম্পূর্ণ ফিচার-সমৃদ্ধ সংস্করণ হয়। প্রফেশনাল ডেভেলপমেন্ট একটি **পুনরাবৃত্তিমূলক (iterative)** প্রক্রিয়া — প্রথমে একটি সাধারণ, কার্যকরী সংস্করণ (যাকে অনেক সময় "MVP" বা Minimum Viable Product বলা হয়) তৈরি করা হয়, তারপর ধাপে ধাপে ফিচার, error handling, এবং পারফরম্যান্স উন্নতি যোগ করা হয়। এই চ্যাপ্টারে আমাদের ক্যালকুলেটর প্রোগ্রামটি একটি "first working version"-এর উদাহরণ — এটি মূল কাজটি করে, কিন্তু জটিল error handling (যেমন zero-division) এখনো যোগ করা হয়নি।

### Behind the Scenes — Compilation থেকে Execution পর্যন্ত সম্পূর্ণ যাত্রা

আমাদের ক্যালকুলেটর প্রোগ্রামের ক্ষেত্রে, `g++` কমান্ড চালানোর পর যা ঘটে তার একটি সংক্ষিপ্ত সারসংক্ষেপ (1.1 বিভাগে আলোচিত ধাপগুলোর প্রয়োগ):

1. **Preprocessing:** `#include <iostream>` প্রসেস হয়, `iostream` হেডারের কন্টেন্ট আমাদের ফাইলে যুক্ত হয়।
2. **Compilation:** সোর্স কোড tokenize, parse, এবং semantically analyze করা হয় — এই ধাপে `int`/`double` টাইপ যাচাই, variable ঘোষণা যাচাই, ইত্যাদি ঘটে।
3. **Assembly:** কম্পাইলার মধ্যবর্তী কোডকে অ্যাসেম্বলি ভাষায় রূপান্তর করে।
4. **Linking:** আমাদের কোড এবং `iostream` লাইব্রেরির প্রি-কম্পাইলড কোড একত্রিত (link) করা হয়, যাতে `std::cout`, `std::cin`-এর প্রকৃত বাস্তবায়ন (implementation) আমাদের প্রোগ্রামের সাথে যুক্ত হয়।
5. **Executable তৈরি:** সবকিছু একত্রিত হয়ে একটি সম্পূর্ণ এক্সিকিউটেবল ফাইল (`calculator`) তৈরি হয়।
6. **Execution:** অপারেটিং সিস্টেম এক্সিকিউটেবল ফাইলটি মেমোরিতে লোড করে, এবং `main` function থেকে execution শুরু হয়।

### Professional Programmer Notes

বাস্তব প্রফেশনাল প্রজেক্টে, ম্যানুয়ালি `g++` কমান্ড টাইপ করার বদলে সাধারণত **build system** (যেমন CMake) ব্যবহার করা হয়, যা কম্পাইলেশন প্রক্রিয়া স্বয়ংক্রিয় ও পরিচালনাযোগ্য করে তোলে, বিশেষত যখন প্রজেক্টে বহু ফাইল এবং জটিল dependency থাকে। এছাড়া, **IDE (Integrated Development Environment)** যেমন Visual Studio, CLion, বা VS Code, কোড লেখা, কম্পাইল করা, এবং ডিবাগ করা — সবকিছু একটি একক ইন্টারফেসের মধ্যে সমন্বিত করে, যা প্রফেশনাল workflow-কে উল্লেখযোগ্যভাবে দ্রুততর করে তোলে।

### Interview Questions

1. **প্রশ্ন:** একটি C++ প্রোগ্রাম লেখা থেকে রান করা পর্যন্ত মূল ধাপগুলো কী কী?
   **উত্তর:** পরিকল্পনা, সোর্স কোড লেখা, কম্পাইল করা (preprocessing, compilation, assembly, linking সহ), রান করা, এবং প্রয়োজনে ডিবাগ ও উন্নতি করা।

2. **প্রশ্ন:** "logical bug" এবং "syntax error"-এর মধ্যে পার্থক্য কী?
   **উত্তর:** Syntax error হলো ভাষার ব্যাকরণ লঙ্ঘন, যা কম্পাইলেশনকেই ব্যর্থ করে দেয়। Logical bug হলো এমন কোড, যা সফলভাবে কম্পাইল ও রান হয়, কিন্তু ভুল বা অপ্রত্যাশিত ফলাফল দেয় (যেমন integer division-জনিত ভুল ফলাফল)।

3. **প্রশ্ন:** কেন প্রফেশনাল প্রোগ্রামাররা ছোট ছোট ধাপে কোড লিখে বারবার কম্পাইল ও টেস্ট করার পরামর্শ দেন?
   **উত্তর:** এতে করে কোনো সমস্যা দেখা দিলে তার উৎস সহজে চিহ্নিত করা যায়, কারণ সাম্প্রতিক পরিবর্তনের পরিমাণ ছোট থাকে। একসাথে অনেক পরিবর্তন করে তারপর টেস্ট করলে, কোন নির্দিষ্ট পরিবর্তনটি সমস্যা তৈরি করেছে তা খুঁজে বের করা কঠিন হয়ে পড়ে।

## Chapter 1 Summary (চ্যাপ্টার সারসংক্ষেপ)

এই চ্যাপ্টারে আমরা C++ প্রোগ্রামিং-এর একদম মৌলিক ভিত্তি তৈরি করেছি। নিচে প্রতিটি বিভাগের মূল বিষয়গুলো সংক্ষেপে তুলে ধরা হলো:

- **1.1 Statements and Program Structure:** একটি প্রোগ্রাম মূলত statement-এর একটি ক্রমানুসারে সাজানো তালিকা। প্রতিটি C++ প্রোগ্রাম `main` function থেকে শুরু হয়, এবং statement গুলো সাধারণত উপর থেকে নিচে, ক্রমানুসারে execute হয়। ব্লক (`{ }`) একাধিক statement-কে একত্রে গ্রুপ করে এবং নিজস্ব স্কোপ তৈরি করে।

- **1.2 Comments:** Comment হলো এমন কোড, যা কম্পাইলার সম্পূর্ণভাবে উপেক্ষা করে, এবং শুধুমাত্র মানুষের পড়ার জন্য লেখা হয়। `//` single-line, `/* */` multi-line comment-এর জন্য ব্যবহৃত হয়। ভালো comment "কী" নয়, "কেন" ব্যাখ্যা করে।

- **1.3 Objects and Variables:** Object হলো মেমোরির এমন একটি অঞ্চল যা মান ধারণ করে। Variable হলো একটি named object। একটি variable ব্যবহারের আগে অবশ্যই ঘোষণা (declare) করতে হয়, যা তার নাম ও টাইপ নির্ধারণ করে।

- **1.4 Assignment and Initialization:** Initialization ঘটে variable তৈরির মুহূর্তে, Assignment ঘটে পরবর্তীতে মান পরিবর্তনের জন্য। আধুনিক C++-এ brace initialization (`{ }`) প্রস্তাবিত, কারণ এটি narrowing conversion প্রতিরোধ করে।

- **1.5 iostream — cout, cin, endl:** `std::cout` (সাথে `<<`) আউটপুট প্রদর্শনের জন্য, `std::cin` (সাথে `>>`) ইনপুট গ্রহণের জন্য ব্যবহৃত হয়। `'\n'` সাধারণত `std::endl`-এর চেয়ে বেশি efficient, কারণ এটি বাফার flush করে না।

- **1.6 Uninitialized Variables and Undefined Behavior:** Uninitialized variable-এ অনির্ধারিত (garbage) মান থাকে, যা ব্যবহার করলে undefined behavior ঘটে — যার ফলাফল সম্পূর্ণ অনির্ভরযোগ্য। সবসময় variable initialize করা উচিত।

- **1.7 Keywords and Identifiers:** Keyword হলো ভাষার সংরক্ষিত শব্দ, যা identifier হিসেবে ব্যবহার করা যায় না। Identifier নামকরণে নির্দিষ্ট নিয়ম (letter/digit/underscore, সংখ্যা দিয়ে শুরু নয়, case-sensitive) মানতে হয়, এবং প্রফেশনাল কোডে সামঞ্জস্যপূর্ণ naming convention অনুসরণ করা উচিত।

- **1.8 Whitespace and Formatting:** কম্পাইলার whitespace সাধারণত উপেক্ষা করে, কিন্তু সুসংগঠিত ইনডেন্টেশন ও ফরম্যাটিং মানুষের পড়ার জন্য অত্যন্ত গুরুত্বপূর্ণ। প্রফেশনাল টিমে প্রায়ই স্বয়ংক্রিয় ফরম্যাটার টুল ব্যবহৃত হয়।

- **1.9 Literals and Operators:** Literal হলো সরাসরি কোডে লেখা একটি স্থির মান। Operator একাধিক operand নিয়ে একটি নির্দিষ্ট গণনা সম্পাদন করে। Integer division-এর দশমিক অংশ বাদ পড়ে যায়, এবং `=` ও `==` গুলিয়ে ফেলা একটি সাধারণ ভুল।

- **1.10 Expressions:** Expression মূল্যায়িত হয়ে একটি মান উৎপন্ন করে। Operator precedence নির্ধারণ করে জটিল expression-এ কোন অপারেশন আগে ঘটবে; বন্ধনী ব্যবহার করে স্পষ্টতা নিশ্চিত করা প্রফেশনাল প্র্যাকটিস।

- **1.11 Developing Your First Program:** পরিকল্পনা → কোড লেখা → কম্পাইল → রান → ডিবাগ → উন্নতি — এই workflow অনুসরণ করে আমরা একটি সম্পূর্ণ ক্যালকুলেটর প্রোগ্রাম তৈরি করেছি, যা এই চ্যাপ্টারের সবগুলো ধারণা একত্রিত করেছে।

### মূল নীতিমালা যা মনে রাখা জরুরি

1. **সবসময় variable initialize করুন** — কখনো uninitialized variable ব্যবহার করবেন না।
2. **অর্থবহ নাম ব্যবহার করুন** এবং সামঞ্জস্যপূর্ণ naming convention অনুসরণ করুন।
3. **`'\n'` প্রাধান্য দিন `std::endl`-এর চেয়ে**, যদি না বাফার flush করার নির্দিষ্ট প্রয়োজন থাকে।
4. **কখনো `using namespace std;` ব্যবহার করবেন না** প্রফেশনাল কোডে।
5. **জটিল expression-এ বন্ধনী ব্যবহার করুন** স্পষ্টতার জন্য।
6. **সামঞ্জস্যপূর্ণ ফরম্যাটিং বজায় রাখুন** — ইনডেন্টেশন, ব্রেস স্টাইল, স্পেসিং।

## Extra: Frequently Confused Concepts (অতিরিক্ত: প্রায়ই বিভ্রান্তিকর ধারণা)

এই বিভাগে চ্যাপ্টার জুড়ে আলোচিত কয়েকটি বিষয় নিয়ে সংক্ষিপ্ত তুলনামূলক পুনরালোচনা করা হলো, যা বিগিনারদের প্রায়ই বিভ্রান্ত করে।

### `=` বনাম `==`

```cpp
x = 5;    // Assignment — x-এর মান 5 করে দেওয়া হচ্ছে
x == 5    // Comparison — x-এর মান 5 এর সমান কিনা যাচাই করা হচ্ছে, ফলাফল bool
```

### Declaration বনাম Initialization বনাম Assignment

```cpp
int x;         // শুধু Declaration — মান অনির্ধারিত
int y{ 5 };     // Declaration + Initialization একসাথে
y = 10;          // শুধু Assignment (y ইতিমধ্যে declare করা আছে)
```

### `std::endl` বনাম `'\n'`

```cpp
std::cout << "টেক্সট" << std::endl;   // নতুন লাইন + বাফার flush
std::cout << "টেক্সট" << '\n';         // শুধু নতুন লাইন, বেশি efficient
```

### Statement বনাম Expression

```cpp
5 + 3            // Expression — একটি মান (8) উৎপন্ন করে, নিজে সম্পূর্ণ নির্দেশনা নয়
int x{ 5 + 3 };   // Statement — একটি সম্পূর্ণ নির্দেশনা, যার ভেতরে expression ব্যবহৃত হয়েছে
```

### Copy Initialization বনাম Brace Initialization

```cpp
int x = 5;    // Copy initialization — narrowing conversion চুপচাপ ঘটতে দেয়
int y{ 5 };    // Brace initialization — narrowing conversion কম্পাইল-টাইমে ধরে ফেলে
```

## Chapter 1 Quiz (চ্যাপ্টার কুইজ)

নিচের প্রশ্নগুলো সমাধান করে যাচাই করুন এই চ্যাপ্টারের ধারণাগুলো কতটা আত্মস্থ হয়েছে। প্রতিটি প্রশ্নের উত্তর প্রশ্নের ঠিক পরেই দেওয়া আছে, কিন্তু নিজে চেষ্টা করার পর উত্তর দেখার পরামর্শ দেওয়া হচ্ছে।

**প্রশ্ন ১:** নিচের কোডটি কম্পাইল হবে কিনা, এবং হলে আউটপুট কী হবে তা নির্ণয় করুন:
```cpp
#include <iostream>

int main()
{
    int x{ 5 };
    int y{ 10 };
    std::cout << x + y * 2;
    return 0;
}
```
**উত্তর:** কম্পাইল হবে। আউটপুট: `25` (operator precedence অনুযায়ী প্রথমে `y * 2 = 20`, তারপর `x + 20 = 25`)।

---

**প্রশ্ন ২:** নিচের কোডে কী সমস্যা আছে চিহ্নিত করুন:
```cpp
int main()
{
    int score
    std::cout << score;
    return 0;
}
```
**উত্তর:** দুইটি সমস্যা: (১) `int score` এর পর সেমিকোলন নেই, যা সিনট্যাক্স এরর তৈরি করবে। (২) এমনকি সেমিকোলন যোগ করলেও, `score` uninitialized অবস্থায় ব্যবহৃত হচ্ছে, যা undefined behavior ঘটাবে।

---

**প্রশ্ন ৩:** নিচের দুইটি কোডের আউটপুটে পার্থক্য হবে কি? ব্যাখ্যা করুন।
```cpp
// কোড A
double result{ 7 / 2 };

// কোড B
double result{ 7.0 / 2 };
```
**উত্তর:** হ্যাঁ, পার্থক্য হবে। কোড A-তে `7 / 2` প্রথমে integer division হিসেবে গণনা হয় (ফলাফল `3`), তারপর সেটি `double`-এ রূপান্তরিত হয়ে `result = 3.0` হয়। কোড B-তে `7.0 / 2` floating-point division হিসেবে গণনা হয় সরাসরি, ফলাফল `result = 3.5`।

---

**প্রশ্ন ৪:** নিচের identifier নামগুলোর মধ্যে কোনগুলো বৈধ এবং কোনগুলো অবৈধ?
```
a) totalScore
b) 2ndAttempt
c) is_valid
d) double
e) _count
```
**উত্তর:** 
- (a) `totalScore` — বৈধ
- (b) `2ndAttempt` — অবৈধ (সংখ্যা দিয়ে শুরু)
- (c) `is_valid` — বৈধ
- (d) `double` — অবৈধ (এটি একটি C++ keyword)
- (e) `_count` — টেকনিক্যালি বৈধ, কিন্তু প্রফেশনাল কোডে এড়িয়ে চলা উচিত (আন্ডারস্কোর দিয়ে শুরু হওয়া নাম প্রায়ই লাইব্রেরির জন্য সংরক্ষিত থাকে বিশেষ প্যাটার্নে)

---

**প্রশ্ন ৫:** ব্যাখ্যা করুন কেন নিচের কোডটি একটি বিপজ্জনক bug তৈরি করতে পারে, যদিও এটি সফলভাবে কম্পাইল হয়:
```cpp
int x{ 10 };
if (x = 20)
{
    std::cout << "শর্ত সত্য";
}
```
**উত্তর:** এখানে `==` (comparison) এর বদলে `=` (assignment) ব্যবহৃত হয়েছে। এটি `x`-এর মান `20`-তে পরিবর্তন করে দিচ্ছে, এবং এই assignment expression-এর মান (`20`, যা non-zero, তাই `true` হিসেবে গণ্য) `if` কন্ডিশনে ব্যবহৃত হচ্ছে। ফলে শর্তটি সবসময় সত্য হবে (যতক্ষণ না assign করা মান 0 হয়), এবং `x`-এর মূল মান (`10`) হারিয়ে গিয়ে `20` হয়ে যাবে — যা প্রোগ্রামারের উদ্দেশ্য নাও হতে পারে।

---

**প্রশ্ন ৬:** নিচের কোডে ব্লক ও স্কোপ সম্পর্কিত কোনো সমস্যা আছে কিনা চিহ্নিত করুন:
```cpp
int main()
{
    {
        int value{ 42 };
    }
    std::cout << value;
    return 0;
}
```
**উত্তর:** হ্যাঁ, সমস্যা আছে। `value` variable-টি একটি nested block-এর ভেতরে ঘোষণা করা হয়েছে, এবং সেই block শেষ হওয়ার সাথে সাথে `value` আর অ্যাক্সেসযোগ্য থাকে না (এটি স্কোপের বাইরে চলে গেছে)। তাই `std::cout << value;` লাইনটি কম্পাইল এরর তৈরি করবে, কারণ `value` এই বিন্দুতে সংজ্ঞায়িত নয়।

---

**প্রশ্ন ৭ (প্রোগ্রামিং প্রশ্ন):** একটি সম্পূর্ণ প্রোগ্রাম লিখুন যা ব্যবহারকারীর কাছ থেকে একটি আয়তক্ষেত্রের দৈর্ঘ্য ও প্রস্থ গ্রহণ করে, তার ক্ষেত্রফল ও পরিসীমা গণনা করে প্রদর্শন করে। প্রোগ্রামে অবশ্যই সঠিক variable initialization, উপযুক্ত naming convention, এবং readable formatting থাকতে হবে।

**উত্তর (একটি সম্ভাব্য সমাধান):**
```cpp
#include <iostream>

int main()
{
    double length{};
    double width{};

    std::cout << "আয়তক্ষেত্রের দৈর্ঘ্য লিখুন: ";
    std::cin >> length;

    std::cout << "আয়তক্ষেত্রের প্রস্থ লিখুন: ";
    std::cin >> width;

    double area{ length * width };
    double perimeter{ 2 * (length + width) };

    std::cout << "ক্ষেত্রফল: " << area << std::endl;
    std::cout << "পরিসীমা: " << perimeter << std::endl;

    return 0;
}
```

## What's Next (পরবর্তীতে কী)

এই চ্যাপ্টারে আমরা C++ প্রোগ্রামিং-এর একদম মৌলিক গাঁথনি — statement, variable, initialization, I/O, naming, formatting, literal, operator, এবং expression — সম্পর্কে শিখেছি। এই ভিত্তিটি অত্যন্ত গুরুত্বপূর্ণ, কারণ পরবর্তী প্রতিটি চ্যাপ্টার এই ধারণাগুলোর উপর ভিত্তি করে গড়ে উঠবে।

পরবর্তী চ্যাপ্টারে আমরা অনুসন্ধান করব:
- **Functions** — কোডকে পুনর্ব্যবহারযোগ্য একক-এ সংগঠিত করা
- **Fundamental Data Types** — বিস্তারিতভাবে বিভিন্ন টাইপ, তাদের আকার ও সীমা
- **Control Flow** — `if`, `else`, লুপ ব্যবহার করে প্রোগ্রামের সিদ্ধান্ত গ্রহণ ক্ষমতা তৈরি করা

এই মৌলিক ভিত্তিটি মজবুতভাবে আয়ত্ত করার পরই এই পরবর্তী, আরও শক্তিশালী ধারণাগুলোতে এগিয়ে যাওয়া উচিত।
